# 自然资源本体应用客户演示讲稿

- 文档版本：V1.0
- 演示应用：GIS Data Agent
- 本体版本：自然资源“一张图”本体 V2.0.1
- 演示数据：规划院提供数据样例及 Demo 系统功能演示建议
- 场景范围：重庆市璧山区福禄镇和平村、斑竹村
- 结论边界：辅助预审，不替代法定审批或行政决定

## 一、演示主线

本次不按十个菜单逐项展示，而是用一条业务闭环说明时空数据底座如何变得更好用：

> 规划地块从什么状态变成什么状态，属于哪一种自然资源业务过程，是否命中已注册的空间约束，还缺少什么审批证据？

和平村负责演示地块级用地转换和空间约束辅助预审；斑竹村负责演示规划前后土地利用结构变化，以及统计指标如何回到具体地块和本体状态。

### 页面导航说明

本手册中的“数据治理”“能力闭环”不是 GIS Data Agent 的一级页面，也不是“平台运营”下的治理功能。完整入口是：

> 智能分析 > 本体应用 > 数据治理（或能力闭环）

进入“本体应用”后，在白色工作区中找到 `Cognitive Runtime` 执行链；其下方依次排列“分析结论、语义证据、数据治理、能力闭环”四个内部页签。屏幕较窄时，先横向滚动“智能分析”的顶部页签栏找到“本体应用”。

## 二、30 分钟安排

### 0-3 分钟：传统模式的问题

打开 GIS Data Agent 的“智能分析 > 本体应用”。

讲解要点：

- 传统数据底座能够保存和展示数据，但字段、代码、业务规则和证据仍分散在不同系统和文档中。
- 地理实体编码回答“它是谁”；本体进一步回答“它是什么、处于什么状态、发生了什么过程、受什么规则约束、依据在哪里”。
- 本体不是新的业务系统菜单，也不是把表名和功能名改造成类。

### 3-8 分钟：数据汇聚与语义注册

在“本体应用”工作区中，找到 `Cognitive Runtime` 执行链下方的四个内部页签，点击第三个“数据治理”。不要进入“平台运营”下的治理功能。

讲解要点：

- 本次真实汇聚 10 个来源资产，包含 Shapefile 和 Excel。
- 和平村 902 个规划地块、斑竹村 1,555 个规划地块均保留源坐标系、源字段和文件哈希。
- `TDGHDL.JQDLMC` 映射到转换的源状态，`TDGHDL.GHDLMC` 映射到目标状态，`TDGHDL.BSM` 映射到地块身份。
- 21 类地类术语已映射，水库水面、河流水面、特殊用地 3 类进入治理待办，没有静默猜测。
- 和平村项目台账有 16 项，但 `TDGHDL.XMMC` 全为空，因此系统明确显示 0/16 空间关联，而不是伪造项目位置。

### 8-16 分钟：和平村用地转换辅助预审

选择“用地转换辅助预审”，执行语义分析。

讲解要点：

- 902 个规划地块中，445 个地类发生变化，变化面积 79.73 公顷。
- 本体把变化表达为“地块实体 + 源状态 + 转换过程 + 目标状态”，避免把土地永久固化为某一类别。
- 实际识别出农业结构调整、建设占用、土地复垦、土地整治和一般土地利用转换。
- GIS 引擎在源投影坐标系中执行真实叠加和面积计算。
- 25 个变化地块命中禁止性或保护性空间约束。
- 108 个地块涉及建设占用但未关联审批文件，空间上未发现冲突也不能显示为合规，只能标记“材料待补”。
- 312 个地块命中地灾或高郁闭度林地等条件约束，进入跨部门复核。

点击代表性地块右侧证据按钮。

讲解要点：

- 页面可追溯到 `LandParcel`、源状态、转换过程、目标状态及 `constrainedBy`、`authorizedBy` 等关系。
- 每个空间命中显示约束类型、名称和真实相交面积。
- 每个判断绑定本体 V2.0.1、演示包版本和源资产 SHA-256。

### 16-21 分钟：斑竹村土地利用结构调整

切换“土地利用结构调整”，执行语义分析。

讲解要点：

- 1,555 个规划地块中，559 个发生变化，变化面积 87.24 公顷。
- 结构调整表显示农用地从 625.63 公顷增至 634.69 公顷，净增 9.06 公顷。
- 旱地增加 16.21 公顷，园地增加 1.73 公顷。
- 林地减少 3.31 公顷，坑塘水面减少 4.20 公顷。
- 宅基地（村居住用地）减少 12.20 公顷。
- 统计变化通过本体状态与 559 个规划变化图斑关联，既能看总量，也能回到空间对象。

### 21-25 分钟：质量、证据和版本治理

回到“本体应用”工作区，点击 `Cognitive Runtime` 执行链下方第三个内部页签“数据治理”。

讲解要点：

- 系统检查 CRS、几何、地块标识、规划前后状态、语义映射、项目关联和审批证据。
- 本体包、演示数据包、源文件分别版本化；本体哈希不匹配或数据文件被改写时，运行时拒绝加载。
- 质量警告形成治理任务，而不是被智能体隐藏。

### 25-28 分钟：总体架构与跨部门扩展

在同一位置点击第四个内部页签“能力闭环”。

讲解要点：

- 数据层承载基础地理、规划地类、管控边界和项目台账。
- 语义层以本体为内核，定义跨数据源共享的实体、状态、过程、规则、角色和证据语义。
- MMFE 执行实际语义融合，本体为其提供目标语义和约束。
- GIS 引擎负责坐标转换、空间叠加和面积计算。
- Agent 负责问题理解、任务规划、工具调用和证据解释。
- 应用层可面向规划审查、自然资源业务协同及跨行业场景复用同一语义底座。

### 28-30 分钟：总结

建议收束表述：

> 本体建设的价值不是增加一个图谱页面，而是让基础地理数据从“可看、可查”升级为“可理解、可计算、可解释、可协同”的时空数据底座。它让智能体有稳定的领域知识结构，让跨部门数据有可对齐的语义目标，也让每个分析结论能够回到规则、数据和版本证据。

## 三、十项能力对应关系

| 数据中心能力 | 本场景中的落点 |
|---|---|
| 数据汇聚 | Shapefile、Excel 多源资产统一注册 |
| 数据治理 | 术语映射及项目空间关联缺口显式管理 |
| 数据质检 | CRS、几何、标识、状态、映射和证据规则校验 |
| 数据展示 | 规划地块、转换过程和管控边界联动地图 |
| 数据分析 | 规划前后状态转换和空间叠加 |
| 数据分发 | 认证只读 GeoJSON 和版本化证据包 |
| 数据安全 | 认证 API、来源追踪和用途范围声明 |
| 全流程管理 | 问题解析到证据解释的六步执行链 |
| 数据反馈 | 未映射术语、未关联项目和缺失材料形成治理待办 |
| 更新维护 | 本体、演示包和源文件哈希独立版本化 |

## 四、演示注意事项

- 不表述“系统已经完成法定合规审查”，统一使用“辅助预审”“空间初筛”“条件复核”。
- 不宣称重点项目已经定位到具体图斑；当前源数据缺少可靠项目空间关联。
- 不把本体描述成空间计算引擎；叠加和面积由 GIS 引擎完成。
- 不把 MMFE 描述成本体；MMFE 是依据本体执行语义融合的引擎。
- 不只展示漂亮图谱，要始终回到业务问题、规则判断和来源证据。
