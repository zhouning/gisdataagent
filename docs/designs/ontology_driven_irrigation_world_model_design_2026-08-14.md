# 本体驱动的灌区世界模型（ODIWM）科学与系统设计方案

- 日期：2026-08-14
- 文档状态：研究与原型设计基线
- 适用范围：灌区渠系配水、田间灌溉与水土作物状态的协同推演
- 能力边界：本方案定义待验证的目标架构，不代表相关模型、数据、指标或真实控制能力已经实现
- 路线定位：专业模型与守恒内核为主线，学习型代理按证据晋级，JEPA 按数据条件触发

## 1. 执行摘要

本方案面向灌区运行中的一个明确问题：

> 在供水能力、渠系容量、天气预报、作物需水、水权配额和调度权限均受约束，且真实状态只能被部分观测的条件下，如何重建当前灌区状态，比较不同渠系配水与田间灌溉方案的可能后果，并向有权人员提供可复核、可追溯的候选 Proposal？

本方案将本体用于确定对象、关系、状态变量、动作类型、约束、数据映射和证据身份，将 Geospatial Kernel 风格的权威拓扑编译、守恒账、状态估计和预测闭包作为计算边界，将专业水动力、土壤水分和作物模型用于表达已知机制，将规划器用于搜索或比较候选方案，将语言模型限制在意图理解、语义落地、工具编排和结果解释范围内。学习模型只在完成数据审计、简单基线和专业模型验证后，用于状态估计、参数校准、受界残差或快速近似。

核心定位为：

> ODIWM 是一个由版本化灌区本体约束、以权威地理拓扑和守恒计算为基础、面向对象关系状态、由专业模型提供机制主干、可由通过准入的学习模型加速、能够进行动作条件多步推演并接受规划器消费的研究型动态系统。

这里的“本体驱动”不表示用 OWL 推理代替水动力计算，也不表示本体能够消除预测不确定性或自动产生因果效应。本体的主要职责是提供稳定、可验证的语义合同；动态状态、物理过程、概率预测、方案优化和现实执行仍由各自适合的模型与运行时承担。

技术路线采用非对称组织：工程和首期科研主线是“本体/GIS 拓扑 + 守恒内核 + 状态估计 + 专业模型 + 约束优化 + Proposal”；学习型代理是满足数据和验证门后启动的加速支线；JEPA 只是该支线中的候选研究方法，不是 Geospatial Kernel 的实现基础，也不是原型交付或系统上线的前置条件。

首期建议只建设一个可证伪的窄闭环：

- 一个具有较完整数据的代表性渠系或管理片区；
- 一种主要作物；
- 一个完整灌溉季；
- 小时级渠系状态和日级田间水分状态；
- 闸门开度、配水量、供水时段和田间灌溉量等有限动作；
- 以历史回放和前瞻影子运行作为主要验证方式；
- 只生成候选 Proposal，不直接控制闸门、泵站或生产系统。

三个特大灌区不应被当作三个同时从零建设的演示项目。更合理的研究设计是“一处主试点、两处迁移验证”：在一处形成完整数据和模型闭环，在另外两处按冻结协议分别开展零样本、少样本和充分校准比较，检验本体对齐、模型迁移和运行规则差异。

## 2. 设计结论与允许声明

### 2.1 可以作为设计目标的能力

- 建立版本化、可审定的灌区领域本体和数据映射；
- 将水源、渠系、工程、田块、土壤、作物、用水主体和规则组织为类型化状态图；
- 区分观测、隐状态、外生强迫、候选动作、已批准动作、已下发指令、实际执行和结果；
- 接入经过验证的专业水动力、土壤水分、作物需水和调度模型；
- 在冻结的输入和模型条件下进行多步情景推演；
- 训练并评估面向特定任务的快速代理模型；
- 比较规则、优化和搜索算法生成的候选方案；
- 输出带约束、风险、不确定性、证据和适用范围的 Proposal；
- 通过人工审批、执行回执、对账和复盘形成完整审计链。

### 2.2 当前不能预先承诺的能力

- 不能预先承诺学习模型优于专业机理模型；
- 不能声称既有 Geospatial Kernel 基于 JEPA，或已经具有可直接迁移的 JEPA 编码器、目标函数和模型权重；
- 不能把普通潜在状态回归或“冻结 embedding + 下一状态预测”直接称为完整 JEPA；
- 不能预先承诺达到一千倍加速或完整规划毫秒级响应；
- 不能把语义正确或物理守恒直接表述为因果有效；
- 不能把历史调度行为直接当成最优动作标签；
- 不能声称 MCTS 必然优于 MPC、MILP、规则或其他规划方法；
- 不能因 Action Type 对齐就声称已经解决 Sim-to-Real；
- 不能把过程模型生成的轨迹冒充真实干预证据；
- 不能由一个灌区的成功结果推断三个灌区或全国灌区普遍有效；
- 不能用论文目标、页面演示或系统闭环代替预测与决策价值证据；
- 不能让语言模型绕过专业模型、规则、权限和人工审批直接形成设备控制命令。

### 2.3 设计成功的判定方式

本课题的成功不以是否使用 JEPA、PINN、MCTS 或知识图谱来判定，而以以下问题是否得到可复现回答来判定：

1. 本体约束是否降低了对象错配、关系错连、单位错误和非法动作？
2. 类型化状态是否能在部分观测条件下被可靠重建？
3. 动作条件模型是否在未见时段和未见事件上优于强基线？
4. 多步推演是否保持质量守恒、数值稳定和不确定性校准？
5. 快速代理是否在同任务、同精度口径下提供可重复的速度收益？
6. 规划器是否在独立评估环境中降低 decision regret 或提高方案可行率？
7. 本体对齐是否改善跨灌区迁移，而不是只增加建模成本？
8. 前瞻影子运行是否改善会商效率、证据完整性和风险发现？

任何核心问题得到否定结果，都应被保留为正式研究结论，而不是通过更换口径或继续调参隐藏。

## 3. 继承的设计原则与教训

### 3.1 状态、观测和证据必须分开

遥测水位、流量、闸位、遥感土壤水分和作物指数都是观测，不等于完整真实状态。渠段存量、根区水分、实际输水损失、作物胁迫和地下水交换通常需要状态估计。

系统维护的不是一张“最新数据表”，而是对真实状态的带不确定性估计。每个状态值必须能追溯到观测、模型、同化增量和质量标记。

### 3.2 动作、外生强迫和结果必须分开

- 闸门开度、泵站启停、配水量和灌溉时段属于可控动作；
- 降雨、温度、上游天然来水和作物需水预报属于外生强迫；
- 水位、流量、土壤水分、作物胁迫和供水公平属于状态或结果；
- 调度计划、下发指令、设备执行和实际过流不能合并成一个字段。

若角色混写，模型可能把天气变化误认成动作效果，或把计划流量误认成实际边界通量。

### 3.3 形式化同构不证明方法可迁移

灌区运行、土地规划和机器人控制都可以写成 state + action -> next state，但这不证明它们具有相同的数据生成机制、反馈频率、可试验性、责任结构和最优性定义。

灌区中的短周期输配水具有较强物理约束和明确执行器，适合运行型动态模型；种植结构、水权制度和重大工程调整属于长期治理问题，只适合比较由专家或有权机构给出的候选情景，不能沿短周期控制路线外推。

### 3.4 专业模型是基线和机制后端

世界模型不应通过换名替代成熟水动力、土壤水分、作物需水和运筹优化模型。专业模型承担：

- 物理过程计算；
- 高可信合成轨迹生成；
- 模型适用性判断；
- 学习模型的教师或评估器；
- 学习模型失效时的回退路径。

学习模型只有在明确任务上超过强基线，或在可接受误差下显著降低计算成本，才获得相应能力声明。

### 3.5 规划器是消费者，不是世界模型

世界模型负责给定当前状态、动作和外生情景后的未来状态推演。MPC、MILP、MCTS、beam search 或规则搜索消费这些推演结果。

将规划器与世界模型分离，可以分别回答：

- 模型是否预测正确；
- 规划器是否搜索有效；
- 目标权重是否得到授权；
- 候选动作是否允许执行。

### 3.6 本体约束不等于因果识别

本体可以保证“谁对什么对象实施了什么动作”表达正确，可以限制不可能或不允许的关系，但不能自动消除混杂、选择偏差、未观测因素和反事实不可观测问题。

没有田间试验、准实验、可靠机理或其他可辩护证据时，系统只能声明“在给定模型和情景下的条件差异”，不能声明现实中的因果效应。

### 3.7 证据链完整不等于结论有效

数据哈希、模型版本和运行轨迹只能证明结果如何产生。它们不能单独证明模型预测有效、动作具有因果效果、方案优于现行调度或已获得执行授权。

本方案因此将证据至少分为四个互不补偿的维度：

1. 数据与程序完整性；
2. 物理与预测有效性；
3. 动作效果或因果证据；
4. 业务权限与人工批准。

### 3.8 失败结果必须进入后续设计

如果学习模型未超过 persistence、规则或专业模型，或者错误拓扑与正确拓扑表现相近，说明模型可能没有学到预期机制。应冻结失败窗口、分析原因并使用新的验证窗口，而不能在已读取结果上反复调参后继续声称盲测。

### 3.9 Geospatial Kernel 与 JEPA 的实现血缘必须分开

既有 Geospatial Kernel 是一个地理拓扑、守恒通量、状态估计、专业算子、预测闭包和证据准入体系，其核心关系是：

~~~text
GIS Compiler
  -> Conservative Kernel
  -> Forecast Closure
~~~

它没有以 JEPA 为实现骨架，也没有提供现代 JEPA 通常需要的 context encoder、target encoder、停止梯度或 EMA target 更新、masked latent target prediction 和相应训练循环。历史上标记为 JEPA 的“冻结地理 embedding + 潜在状态预测”原型属于独立探索，更准确地说是潜在动力学模型，不构成 Geospatial Kernel 已实现 JEPA 的证据。

因此，本方案继承的是对象身份、权威关系、状态/动作/forcing 合同、守恒账、算子接口和验证门，而不是 JEPA 网络、训练目标或模型权重。未来 JEPA 候选若与内核集成，也只能通过上述稳定合同接入，属于新建模型服务，不属于既有实现的算法延续。

### 3.10 技术路线按必要性和证据分级

灌区项目不需要先完成两套同等规模的系统再决定方向。路线优先级如下：

1. **必要基础：**本体与 GIS 拓扑、数据和动作合同、守恒账、状态估计、专业模型、规则与约束优化；
2. **优先比较：**简化机理模型、状态空间模型、降阶模型和受界残差；
3. **数据充分后比较：**图时空模型、神经算子和其他学习型代理；
4. **满足专门触发条件后研究：**JEPA 式表示学习及动作条件潜在预测。

前一层不因后一层失败而失效；后一层必须证明相对于前一层的新增价值。这样既允许探索学习方法，又避免将工程闭环押在尚未证明适合灌区控制的数据假设上。

## 4. 场景边界与首期业务问题

### 4.1 首期业务问题

首期只回答：

> 在未来若干小时至若干天的天气和供水不确定条件下，比较有限集合内的渠系配水与田间灌溉计划，使候选方案满足工程、水权和安全硬约束，并报告水量、作物胁迫、供水公平、能耗和不确定性。

预测与规划时域需要在试点数据审计后冻结。建议采用多时间尺度：

- 渠系水动力：分钟至小时；
- 配水与调度：小时至日；
- 根区土壤水分和蒸散：日；
- 作物胁迫和生长：日到生育阶段；
- 季节结果：只用于后评估，不作为首期实时控制状态。

### 4.2 首期空间范围

- 一个水源或明确供水边界；
- 一个骨干渠或具有清晰边界的支渠系统；
- 若干控制闸、泵站、分水口和量测点；
- 与渠系相连的明确田块或用水单元；
- 一种主要作物；
- 一个完整灌溉季；
- 一个明确的调度责任主体和审批边界。

### 4.3 首期动作范围

允许进入候选集的动作应限制为已有工程能力可执行的动作：

- 闸门目标开度或目标过流过程；
- 泵站启停和目标流量；
- 分水口供水时段与水量；
- 田块或用水单元的灌溉开始时间、持续时间和水量；
- 供水不足时在授权规则内的重新分配。

以下内容不进入首期：

- 新建或拆除水库、渠道和泵站；
- 长期水权制度重构；
- 跨区域产业或种植结构调整；
- 施肥、农药、品种和轮作联合优化；
- 无人值守自动控制；
- 对历史调度人员或管理制度作价值判断。

### 4.4 首期用户与责任

主要用户包括灌区调度人员、渠系运行人员、农艺或需水分析人员、数据与模型工程人员、审批人员和科研评估人员。

系统负责计算、比较、暴露风险和组织证据；正式配水和设备操作责任仍属于有权机构和指定人员。

## 5. 可证伪的科学问题

### 5.1 H1：本体约束是否带来可测量价值

假设：

> 在相同数据、参数规模和训练预算下，类型化对象、权威关系、单位与动作约束能够降低语义错误和非法动作，并改善跨灌区迁移或少样本适配。

对照：

- 无本体约束的平面特征模型；
- 只有对象类型、没有关系约束的模型；
- 使用静态关系但没有版本和来源的模型；
- 完整类型、关系、单位、动作和证据约束模型。

主要指标：

- 对象和关系 grounding 正确率；
- 单位与空间支撑错误率；
- 非法动作 false allow / false block；
- 跨灌区零样本与少样本性能退化；
- 新灌区数据映射和模型接入成本。

否证条件：

- 完整本体约束相对轻量类型合同没有稳定收益；
- 迁移收益不能超过额外建模和维护成本；
- 模型仍能在错误关系或反向拓扑下保持相同表现。

### 5.2 H2：物理约束是否改善多步稳定性

假设：

> 在相同训练数据下，显式水量账、权威拓扑、非负与容量约束能够降低长时 rollout 漂移和物理违规，并在可接受范围内保持预测精度。

对照：

- 无物理约束的数据驱动模型；
- 只使用软损失的模型；
- 硬拓扑和水量账约束模型；
- 专业机理模型；
- 机理模型加受界残差修正。

主要指标：

- 控制体水量闭合误差；
- 负水量、超容量和逆向传播次数；
- 多步误差增长曲线；
- 极端情景的尾部失败；
- 预测精度与物理合规的 Pareto 关系。

否证条件：

- 物理约束只改善账面指标但显著恶化有效预测；
- 学习残差成为未记账的自由水源或水汇；
- 多步稳定性未优于简单状态更新或专业模型。

### 5.3 H3：动作条件模型是否学到动作响应

假设：

> 模型在未见事件和未见动作组合上能够区分不同合法动作的响应，而不是只利用时间、天气或状态相关性。

必须进行：

- zero-action 对照；
- action shuffle 对照；
- action-agnostic 对照；
- forcing-only 对照；
- 反向或错误拓扑对照；
- 指令值与实际执行值替换对照。

否证条件：

- 动作条件模型未超过 action-agnostic 强基线；
- 打乱动作后性能不下降；
- 使用计划动作与实际动作得到相近结果；
- 错误拓扑对结果没有可解释影响。

### 5.4 H4：快速代理是否具有工程价值

假设：

> 对冻结的任务、硬件、时域、空间分辨率和输出变量，学习型代理在达到预注册误差和守恒门槛时，比指定专业模拟器具有可重复的端到端速度优势。

速度评估必须分别报告：

- 单步推理；
- 固定时域单次 rollout；
- 情景集合批量 rollout；
- 完整候选搜索；
- 数据装载、状态估计、模型计算和结果写入；
- 冷启动与热启动；
- p50、p95、峰值内存和能耗。

否证条件：

- 速度收益来自降低空间分辨率、减少输出或放宽精度；
- 只比较专业模型全流程与代理模型一次前向；
- 代理模型在关键事件上超过允许误差或破坏硬约束；
- 完整规划链路没有实质速度收益。

### 5.5 H5：规划器是否改善候选方案质量

假设：

> 在冻结目标、权重、约束、计算预算和独立评估环境下，使用世界模型 rollout 的规划器能够相对现行规则或专业优化基线降低 regret，或提高可行方案发现率。

对照至少包括：

- 专家或现行规则；
- 传统网络流、线性或混合整数优化；
- MPC 或鲁棒 MPC；
- 适用时的 MCTS 或 beam search；
- 随机和简单启发式候选。

否证条件：

- 规划器只在训练使用的同一模拟器中获益；
- 规划器利用模型缺陷获得虚假高分；
- 在独立高保真模型、隐藏事件或影子运行中收益消失；
- 方案可行率、稳定性或人工接受度劣于规则基线。

## 6. 形式化定义

### 6.1 部分可观测、多尺度图动态系统

ODIWM 表示为受本体、权威拓扑、专业模型和业务规则约束的部分可观测图动态系统。

设：

- O^v：版本 v 的灌区领域本体；
- G_t^v：绑定本体版本和来源证据的灌区实例关系图；
- x_t：真实但不能完全观测的系统状态；
- o_t：传感器、遥感、业务记录等观测；
- b_t：对 x_t 的 belief state；
- a_t：候选或实际动作；
- e_t：天气、上游供水、天然来水和需水等外生强迫；
- R^v：版本化工程、配额、安全和权限规则；
- M：专业模型、状态估计器和学习模型组成的模型集合；
- q_t：观测质量、缺测和可用性状态。

状态估计可写为：

~~~text
b_t = P(
  x_t
  | issue_time 前可获得的观测,
    已执行动作,
    已发生外生输入,
    权威实例图,
    数据质量
)
~~~

动作条件转移可写为：

~~~text
x_(t+Δ) ~ T_M(
  x_t,
  a_t^executed,
  e_t^vintage,
  G_t^v,
  O^v,
  R^v
)
~~~

观测模型可写为：

~~~text
o_t ~ H(x_t, sensor_state_t, quality_t)
~~~

这里的概率项不能被本体替代。本体确定变量含义、对象类型、关系和合法取值边界；状态估计和转移仍需表达不确定性。

### 6.2 分层状态

状态至少分为以下部分：

~~~text
x_t = {
  water_source_state,
  canal_hydraulic_state,
  control_structure_state,
  field_soil_state,
  crop_state,
  operation_state,
  governance_state,
  evidence_state
}
~~~

具体包括：

| 状态层 | 示例 |
|---|---|
| 水源 | 可供水量、库水位、取水能力、供水约束 |
| 渠系 | 渠段水位、流量、存量、输水损失和传播状态 |
| 工程 | 闸门开度、泵站工况、设备可用性、通信状态 |
| 田块土壤 | 根区含水量、入渗、深层渗漏、盐分或地下水影响 |
| 作物 | 物候、冠层、生物量、水分胁迫、需水状态 |
| 运行 | 已供水量、轮灌进度、未完成任务、能耗 |
| 治理 | 水权、配额、优先级、禁限规则、审批状态 |
| 证据 | 来源、版本、质量、可用时间、不确定性、复核状态 |

### 6.3 动作生命周期

同一个业务意图必须区分：

~~~text
proposed action
  -> approved action
  -> issued command
  -> accepted command
  -> executed actuator state
  -> measured boundary flux
  -> observed outcome
~~~

模型状态转移优先使用实际执行状态和实测边界通量。计划、批准或下发值只能在无法获得执行值时作为带明确不确定性的代理，不能静默替代。

### 6.4 外生情景

外生情景至少包含：

- 天气预报及其 issue time 和版本；
- 上游供水或来水情景；
- 作物需水预测；
- 设备故障或检修情景；
- 价格、能耗或其他运行条件；
- 数据缺测和通信故障情景。

历史评估只能使用当时可获得的预报版本。事后再分析数据可用于诊断，不能冒充实时输入。

### 6.5 水量账

对任一渠系控制体，最低限度的水量账为：

~~~text
next_storage
= current_storage
+ upstream_inflow
+ lateral_inflow
+ explicit_analysis_increment
- downstream_outflow
- diversion
- evaporation
- seepage
+ numeric_residual
~~~

所有项必须统一时间和单位。状态同化增量、物理通量、经验损失和数值残差必须分账。

对田块根区，最低限度的水量账为：

~~~text
next_root_zone_water
= current_root_zone_water
+ precipitation
+ applied_irrigation
+ capillary_rise
- runoff
- evapotranspiration
- deep_percolation
+ explicit_analysis_increment
~~~

学习模型不能通过不可审计的自由残差凭空增加或删除水量。若使用残差修正，应优先修正有物理含义且有界的参数、状态或成对通量。

### 6.6 多时间尺度耦合

渠系和田间模型不使用统一粗时间步强行计算。建议：

- 渠系模型按分钟或小时推进；
- 田间水分按小时汇总到日级状态；
- 作物过程按日或生育阶段推进；
- 调度在固定滚动窗口内更新；
- 新观测到达后执行状态同化并重新规划。

渠系向田间输出实际到达水量、时间和质量；田间向调度层输出需水、可接受供水窗口、胁迫风险和回归水估计。耦合接口必须保持守恒和来源可追溯。

### 6.7 条件情景与因果效应的区别

对于固定初始 belief state、外生情景分布和模型集合，不同动作产生的结果差异属于模型条件情景：

~~~text
delta_model = rollout(action_A) - rollout(action_B)
~~~

只有在动作定义、混杂控制、试验或准实验、模型适用性和外推范围均有充分证据时，才可以进一步讨论因果效应。系统必须在报告中标明：

- 结果是专业模型情景、学习模型情景还是观察数据估计；
- 是否存在独立干预证据；
- 哪些假设不可验证；
- 是否超出训练、校准或观测支持范围。

## 7. 灌区本体设计

### 7.1 本体的职责

本体负责：

- 定义现实世界中的稳定对象、状态、过程、角色、规则、信息对象和观测；
- 约束对象间允许存在的关系；
- 定义状态变量、单位、空间支撑和时间支撑；
- 定义动作类型、适用对象、前置条件和能力边界；
- 提供来源数据、字段、接口和模型端口到领域语义的映射；
- 支持能力问题、形状校验、版本管理和审定；
- 为跨灌区映射提供稳定 ID 和有方向的对应关系。

本体不负责：

- 保存全部高频遥测、栅格和几何；
- 执行水动力或作物模型；
- 自动产生业务规则的所有运行时判断；
- 自动识别因果关系；
- 自动决定方案目标权重；
- 承担设备控制事务。

### 7.2 模块划分

建议将以下模块严格分离：

1. **核心语义模块。**实体、状态、过程、观测、动作、规则、角色、证据和时间的通用概念。
2. **灌区领域模块。**水源、渠系、工程、田块、土壤、作物、用水与调度概念。
3. **参考分类模块。**工程类型、作物分类、土壤分类、设备状态、质量等级等代码表，优先使用 SKOS。
4. **数据映射模块。**数据库表、字段、传感器标签、文件和接口与领域概念的映射。
5. **运行能力模块。**查询、模型、函数、ActionDefinition 和执行适配器的能力描述。
6. **来源与证据模块。**标准、文档、数据制品、模型版本、运行记录和审定状态。

领域本体不能因为来源数据库中存在一张表，就自动创建一个领域类；运行工具、数据库表和应用菜单也不能进入现实对象的类层次。

### 7.3 核心对象

| 类别 | 核心对象 |
|---|---|
| 灌区与管理 | IrrigationDistrict、ManagementArea、WaterUser、ManagementOrganization |
| 水源 | Reservoir、RiverIntake、GroundwaterWell、TransferInlet |
| 输配水网络 | CanalReach、Junction、Turnout、DeliveryPoint、DrainageReach |
| 控制工程 | Gate、PumpStation、CheckStructure、ControlDevice |
| 量测设施 | WaterLevelStation、FlowGauge、SoilMoistureSensor、WeatherStation |
| 农业空间 | FieldParcel、IrrigationUnit、SoilProfile、CropStand |
| 信息对象 | Observation、Forecast、StateEstimate、Rule、Quota、Proposal、Command、Receipt |
| 过程 | Conveyance、Diversion、IrrigationApplication、Infiltration、Evapotranspiration、CropGrowth |

类名和中文标签可在实施阶段本地化，但稳定 ID 不应依赖可变标签。

### 7.4 核心关系

| 关系 | 语义 |
|---|---|
| upstreamOf / downstreamOf | 权威水流方向 |
| conveysWaterTo | 输水对象关系 |
| divertsFrom / deliversTo | 分水和交付关系 |
| controlledBy | 渠段或构筑物由控制设备调节 |
| observedBy | 对象由量测设施观测 |
| supplies | 水源或渠系向用水单元供水 |
| contains / partOf | 管理或空间层级 |
| hasSoilProfile | 田块与土壤剖面关系 |
| growsCrop | 田块与作物群体关系 |
| governedBy | 对象或动作受规则约束 |
| subjectToQuota | 对象或主体受配额约束 |
| targets | 动作指向对象 |
| generatedFrom | 状态、结果或 Proposal 的来源 |

水力传播关系必须有方向、有效时间和来源证据。邻近或空间相交不能自动升级为水力连通。

### 7.5 实体、状态和过程分离

渠段、闸门和田块是持续存在的实体。某一时刻的水位、开度、作物状态和配额余额是带有效时间的状态记录。输水、灌溉、入渗和蒸散是过程。

不应通过不断改变实体的 OWL 类型来表达高频状态，也不应覆盖历史事实。动态状态应保存在适合时序和事务查询的状态存储中，并引用稳定实体 ID 和本体版本。

### 7.6 观测、状态、强迫、动作和结果分离

本体和数据合同必须明确以下角色：

| 角色 | 示例 |
|---|---|
| Observation | 流量计读数、遥感指数、土壤传感器值 |
| StateEstimate | 同化后的渠段存量、根区水分 |
| Forcing | 降雨预报、上游供水情景、气温 |
| ProposedAction | 候选闸门或配水计划 |
| ExecutedAction | 实际设备状态和执行时段 |
| BoundaryFlux | 实测或核验后的实际过流和入田水量 |
| Outcome | 未来水位、胁迫、用水、公平和能耗 |
| Evidence | 来源、哈希、质量、模型版本和审批记录 |

### 7.7 动作定义

每个 ActionDefinition 至少包含：

- 稳定动作类型 ID 和版本；
- 允许的目标对象类型；
- 输入参数、单位、范围和时间剖面；
- 前置条件；
- 工程能力与硬约束；
- 可能副作用；
- 风险等级；
- 所需审批角色；
- 幂等规则；
- 执行适配器；
- 外部回执和对账方式；
- 失败、撤销和补偿方式；
- 可用于训练、评估或生产的证据等级。

动作定义可以引用本体稳定 ID，但动作事务状态不写入 OWL。

### 7.8 时间和版本

至少区分：

- valid time：事实在现实中何时有效；
- transaction time：系统何时记录或更正该事实；
- issue time：预报或 Proposal 何时发布；
- available at：数据何时可被模型实际获得；
- executed time：动作何时实际执行；
- observed time：结果何时被观测。

历史回放必须按照 issue time 和 available at 截断数据，防止未来信息泄漏。

### 7.9 形式语义与运行时边界

建议使用：

- OWL 表达类、属性、互斥和基础公理；
- SKOS 表达分类体系、代码和有方向映射；
- SHACL 表达记录完整性、基数、单位和允许状态转换；
- PROV-O 表达来源与派生；
- GeoSPARQL 表达空间对象和关系语义；
- OWL-Time 表达时间概念。

OWL 的开放世界语义不足以执行全部闭世界业务规则。工程容量、配额、时窗、权限和设备状态仍需规则引擎、事务服务和数值模型校验。完整 OWL 推理应主要用于离线发布门，不作为高频在线控制依赖。

### 7.10 权威、发布与投影

推荐采用：

~~~text
事务型权威本体模型
  -> 确定性编译
  -> 不可变版本包
  -> OWL/RDF/SHACL/JSON-LD 发布制品
  -> 可重建的只读图投影
~~~

发布版本不可原地修改。回滚通过切换活动版本指针完成。所有运行、查询、状态编译、模型训练和 Proposal 均绑定精确版本和内容哈希。

大规模几何、高频时序、栅格、模型张量和运行结果继续保存在空间数据库、时序存储、湖仓或对象存储中；RDF 保存语义、关系、引用和来源，不承担全部数据载荷。

### 7.11 映射治理

来源表、字段、设备标签和地方术语只能形成以下映射状态：

- confirmed：严格匹配或经专家审定；
- candidate：自动发现但未审定；
- conflict：存在冲突；
- rejected：已确认不等价；
- deprecated：旧版本映射。

名称相似或大模型判断不能直接产生 owl:sameAs。跨灌区对齐必须保留方向、来源、版本、适用时间和审定人。

### 7.12 能力问题

本体首版发布前至少应回答：

1. 给定水源，能否遍历到所有合法供水路径和交付点？
2. 给定田块，能否找到其供水渠系、水源、管理主体和适用配额？
3. 哪些闸门和泵站能影响指定交付点？
4. 给定控制设备，允许执行哪些动作，参数和单位是什么？
5. 某动作受到哪些容量、安全、时窗、配额和审批约束？
6. 某一时刻的观测、状态估计和实际执行记录分别是什么？
7. 哪些观测可用于某个状态变量的同化？
8. 哪些渠道关系是权威水力连通，哪些只是空间邻近？
9. 某个 Proposal 使用了哪个本体、数据、预报、模型和规则版本？
10. 某项跨灌区映射是 confirmed、candidate 还是 conflict？
11. 能否识别指令与实际执行不一致的事件？
12. 能否找到某次运行中的水量账、约束检查和人工审批证据？

能力问题、SHACL、拓扑校验、单位校验和领域专家审定必须全部独立报告，不能用“类数量”作为本体质量指标。

## 8. 数据与状态构建设计

### 8.1 数据分层

数据按其在推演中的角色管理，而不是按文件格式简单归档：

| 数据层 | 内容 | 主要用途 |
|---|---|---|
| 权威静态数据 | 灌区边界、渠系、断面、闸泵、田块、土壤和规则 | 对象身份、拓扑和硬约束 |
| 高频观测 | 水位、流量、闸位、泵站工况、气象和土壤水分 | 状态估计与在线校正 |
| 预报与情景 | 天气、供水、需水和设备情景 | 外生 forcing |
| 动作记录 | 计划、批准、指令、设备状态和实际过流 | 动作条件训练与对账 |
| 农业过程 | 作物、物候、灌溉、蒸散、胁迫和产量 | 田间模型和季节后评估 |
| 规则与权利 | 调度规程、水权、配额、优先级和审批权限 | action mask 和 policy |
| 模型与证据 | 模型版本、参数、运行环境、评价和人工复核 | 复现与 claim gate |

### 8.2 数据记录最低合同

每条可进入模型的数据至少包含：

- 稳定对象 ID；
- 变量或关系的本体 ID；
- 数值、单位和缺测状态；
- 空间支撑和时间支撑；
- valid time；
- available at；
- 来源标识和制品哈希；
- 质量等级和审定状态；
- 本体与映射版本；
- 是否允许用于训练、开发、验证或在线运行；
- 是否可能包含目标或未来信息。

对高频时序，还需声明采样、聚合、修订和迟到数据策略。

### 8.3 权威拓扑编译

渠系图必须从权威 GIS、工程台账和现场核验材料编译。编译过程至少验证：

- 节点和渠段身份唯一；
- 上下游方向明确；
- 分支和汇合完整；
- 闸门、泵站和分水口挂接位置正确；
- 断面、长度、坡度、糙率或其他模型参数有来源；
- 田块与交付点的供水关系经过审定；
- 关系有效时间覆盖实验窗口；
- 拓扑版本与模型输入轴一致。

学习模型可以学习传播强弱、时延和残差，但不能制造缺失的权威水力连接，也不能改变稳定对象身份和基本方向。

### 8.4 观测编译

观测编译负责：

- 统一单位、坐标、时区和采样频率；
- 识别设备校准、漂移、断线和异常；
- 记录原始值、质量控制值和派生值；
- 保留缺测，不静默插值；
- 对插值、同化和估算值标记方法、输入和不确定性；
- 按 issue time 截断历史回放可见数据；
- 输出完整的 observation manifest。

缺测可以通过显式 mask、训练期统计或状态估计处理，但不能用零值、前向填充或未来数据静默代替。

### 8.5 Belief-State Estimator

状态估计器将观测、模型和历史执行动作合成为 belief state。首期应优先使用透明、可诊断的方法：

- 质量控制后的直接观测映射；
- 水量账和边界条件反演；
- 卡尔曼滤波、集合卡尔曼滤波或其他适用的状态同化；
- 田间土壤水分的水量平衡更新；
- 在数据足够后比较学习型状态估计器。

每次分析更新必须单独记录：

~~~text
analysis_increment = posterior_state - prior_state
~~~

analysis increment 不是水力转移通量，也不能被计入动作效果。状态估计器应输出均值、区间、支持观测和质量状态。

### 8.6 状态快照

每个可复现状态快照至少绑定：

- snapshot ID 和 issue time；
- 本体版本和实例图哈希；
- 数据 manifest；
- 状态估计器及参数版本；
- 每个对象的显式状态与不确定性；
- 历史执行动作窗口；
- forcing vintage；
- 规则与权限版本；
- 缺测和降级说明。

Planner 和模拟器只能消费已冻结的状态快照，不能在运行中静默读取更新后的数据。

### 8.7 训练样本单位

有效训练样本不是传感器行数或图节点数量，而是具有独立初始状态、动作、外生强迫和结果支持的轨迹窗口或事件。

每个 transition example 至少包含：

~~~text
issue-time state snapshot
+ executed action sequence
+ issue-time available forcing
+ authoritative graph
+ rules and masks
-> future observations or state targets
+ provenance and evidence class
~~~

同一事件内高度相关的分钟级记录不能被当作大量独立样本夸大有效样本量。

### 8.8 数据切分

至少设置：

- 时间切分：不同灌溉季或连续时间块；
- 事件切分：独立供水、故障、短缺或天气事件；
- 空间切分：未见支渠、田块或用水单元；
- 灌区切分：整灌区留出；
- 极端情景压力测试；
- 前瞻影子窗口。

禁止随机拆分相邻时间行导致泄漏。归一化、特征选择、参数校准和阈值选择只能使用训练与开发数据。

## 9. 混合动力学与模型路由

### 9.1 总体原则

动力学层采用专业模型、状态估计和学习模型的组合，而不是纯端到端替代：

~~~text
当前 belief state
+ 实际或候选动作
+ 外生情景集合
+ 权威渠系与田块图
+ 工程和治理约束
        |
        v
专业模型 / 简化模型 / 学习型代理的受控路由
        |
        v
未来状态、结果、不确定性、水量账和适用性证据
~~~

模型路由必须依据任务、空间范围、可用数据、模型适用范围、计算预算和证据等级，不由语言模型自由决定。

默认路由顺序为：通过校准和适用性检查的专业模型，透明简化模型或状态空间/降阶模型，通过独立准入的学习型代理。只有在需要大量情景 rollout 且专业模型不能满足计算预算时，才以代理模型承担限定范围的预演；进入规划的候选结果仍需按风险和适用性由专业模型抽查、复核或使用独立评估器判定。路由顺序只能由冻结策略和证据等级改变，不能因为某种模型名称更“先进”而改变。

### 9.2 渠系水动力

候选模型包括但不限于：

- 完整或简化的一维 Saint-Venant 模型；
- 运动波或扩散波近似；
- 水库和渠池蓄量模型；
- 经过验证的渠系专用仿真软件；
- 适用于特定渠系的状态空间或传递函数模型。

不能预先假定所有渠段都需要完整 Saint-Venant 方程，也不能用简化模型覆盖存在回水、反向流、复杂控制结构或显著非恒定流的场景。模型选择应由工况、数据和独立验证决定。

### 9.3 田间土壤水分

候选模型包括：

- 根区水量平衡或分层桶模型；
- Richards 方程模型；
- 经过验证的田间水分模型；
- 机理模型加区域参数校准或残差修正。

Richards 方程不应仅因理论完整就默认用于所有田块。若土壤参数和边界资料不足，复杂模型可能不可识别。首期应同时保留透明强基线，并报告参数不确定性。

### 9.4 作物蒸散与生长

首期可以从经验证的参考蒸散、作物系数和水分胁迫模型起步。若数据支持，再比较 AquaCrop、DSSAT、APSIM 或其他经过验证的作物模型。

作物模型选择必须明确：

- 适用作物和区域；
- 时间尺度；
- 参数来源；
- 校准与验证分离；
- 水分胁迫和产量响应边界；
- 许可和部署条件。

产量属于季节性结果，不能被短期水位或土壤水分预测精度自动背书。

### 9.5 渠系—田间耦合

耦合量必须是显式边界通量：

- 渠系向田间：实际到达水量、到达时间、供水持续时间和质量；
- 田间向渠系或排水系统：地表径流、排水、回归水和其不确定性；
- 田间向规划器：需水窗口、胁迫风险和可接受延迟；
- 调度向渠系：批准的目标流量、闸位或泵站计划。

同一水量在渠系出口和田间入口之间必须有对账规则，输水损失和未计量差异不能隐入学习模型。

### 9.6 模型注册

每个模型版本至少登记：

- 模型名称、版本、许可和实现身份；
- 输入输出变量及本体映射；
- 空间、时间和工况适用范围；
- 参数来源和校准窗口；
- 训练、开发和验证数据范围；
- 数值容差和守恒规则；
- 已知失败模式；
- 性能基准；
- 是否允许用于研究、影子运行或受控试点；
- 运行环境、制品哈希和依赖。

模型适用性判断失败时必须停止或降级，不能静默切换到未经验证的模型。

### 9.7 学习残差的边界

学习模型可以：

- 修正受界糙率、渗漏系数或其他可解释参数；
- 修正状态估计偏差；
- 学习已记账通量的受界残差；
- 作为专业模型的快速代理；
- 估计模型分歧和不确定性。

学习模型不能：

- 改变权威对象 ID、方向或渠系拓扑；
- 产生未记账的自由水源或水汇；
- 用任意 latent 值覆盖硬约束；
- 在已评分隐藏窗口上继续调参；
- 将合成轨迹标记为真实干预结果。

## 10. 学习型快速代理与可选 JEPA 研究

### 10.1 定位

学习型快速代理的目标是在明确任务和误差门槛下补充专业模型，而不是替代 Geospatial Kernel、守恒账或专业机制。首轮至少应比较：

- 线性或非线性状态空间模型；
- 简化机理模型和降阶模型；
- 专业模型加受界残差；
- 直接监督的图时空模型；
- 适用时的神经算子；
- 满足专门条件时的 JEPA 式潜在预测模型。

候选模型共享相同的对象、状态、动作、forcing、拓扑、数据切分和评价合同。模型选择依据是显式状态误差、多步稳定性、守恒和约束违规、OOD 风险、计算成本及规划复核通过率，不依据是否使用 JEPA、PINN 或其他特定名称。

### 10.2 JEPA 的触发条件与命名边界

JEPA 不是默认候选。只有在数据审计表明存在足够多相互独立的轨迹窗口、较丰富的无标签多模态观测、可定义且有业务意义的遮蔽目标，以及独立时间/事件测试窗口时，才启动 JEPA 实验。若问题只有少量结构化状态变量和明确监督目标，直接监督、状态空间或降阶路线通常更容易验证，应优先作为基线。

称为 Irrigation-JEPA 的模型至少应具有：

- 明确分离的 context encoder 与 target encoder；
- target 分支停止梯度，并采用预注册、可复现的更新机制，例如 EMA；
- 对被遮蔽对象、变量、空间区域或未来窗口的 target embedding 进行预测；
- predictor 只消费 issue time 可用的 context、候选动作和 forcing；
- 防止 target 分支的未来执行状态或事后信息泄漏到 context；
- 相对同容量直接监督或普通潜在动力学模型的独立消融。

只使用冻结地理 embedding，再用网络回归下一时刻 embedding，属于“冻结表征 + 潜在动力学预测”；没有 context/target 分支和 JEPA 目标时，应称为潜在动力学模型或学习型代理，不命名为 Irrigation-JEPA。

即使满足上述结构，Irrigation-JEPA 仍只是一种待验证的对象关系潜在动力学候选，不是整个系统的同义词，也不是产品上线的前置条件。

以下 10.3 至 10.13 节给出 JEPA 候选的研究设计约束，不要求状态空间、降阶、受界残差或其他非 JEPA 代理照搬其网络结构；所有候选只共享输入输出合同、硬约束和评价协议。

它借鉴联合嵌入预测架构的思想，在潜在表示中预测未来对象状态，但必须同时满足：

- 潜在表示与稳定对象、关系和显式状态有可审计对应；
- 动作和外生强迫显式进入转移；
- 多步 rollout 写回未来状态；
- 关键状态可解码并按专业指标验证；
- 硬拓扑和水量账不能被潜在模型绕过；
- 与无本体、无物理、无动作和专业模型基线公平比较。

### 10.3 输入表示

输入不是一张平面表，而是类型化异构图：

~~~text
nodes:
  water source
  canal reach
  gate / pump / turnout
  delivery unit
  field parcel
  soil profile
  crop stand
  management unit

edges:
  hydraulic direction
  control relation
  delivery relation
  containment
  observation relation
  governance relation
~~~

每个节点包含：

- 稳定 ID 和对象类型；
- 显式数值状态；
- 数据质量和缺测 mask；
- 可选静态属性；
- 可选潜在表示；
- 允许动作和约束摘要。

关系边包含类型、方向、参数、有效时间、来源和置信状态。

### 10.4 编码器

建议使用类型专用编码器，将不同对象的显式状态投影到共同计算空间，同时保留对象类型和变量可解释性。

可比较：

- 显式特征与简单图模型；
- 类型化图神经网络；
- graph transformer；
- 不使用图关系的对照模型。

复杂模型只有在未见事件、长时 rollout 或规划消费上提供稳定增益时才应保留。

### 10.5 Context 与 target

训练时，context 只包含 issue time 可获得的信息。target 可以是未来对象的潜在表示和显式状态，但必须防止：

- 将未来观测泄漏到 context；
- 从相邻时间或同一事件的随机拆分泄漏；
- 使用验证窗口拟合归一化；
- 让 target encoder 读取候选动作之外的未来执行信息。

target encoder 的参数不接受 predictor 侧反向梯度，其更新规则、遮蔽策略和 collapse 防护必须在实验前冻结。JEPA 目标不能只验证 latent 相似度。至少需要显式状态、水量账、动作响应和规划相关指标，并与去除 JEPA 目标但保持容量接近的模型比较。

### 10.6 动作注入

动作通过目标对象、能力端口、时间剖面和物理单位进入模型。例如：

~~~text
action = {
  type,
  target_object,
  start_time,
  duration,
  magnitude,
  unit,
  command_status,
  execution_status
}
~~~

动作只能作用于本体和工程能力允许的端口。不能把自然语言“增加供水”直接编码为无边界 latent perturbation。

### 10.7 外生条件

天气、上游供水和需水情景通过独立 forcing encoder 进入模型，并保留预报版本和集合成员。必须设置：

- no-forcing 对照；
- forcing shuffle 对照；
- 事后资料泄漏检查；
- 预报误差敏感性分析。

### 10.8 多速率转移

建议将快速渠系状态和较慢田间、作物状态分开更新：

~~~text
fast hydraulic transition: minutes / hours
slow soil-crop transition: hours / days
governance and operation state: event driven
~~~

各子模型通过显式供水和需求通量耦合，而不是在一个时间步中同时更新所有变量。

### 10.9 输出头

至少输出：

| 输出 | 用途 |
|---|---|
| future explicit state | 水位、流量、土壤水分、胁迫等 |
| future latent state | 后续多步预测和表示学习 |
| mass and constraint residual | 守恒与约束检查 |
| action feasibility | 允许、阻断或需要复核 |
| outcome vector | 水量、胁迫、公平、能耗等分离指标 |
| uncertainty | 数据、参数、模型和情景不确定性 |
| applicability | 是否位于训练和校准支持范围 |

Evidence gate 不应由学习模型自行给出最终结论，而由独立规则和验证结果计算。

### 10.10 训练目标

对满足 10.2 命名边界的 JEPA 候选，训练目标可以写为：

~~~text
L =
  λ_state * L_explicit_state
+ λ_jepa * L_latent_prediction
+ λ_rollout * L_multistep
+ λ_mass * L_mass_balance
+ λ_action * L_action_response
+ λ_constraint * L_constraint
+ λ_uncertainty * L_calibration
+ λ_distill * L_professional_model
~~~

其中：

- 显式状态损失验证真实业务变量；
- JEPA 损失学习对象级未来表示；
- 多步损失控制误差累积；
- 水量损失不能替代硬守恒层；
- 动作响应损失用于区分动作和 forcing；
- 约束损失辅助预测风险，但硬约束仍由独立 mask 执行；
- 不确定性损失验证概率校准；
- 专业模型蒸馏只支持近似该模型，不自动支持真实世界因果。

损失权重只能用训练和开发集选择。不能因某个权重在隐藏测试集表现好而事后调整。

### 10.11 物理约束方式

物理融合按优先级考虑：

1. 权威拓扑和动作端口硬约束；
2. 数值计算前后的单位、容量和非负检查；
3. 显式守恒层或投影到可行状态；
4. 专业模型提供状态或通量；
5. 有界参数或通量残差；
6. 物理损失、弱形式约束或适用的 PINN；
7. 神经算子等代理架构，并另行施加和验证守恒与边界约束。

PINN 只是候选物理信息学习技术；神经算子首先是一类算子学习代理，并不因名称而自动满足物理规律。若它们在复杂渠网、刚性过程、长时 rollout 或训练成本上不优于其他方法，应保留否证并采用更合适的混合路线。

### 10.12 不确定性

至少区分：

- 观测噪声和缺测；
- 初始状态不确定性；
- 天气和供水情景不确定性；
- 参数不确定性；
- 模型结构不确定性；
- 跨灌区域偏移；
- 规划目标和权重不确定性。

可使用集合模型、参数集合、概率输出、conformal prediction 或模型间分歧，但必须用独立数据检验覆盖率和风险校准。

### 10.13 模型晋级条件

任何学习型代理只有在以下条件全部满足后，才能进入规划实验：

- 状态和关系合同通过；
- 未见时间和事件上的显式状态预测通过；
- 多步水量账和稳定性通过；
- action-agnostic、action shuffle 和错误拓扑对照按预期退化；
- 相对专业模型和简单基线的优势或速度价值明确；
- 不确定性和适用性门通过；
- 未读取规划评估和影子运行结果进行调参。

若采用 JEPA，还必须证明 JEPA 目标相对同容量直接监督或普通潜在动力学模型具有可重复增量；否则不得把一般代理模型结果归因于 JEPA。未通过的模型仍可作为研究结果和失败案例，但不能进入生产候选。即使所有学习型代理均未通过，专业模型和约束优化路线仍继续作为系统主线。

## 11. 反事实推演设计

### 11.1 问题模板

允许的问题类型包括：

- 如果未来供水减少，现有轮灌计划会产生什么影响？
- 如果某一闸门或泵站不可用，哪些交付点受影响？
- 如果将某一供水时段前移或后移，田间胁迫如何变化？
- 如果采用不同天气集合，方案排序是否稳定？
- 如果提高尾端保障或公平约束，总用水和能耗如何变化？
- 如果测站缺测，方案不确定性和可执行级别如何变化？

这些问题是条件情景，不因使用“如果”就自动构成统计因果反事实。

### 11.2 情景冻结

每次推演必须冻结：

- 初始 belief state；
- forcing ensemble 和 vintage；
- 候选动作集合；
- 专业和学习模型版本；
- 本体、拓扑和规则版本；
- 时间范围和输出指标；
- 不确定性处理；
- 评价与排序规则。

不同候选方案必须使用相同的初始状态和外生情景集合，除非差异本身就是实验变量。

### 11.3 输出

每个情景输出：

- 逐步状态轨迹；
- 水量账；
- 关键控制点水位和流量；
- 田块供水与土壤水分；
- 作物胁迫；
- 配额和硬约束状态；
- 总用水、能耗和供水公平；
- 不确定性区间；
- 模型适用性；
- 与 baseline 的差异；
- 证据等级和禁止声明。

## 12. Planner 与 Proposal

### 12.1 Planner 的职责

Planner 负责在限定动作空间中生成或比较候选动作序列。它不负责定义世界状态，不拥有设备权限，也不能自行设定公共目标权重。

首期建议采用两种模式：

1. **候选比较模式。**专家、规程或现有优化模型提供候选，系统负责统一推演和比较。
2. **受约束搜索模式。**Planner 在冻结动作模板、范围和计算预算内生成候选。

优先从候选比较模式开始，避免同时验证世界模型和开放式规划器。

### 12.2 方法选择

不同问题适用不同规划方法：

| 问题结构 | 候选方法 |
|---|---|
| 连续流量和滚动控制 | MPC、鲁棒 MPC |
| 离散轮灌和组合调度 | MILP、动态规划、约束搜索 |
| 分层离散决策 | MCTS、beam search |
| 多目标方案比较 | Pareto 排序、稳健决策 |
| 规则明确且规模有限 | 规则引擎和枚举 |

对连续渠系流量和滚动控制，MPC 或鲁棒 MPC 是首要规划基线；对轮灌、配水组合和离散时窗，优先比较 MILP 或约束搜索。MCTS 只有在动作离散化、分支因子、rollout 成本和停止条件经过证明后才采用。不能为了满足概念设计而强行使用。

### 12.3 硬约束与目标

硬约束不进入可补偿的综合分数：

- 工程容量和设备能力；
- 水位、流量和安全限制；
- 水权与配额；
- 取水、供水和轮灌时窗；
- 最低生态或基本供水要求；
- 设备不可用状态；
- 权限和审批边界；
- 数据或模型证据不足时的禁用规则。

目标保持为向量：

- 总供水满足程度；
- 作物胁迫及减产风险；
- 水分生产率；
- 尾端和主体间公平；
- 能耗和运行成本；
- 深层渗漏或环境风险；
- 方案稳定性和切换成本；
- 不确定性与尾部风险。

Planner 输出 Pareto 或非支配候选，不使用未经授权的单一“社会最优”分数。

### 12.4 Proposal 合同

每个 Proposal 至少包含：

~~~text
proposal_id
question_and_scope
state_snapshot_id
ontology_graph_rule_versions
forcing_vintage_and_ensemble
candidate_action_sequence
action_definition_versions
hard_constraint_results
rollout_trace_references
outcome_vector
uncertainty_and_applicability
baseline_comparison
model_and_runtime_versions
evidence_gate_results
required_review_roles
expiry_and_revalidation_conditions
prohibited_claims
~~~

Proposal 是候选方案和证据载体，不是执行命令。任何状态、预报、规则或模型版本变化都可能使 Proposal 失效。

### 12.5 排序边界

只有在以下条件下才允许排序：

- 候选均通过硬约束；
- 使用相同状态和 forcing；
- 指标定义一致；
- 权重由授权主体确认；
- 不确定性和适用性可比；
- 模型在相应工况通过验证。

不满足条件时，系统应输出不可比原因、敏感性或需人工复核，而不是强制生成第一名。

## 13. 本体增强的交互与工具编排

### 13.1 总体路径

自然语言交互采用：

~~~text
用户问题
  -> 意图、主体、时间和空间范围识别
  -> 本体稳定 ID 与关系 grounding
  -> 权限和目的检查
  -> 类型化查询或工具计划
  -> 确定性数据、GIS、模型或规则执行
  -> Proposal 或解释性结果
  -> 证据引用和边界说明
~~~

语言模型不直接计算水动力、土壤水分、作物需水或最优调度。

### 13.2 查询通道

按问题类型路由：

- 本体服务：概念、关系、动作、规则和映射；
- 指标服务：已治理的汇总指标；
- 结构化查询：遥测、状态、计划、执行和结果；
- GIS 工具：空间连接、网络和区域计算；
- 模型服务：状态估计、模拟和规划；
- 文档检索：规程、标准、报告和解释性证据。

本体查询不能替代时序、空间和文档数据；文档检索也不能成为业务事实的新权威。

### 13.3 LLM 边界

语言模型：

- 不持有生产数据库或设备控制凭据；
- 不直接访问未经授权的原始数据；
- 不执行任意 SQL、SPARQL、Python 或系统命令；
- 只输出已注册的类型化查询和工具计划；
- 不能修改本体活动版本、模型和规则；
- 不能伪造数值、证据或执行回执；
- 不能绕过拒绝、超时或人工审批；
- 对歧义对象、时段、单位和目标必须请求确认。

类型化查询计划可以由确定性网关编译为参数化 SQL 或有界 SPARQL，并经过 schema grounding、只读检查、权限、预算、行数、超时和审计控制。

### 13.4 分层推理

- 简单分类、范围和允许值由规则或 SHACL 校验；
- 关系路径由有界图查询处理；
- 必要的 OWL 推理在发布阶段离线执行；
- 数值约束由规则引擎和数值模型处理；
- 动态规划由 Planner 处理；
- 语言模型负责组合已有能力，不替代其算法。

## 14. Action 七阶段管线

### 14.1 阶段一：定义与版本准入

- 动作类型已注册；
- 目标对象类型和执行端口明确；
- 参数、单位、范围和时窗明确；
- 风险、审批、幂等和回执合同明确；
- 执行适配器已登记并通过测试。

### 14.2 阶段二：Proposal 实例化

- 绑定状态、预报、本体、规则和模型版本；
- 形成候选动作序列；
- 保留问题、目标、权重和来源；
- 设置有效期和重验证条件。

### 14.3 阶段三：准入、策略与模拟

- 执行语义、单位、拓扑和能力检查；
- 执行权限、目的和风险策略；
- 执行硬约束和多模型 rollout；
- 生成证据门、风险和不确定性；
- 任一非补偿门失败即拒绝或要求复核。

### 14.4 阶段四：人工审查与批准

- 显示候选、baseline、敏感性和失败条件；
- 审批人可接受、拒绝、修改或要求重算；
- 修改后形成新版本，不能覆盖原 Proposal；
- 高风险动作采用双人复核或指定会商流程。

### 14.5 阶段五：事务提交与 Outbox

- 生成幂等 ActionRun；
- 在本地事务中记录批准、参数和目标；
- 通过 Outbox 异步触发外部副作用；
- 不宣称本地事务与外部控制系统能够原子提交；
- 重试不得导致重复执行。

### 14.6 阶段六：外部执行、回执与对账

- 区分已发送、已接收、已执行和执行失败；
- 保存设备或外部系统回执；
- 对账指令、设备状态和实测边界通量；
- 未知、超时和冲突状态 fail closed；
- 必要时进入撤销、补偿、人工接管或事故处理。

### 14.7 阶段七：状态同化与事后审计

- 将实际执行和观测结果写入新状态；
- 不把失败指令当成已执行动作；
- 比较预测与实际结果；
- 记录人工修改和驳回原因；
- 更新 Failure Memory 和模型监控；
- 触发漂移、退化和再验证流程。

首期仅要求完成到影子 Proposal 与人工审查。阶段五至七的真实控制只能在独立安全审查和受控试点中逐步开放。

## 16. 典型业务工作流

### 16.1 当前状态重建

1. 选择灌区范围和 issue time。
2. 解析本体和实例图版本。
3. 编译当时可用的遥测、气象、田间和运行记录。
4. 执行质量控制和缺测处理。
5. 运行渠系和田间状态估计。
6. 形成带不确定性的状态快照。
7. 输出水量账、质量问题和需人工核验对象。

### 16.2 “如果……会怎样”推演

1. 将自然语言条件落地为 forcing 或候选动作。
2. 检查对象、单位、时窗、权限和动作能力。
3. 冻结 baseline 和 intervention。
4. 对相同 forcing ensemble 分别执行 rollout。
5. 比较结果向量和不确定性。
6. 标记模型条件、外推和证据等级。
7. 输出情景报告，不自动升级为因果结论。

### 16.3 候选配水 Proposal

1. 专家或 Planner 形成有限候选集。
2. 硬约束先行过滤。
3. 每个候选执行相同预算的 ensemble rollout。
4. 输出水量、胁迫、公平、能耗和尾部风险。
5. 生成 Pareto 候选和敏感性分析。
6. 人工选择、修改、拒绝或要求重算。
7. 影子阶段记录“若执行会怎样”，但不向设备下发。

### 16.4 灌溉季后复盘

1. 对账计划、批准、指令、实际设备状态和实测水量。
2. 比较预测与实际状态和结果。
3. 识别数据、状态估计、专业模型、学习模型和规划器误差。
4. 记录专家修改、驳回和现场原因。
5. 更新失败案例，但不自动重训生产候选。
6. 通过完整再验证后才能升级模型版本。

## 17. 首期原型设计

### 17.1 原型目标

建立一个能够在历史回放和前瞻影子环境中运行的“渠系配水—田间灌溉协同推演原型”，验证：

- 灌区本体能否支撑数据和动作语义一致性；
- 当前状态能否被可靠重建；
- 专业模型能否形成统一水量账；
- 学习代理能否在明确任务上增加预测或速度价值；
- 候选 Proposal 能否被专家理解、复核和审计。

### 17.2 推荐范围

- 一个代表性支渠或管理片区；
- 具有量测的上游边界和若干下游交付点；
- 有明确拓扑的闸门、泵站和渠段；
- 若干具有作物和土壤资料的田块或用水单元；
- 一种主要作物；
- 一个完整灌溉季，最好另有独立季节用于验证；
- 一个明确的运行规程和配额体系。

如果只有一个灌溉季，训练型世界模型的证据会非常有限。此时应优先建设专业模型、状态估计和数据闭环，将学习模型限定为探索性研究。

### 17.3 输入

- 渠系与工程权威图；
- 断面、能力和参数；
- 水位、流量、闸位和泵站工况；
- 计划、指令、执行和实际过流；
- 田块、土壤、作物和灌溉记录；
- 气象观测和历史预报 vintage；
- 水权、配额、轮灌和审批规则；
- 模型、参数和数据质量证据。

### 17.4 输出

- issue-time 状态快照；
- 历史回放和未来情景轨迹；
- 水量账与缺口；
- 田块供水、土壤水分和胁迫；
- 候选动作可行性；
- 多目标结果与不确定性；
- Proposal 和人工评审记录；
- 模型、数据、规则和运行审计报告。

### 17.5 不做

- 不直接控制设备；
- 不承诺给出全局最优；
- 不自主决定供水公平或政策权重；
- 不评价历史人员对错；
- 不将合成轨迹当作真实效果；
- 不将一个季节的结果外推为长期气候适应能力；
- 不在首期同时加入施肥、病虫害、品种和基础设施建设。

## 18. 基线、消融与否证实验

### 18.1 状态与预测基线

- last observation / persistence；
- 季节或时段平均；
- 线性状态空间、ARX 或其他透明时序模型；
- 专业渠系模型；
- 专业土壤水分和作物需水模型；
- 不使用动作的预测模型；
- 仅状态和 forcing 的模型。

若开展学习型快速代理研究，还必须在相同任务合同下比较直接监督模型、状态空间或降阶模型、图时空模型，以及所选择的神经算子或 JEPA 候选。JEPA 候选需增加“去除 JEPA 目标但保持模型容量接近”的对照，不能只与 persistence 比较。

复杂模型必须在冻结测试上超过至少一个强简单基线，并说明相对专业模型的关系。

### 18.2 规划基线

- 现行调度规程；
- 专家提供的实际候选；
- 网络流或 MILP；
- MPC 或鲁棒优化；
- 随机和简单启发式；
- 适用时的 MCTS。

### 18.3 本体消融

| 实验 | 目的 |
|---|---|
| 无本体、平面 schema | 测试最小结构基线 |
| 只有对象类型 | 测试类型贡献 |
| 类型 + 权威关系 | 测试拓扑贡献 |
| 类型 + 关系 + 动作合同 | 测试动作约束贡献 |
| 完整版本、单位、证据和规则 | 测试治理增量 |
| 错误或反向关系 | 测试模型是否真正使用关系 |

### 18.4 动力学消融

- 无 action；
- action shuffle；
- proposed action 替代 executed action；
- 无 forcing；
- forcing shuffle；
- 无状态同化；
- 无物理硬约束；
- 仅物理软损失；
- 无学习残差；
- 无不确定性；
- 单步训练与多步训练；
- 专业模型和学习代理。

### 18.5 规划防投机

Planner 不能只在用于训练 surrogate 的同一个模拟器中评估。至少增加一种独立判定：

- 不同实现或更高保真专业模型；
- 隐藏历史事件；
- 现场专家规则审查；
- 前瞻影子运行；
- 小规模受控田间试验。

若 Planner 只利用模拟器偏差获得高分，应判定规划实验失败。

## 19. 严格验证阶梯

Gate 0 至 Gate 4 是所有路线的共享基础。Gate 6 只适用于实际启动的快速代理研究；Gate 7 的动作效果或因果证据与 Gate 8 的离线规划增量属于两个不同证据维度，可以分别开展。未通过 Gate 7 时，Gate 8 只能支持“给定模型条件下”的候选生成或排序，不能支持现实因果收益、生产增益或自动控制声明。

### 19.1 Gate 0：问题、语义和权限冻结

必须冻结：

- 主问题、空间范围、时间尺度和预测时域；
- 对象、关系、状态、观测、forcing、动作和结果；
- 允许动作和禁止动作；
- 目标向量、硬约束和责任主体；
- 数据、模型和执行权限；
- 评价、基线、切分和停止条件。

Gate 0 不通过，不进入模型开发。

### 19.2 Gate 1：本体、映射和实例图

要求：

- 能力问题通过；
- 无重复稳定 ID 和悬空关系；
- SHACL 和单位校验通过；
- 权威水力方向、分支和设备挂接通过；
- candidate 映射不进入生产状态编译；
- 领域专家完成首期范围审定。

### 19.3 Gate 2：数据与时间可用性

要求：

- valid time、available at 和 issue time 完整；
- 历史预报 vintage 可用；
- 计划、指令、执行和实际过流可区分；
- 缺测和质量状态显式；
- 训练、开发、验证分离；
- outcome 未在预测封存前读取。

### 19.4 Gate 3：专业模型与物理账

要求：

- 专业模型适用性经过专家确认；
- 参数和边界有来源；
- 数值稳定性通过；
- 渠系与田间水量账闭合到预注册容差；
- 历史回放误差和失败工况有记录；
- 回水、反向流或其他不适用工况不会被错误简化。

### 19.5 Gate 4：状态估计

要求：

- prior、observation 和 posterior 可复现；
- analysis increment 独立记账；
- 传感器留出和缺测实验通过；
- 状态区间覆盖率得到验证；
- 状态估计优于简单直接填充或明确说明没有增益。

### 19.6 Gate 5：动作条件预测

要求：

- 在未见时间和事件上评估；
- action-agnostic、zero-action 和 shuffle 对照完整；
- proposed 与 executed action 区分实验完整；
- 正确拓扑优于错误或反向拓扑；
- 多时距误差、漂移和尾部风险通过；
- 未超过强基线时关闭相应预测 claim。

### 19.7 Gate 6：快速代理

要求：

- 与指定专业模型使用相同任务合同；
- 精度、守恒和约束门先通过；
- 报告单步、rollout、批量和端到端规划延迟；
- 报告硬件、软件、冷/热启动和资源；
- 不以降分辨率或删输出换取未披露速度；
- 未达到价值门时仍使用专业模型。

### 19.8 Gate 7：动作效果与因果证据

根据证据区分：

- 专业模型条件情景；
- 历史关联性；
- 准实验或自然实验；
- 受控田间试验；
- 前瞻真实干预。

只有满足预注册识别假设和外推边界时，才允许因果主张。其他结果保持“模型条件情景”表述。

### 19.9 Gate 8：Planner

要求：

- 硬约束无补偿；
- baseline 与计算预算公平；
- 独立评估器或隐藏事件；
- decision regret、可行率和尾部风险通过；
- 多目标权重经授权；
- 专家能够复演和理解候选。

### 19.10 Gate 9：跨灌区迁移

要求：

- 迁移前冻结源模型；
- 目标灌区本体映射与数据质量独立审定；
- 报告零样本、固定少样本和充分校准三种结果；
- 不使用目标测试结果选择源模型；
- 分别报告语义、状态、动力学和规划迁移；
- 迁移失败不被本地重训结果掩盖。

### 19.11 Gate 10：前瞻影子与受控试点

影子运行要求：

- 使用实时可得输入和真实业务节奏；
- 不影响生产设备；
- 记录系统延迟、故障、降级和专家驳回；
- 完成至少一个有代表性的业务周期；
- 安全、权限和故障演练通过。

只有联合评审通过后，才讨论有限受控使用。自动控制不是本方案默认终点。

## 20. 评价指标与验收口径

### 20.1 本体与数据

- 能力问题通过率；
- 严重 SHACL 违反数；
- confirmed / candidate / conflict 映射分布；
- 关键对象与关系覆盖率；
- 单位、时区和空间支撑错误率；
- 拓扑方向、路径和挂接准确率；
- 数据来源和版本可追溯率；
- issue-time 可用性违规数。

关键关系和动作映射应要求完整审定，不以总体平均覆盖率掩盖关键缺口。

### 20.2 状态与预测

- 水位、流量、渠段存量；
- 根区土壤水分；
- 田块到水量；
- 蒸散和作物胁迫；
- 不同时距 RMSE、MAE、bias 和适用领域指标；
- 多步误差增长；
- 极端事件分位误差；
- 区间覆盖率、校准误差和 coverage-risk 曲线；
- OOD 或适用性识别。

指标和主次顺序必须在读取隐藏结果前冻结。

### 20.3 物理与安全

- 控制体水量残差；
- 未解释分析增量；
- 负存量、超容量和非法逆流；
- action mask false allow / false block；
- 设备和规则硬约束违反；
- 故障状态下的 fail-closed 行为；
- 手动接管和回退成功率。

数值水量容差与观测闭合误差应分开。前者由求解器和浮点误差决定，后者还包含量测与未建模通量，不能使用同一阈值。

### 20.4 规划

- 可行候选发现率；
- decision regret；
- 相对规则和专业优化的增量；
- 目标向量 Pareto 改善；
- 尾端和主体间公平；
- 对 forcing、参数和权重的敏感性；
- 方案切换频率和稳定性；
- 专家采纳、修改和驳回原因。

### 20.5 性能

- 单模型 step / rollout 延迟；
- 固定情景集合吞吐；
- 完整 Proposal p50 / p95；
- 峰值内存、CPU/GPU 和能耗；
- 冷启动、热启动和失败重试；
- 专业模型与代理在相同精度门下的 Pareto 曲线。

“一千倍”和“毫秒级”只能在冻结任务合同下作为实验结果报告，不能作为无条件设计承诺。

### 20.6 运行与治理

- 查询和工具路由正确率；
- 证据引用完整率；
- 权限泄漏和越权执行数；
- Proposal 重验证和过期处理；
- 审批与回执完整率；
- 指令—执行—实测水量对账率；
- 故障检测和恢复时间；
- 同一输入的可复现率。

## 21. 能力声明阶梯

| 等级 | 能力状态 | 最低证据 | 允许表述 |
|---|---|---|---|
| L0 | 语义与数据合同 | 本体、映射、实例图和 manifest 通过 | 已形成可版本化数据与语义基础 |
| L1 | 数字影子 | 历史状态重建、物理账和专业模型通过 | 能重放和解释历史状态 |
| L2 | 预测支持 | 冻结时间和事件留出超过基线 | 对限定对象和时距具有预测能力 |
| L3 | 条件情景支持 | 动作对照、多步和模型适用性通过 | 可比较给定模型条件下的候选情景 |
| L4 | 动作效果校准 | 试验、准实验或其他独立证据通过 | 在限定条件下支持动作效果判断 |
| L5 | 规划增量支持 | 独立评估中优于规划基线 | 候选生成或排序具有离线增量 |
| L6 | 影子运行支持 | 前瞻业务周期、治理与安全通过 | 可用于实时会商的影子辅助 |
| L7 | 受控使用候选 | 联合审批、小范围试点和回退通过 | 可在限定权限下辅助执行 |

L0 至 L3 是渐进基础；L4 的动作效果校准与 L5 的离线规划增量是两个可独立评估的证据分支。没有 L4 时，L5 只允许声明模型条件下的候选生成或排序增量，不能声明现实动作收益。L6 和 L7 只继承已经通过且与使用目的相关的证据。跨灌区、跨作物、跨时距或重大模型更新需重新验证。

## 22. 三个灌区的研究组织方式

### 22.1 主试点选择

主试点不按知名度选择，而按以下数据和治理条件选择：

- 权威渠系和工程图可获得；
- 关键控制点有稳定量测；
- 计划、指令、执行和实际水量可对账；
- 田块、作物、土壤和灌溉记录达到最低完整度；
- 至少有独立时间窗口；
- 调度和领域专家可持续参与；
- 可以开展影子运行；
- 数据权属、许可和安全边界明确。

### 22.2 两处迁移验证

另外两个灌区用于回答迁移问题：

1. **语义迁移。**核心对象、关系、动作和规则能否复用，哪些必须形成本地 profile？
2. **状态迁移。**状态变量、观测映射和状态估计器能否复用？
3. **动力学迁移。**冻结模型在目标灌区表现如何？
4. **少样本适配。**在固定校准预算下能恢复多少性能？
5. **规划迁移。**动作能力、规则和目标不同后，Planner 还能否使用？

### 22.3 三种迁移协议

- zero-shot：冻结源模型，不读取目标训练结果；
- few-shot：冻结样本和调参预算；
- full-calibration：使用目标训练集形成当地上限。

三种结果必须同时报告。full-calibration 成功不能掩盖 zero-shot 或 few-shot 失败。

### 22.4 灌区差异

淠史杭、河套和都江堰在气候、渠系、供水方式、地下水、盐分、作物和管理制度上差异显著。这些差异是检验迁移的科学条件，不应被统一本体标签掩盖。

尤其需要：

- 河套关注干旱、地下水和盐分过程；
- 都江堰关注重力渠网、复杂分水和长期运行规则；
- 淠史杭关注多水源、大型渠系和区域管理层级。

具体建模范围须由现场数据审计决定，不能仅凭上述概括选定模型。

## 23. 分阶段实施路线

本路线以 Gate 为出口，不以日历到期自动晋级。

### 阶段 A：问题与数据可行性

任务：

- 冻结首期业务问题；
- 完成本体最小范围和能力问题；
- 盘点数据、动作和执行回执；
- 明确责任、部署和许可；
- 选择专业模型与基线；
- 预注册验证协议。

交付：

- 场景合同；
- 数据 readiness 报告；
- 本体 seed 和映射清单；
- 模型候选清单；
- 风险和停止条件。

出口：Gate 0 至 Gate 2。若真实动作和边界数据不足，转为数字影子或专业模型研究，不继续宣称动作学习。

### 阶段 B：本体、状态和专业模型基线

任务：

- 发布灌区本体首版；
- 编译实例图和数据 manifest；
- 建立观测质量与状态快照；
- 接入渠系、田间和作物专业模型；
- 完成历史回放和物理账；
- 建立规则、persistence 和专业模型基线。

交付：

- 不可变本体包；
- 状态构建管线；
- 专业模型适配器；
- 历史回放报告；
- 初始 Failure Memory。

出口：Gate 3 至 Gate 4。此阶段不讨论 Planner 优势。

### 阶段 C：有条件的学习型代理研究

本阶段只有在有效独立事件、数据覆盖、验证窗口和计算加速需求通过审计后才启动。若条件不满足，项目记录不启动理由，保留专业模型路线，并可直接进入基于专业模型的候选比较和 Proposal 工作。

任务：

- 构建严格 transition dataset；
- 实现透明统计、状态空间、降阶和图模型基线；
- 根据过程结构和数据条件选择少量学习型代理候选；
- 只有满足第 10.2 节触发条件时才训练 Irrigation-JEPA，并保留同容量非 JEPA 对照；
- 运行本体、物理、动作和 forcing 消融；
- 在隐藏窗口验证多步与不确定性；
- 完成同任务速度比较。

交付：

- 数据与切分协议；
- 候选路线选择与 JEPA 触发判断；
- 候选模型和 manifest；
- 消融与否证报告；
- 模型卡和适用性边界；
- 是否晋级 Planner 的结论。

出口：适用时通过 Gate 5 至 Gate 6。未触发或失败时保留专业模型路线，不影响后续候选比较、Proposal 和影子工作，但关闭学习型加速声明。

### 阶段 D：Proposal 与规划

任务：

- 建立候选比较模式；
- 比较规则、MILP/MPC 与适用的搜索方法；
- 固化硬约束和多目标输出；
- 实现 Proposal、审批和审计；
- 使用独立评估器验证规划增量。

交付：

- Planner 对比报告；
- Proposal schema 与服务；
- 人工评审工作流；
- decision regret 和风险报告。

出口：Gate 8 的离线规划结论；Gate 7 独立决定是否允许动作效果或现实因果表述。未通过 Gate 7 时，Proposal 必须保持模型条件情景定位。

### 阶段 E：前瞻影子与迁移

任务：

- 完成主试点业务周期影子运行；
- 记录专家采纳、修改和故障；
- 在两个目标灌区执行冻结迁移协议；
- 开展安全、权限和恢复演练；
- 联合评审是否进入受控试点。

交付：

- 影子运行报告；
- 三灌区迁移矩阵；
- 安全和治理证据；
- 受控试点或停止建议。

出口：Gate 9 至 Gate 10。

| 工作包 | 内容 | 关键出口 |
|---|---|---|
| WP1 | 场景、术语、责任与验收合同 | Gate 0 |
| WP2 | 灌区本体、映射、发布和能力问题 | Gate 1 |
| WP3 | 数据、拓扑、时间语义和状态估计 | Gate 2-4 |
| WP4 | 渠系、土壤和作物专业模型耦合 | Gate 3 |
| WP5 | 有条件的学习型快速代理比较；适用时开展 JEPA | Gate 5-6 |
| WP6 | Planner、Proposal 和人机协同 | Gate 8 |

## 25. 风险与缓解

| 风险 | 后果 | 缓解 |
|---|---|---|
| 缺真实执行动作 | 无法验证动作响应 | 先做状态和专业模型；限制 claim |
| 渠系拓扑不完整 | 传播和水量账错误 | 权威编译、现场核验、错误拓扑对照 |
| 观测稀疏或漂移 | 隐状态不可识别 | 状态同化、留出传感器实验、区间输出 |
| 专业模型参数不足 | 高复杂模型不可信 | 保留简化强基线、参数敏感性和多模型 |
| 学习代理造水或漂移 | 多步推演失效 | 硬守恒、受界残差、长时 rollout gate |
| 将普通潜在动力学误称为 JEPA | 技术血缘和实验归因失真 | JEPA 命名门、同容量对照、独立消融 |
| 历史调度偏差 | 模型学习既有策略而非效果 | action/forcing 分离、准实验和试验校准 |
| Planner 利用模型漏洞 | 虚假最优 | 独立评估器、隐藏事件、压力测试 |
| 跨灌区域偏移 | 迁移失败 | zero/few/full 协议、适用性检测、本地 profile |
| OAG 路由错误 | 错数据或错工具 | 类型化计划、确定性校验、Evals 和人工确认 |
| 外部执行不确定 | 重复或错误动作 | 幂等、Outbox、回执、对账、fail closed |
| 自动化越权 | 生产安全事故 | 影子隔离、最小权限、双人复核、手动接管 |
| 目标权重争议 | 方案不可接受 | 保留原始指标、授权权重、Pareto 和异议 |
| 论文导向挤压验证 | 选择性报告 | 预注册、失败记忆、冻结窗口和完整报告 |

## 26. 停止或降级条件

满足以下任一条件时，应停止相应能力升级：

- 无法区分计划、指令和实际执行动作；
- 权威拓扑、边界水量或关键单位无法闭合；
- 有效独立事件数量不足以训练和验证学习模型；
- 学习模型不优于简单或专业基线；
- 错误拓扑、动作打乱或 no-action 对照不按预期退化；
- 多步 rollout 物理违规或不确定性严重失准；
- 代理速度收益依赖降低任务质量；
- Planner 收益不能在独立评估中复现；
- 跨灌区结果只在充分本地重训后成立；
- 影子运行出现越权、不可解释或无法降级的故障；
- 业务部门无法提供目标、约束、审批和责任边界。

降级路径包括：

- 从“世界模型”降级为专业模型情景工作台；
- 从“动作条件预测”降级为状态估计和监测；
- 从“候选生成”降级为专家方案比较；
- 从“跨灌区模型”降级为本地模型加共享本体；
- 从“控制候选”降级为只读影子报告。

降级是科学和工程上的正常结论，不是项目失败的掩饰。

## 27. 非功能要求

### 27.1 可复现

- 每次状态、训练、推演和 Proposal 绑定不可变输入；
- 数据、本体、规则、模型、参数和代码均有版本和哈希；
- 同一输入和确定性配置能够复现；
- 随机性记录 seed、环境和重复次数；
- 报告包含失败和被拒绝结果。

### 27.2 可靠性

- 关键依赖超时和不可用时显式降级；
- 不从失败的高保真模型静默切换到未验证代理；
- 运行状态和外部执行状态独立；
- 未知执行状态进入对账和人工处理；
- 状态快照、Proposal 和审计制品可恢复。

### 27.3 安全与权限

- 主体、角色、目的、空间范围和有效期进入每次查询与动作；
- 默认只读和最小权限；
- 策略服务失败时拒绝，而不是放行；
- 控制网络与语言模型隔离；
- 敏感设施位置和运行数据按授权呈现；
- 所有审批和执行不可抵赖审计。

### 27.4 可维护

- 本体、数据映射、专业模型、学习模型和 Planner 独立版本；
- 通过稳定接口组合，不形成单一巨型服务；
- 模型替换不改变对象身份和证据合同；
- 地方差异通过 profile 和映射表达，不复制整套系统；
- 每次升级运行回归、消融和影响分析。

## 28. 预期成果的严谨表述

### 28.1 可以承诺交付的工程和研究制品

- 灌区本体、映射、能力问题和发布治理；
- 一个主试点的数据与状态合同；
- 专业模型适配和统一水量账；
- 一套 action-conditioned 数据与评估协议；
- 学习型代理的路线选择、候选模型、完整基线和消融；满足触发条件时交付 JEPA 候选及其增量证据；
- Planner 比较与 Proposal 工作流；
- 前瞻影子运行和跨灌区迁移报告；
- 可复现实验、失败案例和模型卡。

### 28.2 不将论文录用作为唯一验收

可围绕以下独立问题形成论文：

1. 本体约束的对象关系状态与跨灌区语义迁移；
2. 物理约束的多速率动作条件动力学和快速代理；
3. 前瞻影子运行中的规划价值、风险和人机协同。

投稿目标可以有挑战性，但期刊录用受外部审稿影响，不应代替数据、协议、代码、实验和现场证据验收。

### 28.3 推荐对外表述

在完成 Gate 0 至 Gate 4 后，可表述为：

> 已建立灌区对象、状态、观测、动作和规则的版本化语义模型，并形成专业模型支持的历史状态重建和条件情景基础。

在完成 Gate 5 至 Gate 6 后，可表述为：

> 在限定灌区、变量和时距上，候选动作条件模型通过冻结验证，并在预注册精度与物理约束下取得可复现的预测或计算效率结果。

在完成 Gate 8 至 Gate 10 后，可表述为：

> 系统能够在前瞻影子环境中生成和比较受约束候选方案，完整保留不确定性、证据和人工审批；是否进入受控使用由联合评审决定。

不建议使用：

- 已实现灌区自主决策；
- 已证明真实最优调度；
- 本体消除了模型幻觉和不确定性；
- 已完成从相关到因果的跃迁；
- 全灌区推演普遍达到毫秒级；
- 一个模型可直接迁移到所有灌区；
- 可以替代调度和农艺专家。

## 29. 立项前必须回答的问题

1. 首期主试点的具体渠系、作物、季节和责任主体是什么？
2. 是否存在可核验的实际执行动作和边界水量？
3. 是否能获得历史预报 vintage，而不仅是事后天气数据？
4. 渠系断面、控制结构和水力拓扑是否足以支持专业模型？
5. 田块、土壤、作物和灌溉记录是否能建立时间对齐？
6. 现有调度规则、配额和审批是否能形式化？
7. 哪个专业模型作为主基线，哪个模型作为独立评估器？
8. 有多少独立灌溉季和事件可用于训练、开发和验证？
9. 是否有条件开展完整业务周期的影子运行？
10. 两个迁移灌区能提供哪些固定预算的数据？
11. 哪些结果属于科研公开，哪些涉及关键基础设施安全？
12. 项目在哪些失败条件下会主动停止学习模型或规划主张？

这些问题未回答前，不应冻结论文数量、千倍加速、毫秒响应或三个灌区完成度。

## 30. 最终设计判断

本体驱动的灌区世界模型具有合理的科学问题和应用价值，但成立条件比“本体 + JEPA + PINN + MCTS”组合更严格。

技术路线已经明确：Geospatial Kernel 风格的拓扑、守恒、状态和证据合同是可复用计算基础，专业模型、状态估计和约束优化是灌区工程主线；学习型代理承担经过验证的加速或误差修正，JEPA 仅在数据和对照实验支持时作为候选。两者不是同等规模的平行押注，也不存在既有 Geospatial Kernel 向 JEPA 的直接实现继承。

本方案的核心不是增加术语，而是建立以下可验证链条：

~~~text
权威对象和关系
  -> 版本化语义与数据合同
  -> 部分可观测状态估计
  -> 专业模型和受约束学习动力学
  -> 动作条件多步推演
  -> 独立规划器和多目标候选
  -> 证据门与人工审查
  -> 影子运行、回执和持续否证
~~~

如果该链条只能完成前半部分，系统仍可以成为可靠的语义化数字影子和专业模型工作台；只有当预测、动作响应、规划增量和前瞻运行依次通过独立验证后，才适合逐级使用“世界模型”“反事实支持”或“辅助调度”等更强表述。

因此，推荐的立项原则是：

> 以一个可证伪的灌区运行闭环为起点，以权威拓扑、守恒内核、专业模型和真实执行数据为基础，以本体保障语义与治理，以透明基线优先、学习模型竞争、JEPA 按条件触发而非预设，以 Proposal 和人工审查作为首期终点，以跨灌区冻结验证决定是否具有可迁移的科研贡献。
