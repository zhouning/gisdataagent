# 农业地理空间世界模型：应用场景版图、旗舰原型与体系架构

日期：2026-07-11

## 1. 核心结论

农业领域最值得建立的不是“农业遥感大模型”，而是一个能够模拟“水—土—作物—经营动作—天气扰动—产量与生态结果”的分层农业世界模型。首个旗舰原型建议定义为：

> **AWM-CropWater：田块—农场—灌区/县域分层的作物—水资源世界模型。**

它比单纯耕地布局优化更具有农业领域独立性，也比“全农业世界模型”更容易形成真实、可验证的闭环。

本文同时完成三个相互衔接的目标：

1. 建立农业世界模型的严格理论边界；
2. 梳理农业领域的完整应用场景版图；
3. 筛选旗舰原型，并定义可复用的 AWM 系统架构。

三者之间不是相互冲突的并列任务，而是一条完整链路：

```text
严格的 AWM 理论框架
        ↓ 提供判定标准
农业应用场景完整版图
        ↓ 进行可行性与价值筛选
旗舰原型选择
        ↓ 反向验证并具体化
AWM 系统架构与通用 Kernel
```

## 2. 严格意义上的 AWM 是什么

农业世界模型至少应被形式化为一个部分可观测、动作条件化、多尺度的动态系统：

\[
b_t=P(x_t\mid o_{\le t},a_{<t})
\]

\[
x_{t+1}\sim T_\theta(x_t,a_t,e_t,G,R)
\]

\[
o_t\sim O_\phi(x_t,q_t)
\]

其中：

- \(x_t\)：真实但不能完全观测的农业状态；
- \(o_t\)：卫星、无人机、传感器、农事记录等观测；
- \(b_t\)：模型对真实状态的信念分布；
- \(a_t\)：灌溉、施肥、播种、品种调整、病虫害防治等可执行动作；
- \(e_t\)：天气、市场、外来病虫害等外生扰动；
- \(G\)：田块、沟渠、道路、农场和行政单元组成的空间关系图；
- \(R\)：水权、耕地保护、农药规范、预算和农业政策约束；
- \(T_\theta\)：动作条件化的农业动力学；
- \(q_t\)：观测质量、传感器条件和数据缺失状态。

一个严格的农业世界模型应回答：

```text
农业状态 S_t
+ 农业管理动作 A_t
+ 外部扰动 E_t
→ 未来状态 S_(t+1)
→ 产量、收益、资源消耗、生态影响和风险
```

### 2.1 认识论边界

必须坚持以下边界：

- 遥感影像是 observation，不是真实完整 state；
- 天气情景是外生扰动，不是管理 action；
- 产量预测不是 world model，除非它能区分不同动作下的未来；
- 优化器不是 world model，它只是 simulator 的消费者；
- 把灌溉量输入神经网络，不代表自动获得了灌溉的因果效应；
- 过程模型生成的轨迹、历史观测轨迹和因果识别结果必须分别标记；
- 没有 action-conditioned transition，就不能称为严格意义上的 simulator；
- 没有多步 rollout 和规划消费闭环，就不能支持世界模型规划主张。

## 3. 三条可能路线

### 3.1 路线 A：农业土地与空间治理世界模型

主要处理：

- 耕地布局优化；
- 高标准农田建设；
- 土地整治；
- 种植结构空间调整；
- 永久基本农田保护；
- 县域粮食安全规划。

优点是与现有 TWM、耕地 DRL/MPC 研究线衔接最直接。问题是它很容易退化为“耕地版 TWM”或土地利用优化，农业生物过程并不充分。

### 3.2 路线 B：田块/农场作物管理世界模型

主要处理：

- 播种、灌溉、施肥和收获时机；
- 作物生长与产量；
- 土壤水分、养分和作物胁迫；
- 病虫害防治；
- 轮作与土壤健康。

它最符合经典世界模型的高频交互闭环，但如果只在单块田或温室中运行，地理空间的独特性会偏弱，更接近精准农业控制模型。

### 3.3 路线 C：分层农业生产世界模型

同时连接：

```text
田块生物物理状态
↕
农场经营动作
↕
灌区水资源网络
↕
县域种植结构与治理约束
```

这是推荐路线。它既有真实动作反馈，又保留 GIS 的空间网络、多尺度、空间外溢和治理属性。

## 4. 农业应用场景版图

| 层级 | 场景 | 世界模型适配度 | 严格判断 |
|---|---|---:|---|
| 田块 | 灌溉时机与灌溉量优化 | 极高 | 动作清晰、反馈频繁、可多步推演 |
| 田块 | 水肥协同管理 | 极高 | 有生物物理转移，但需要施肥记录和氮循环状态 |
| 田块 | 播种、品种、密度与收获窗口 | 高 | 适合季节尺度规划，动作反馈较慢 |
| 田块 | 病虫害传播与防治 | 高 | 必须建模空间传播和防治动作；识别病害本身不算 |
| 田块 | 轮作与土壤健康 | 高 | 长时序和路径依赖强，但验证周期很长 |
| 农场 | 多田块农机调度 | 中高 | 是运营世界模型，但生物物理成分较弱 |
| 农场 | 劳动力、农资和预算联合配置 | 高 | 适合多目标规划，依赖经营记录 |
| 灌区 | 渠系水量分配与田间灌溉协同 | 极高 | 最能体现图结构、上下游干扰和多主体决策 |
| 区域 | 干旱、洪涝、热害应对 | 极高 | 需要天气集合情景和稳健规划 |
| 区域 | 病虫害区域扩散与联合防控 | 高 | 空间干扰显著，适合图动力学 |
| 县域 | 作物种植结构与粮食安全 | 高 | 价值大，但动作反馈慢、因果混杂严重 |
| 县域 | 农业补贴、保险和节水政策 | 中高 | 必须使用政策项目和因果校准数据 |
| 流域 | 农业面源污染治理 | 极高 | 可连接施肥、径流、水质和下游外部性 |
| 供应链 | 产量—仓储—运输—市场响应 | 中高 | 可以构建，但更接近供应链世界模型 |
| 土地治理 | 耕地整治与布局优化 | 高 | 应作为 TWM–AWM 交界模块，而非 AWM 唯一核心 |

### 4.1 不能单独称为世界模型的农业 AI 应用

以下应用可以成为 AWM 的 observation、state encoder 或辅助模型，但不能单独称为世界模型：

- 作物分类；
- 病虫害图片识别；
- 单次产量预测；
- 土壤属性制图；
- 农业知识问答；
- 农田适宜性评价；
- 农业遥感基础模型；
- 不消费 simulator 的静态选址或排序。

## 5. 旗舰原型：AWM-CropWater

建议第一版只解决一个明确问题：

> 在天气不确定、灌区供水受限和田块状态部分可观测的条件下，如何联合规划渠系水量分配与田间灌溉时序，使产量、水分生产率和供水公平达到较优平衡？

### 5.1 状态空间

- 静态状态：田块、土壤、地形、作物类型、灌渠和水源网络；
- 快速动态：降雨、蒸散、土壤水分、渠库水量；
- 作物动态：物候、LAI、生物量、根区状态、水分胁迫；
- 经营状态：已执行灌溉、累计用水、预算和农机可用性；
- 治理状态：水权、配额、取水限制、优先供水规则；
- 证据状态：数据来源、时间戳、质量、缺测和不确定性。

### 5.2 动作空间

第一版只包含：

- 给哪个渠系或田块供水；
- 何时灌溉；
- 灌溉多少；
- 在供水不足时如何重新分配。

以下动作可放到第二阶段：

- 施肥与水肥协同；
- 品种和播期；
- 病虫害防治；
- 应急改种；
- 轮作方案。

硬约束必须直接形成 action mask，例如渠系容量、水权配额、田块可达性、作物生育期和取水禁令，不能只在结果中扣分。

### 5.3 动力学

推荐采用混合动力学，而不是纯端到端模型：

```text
作物/水文过程模型
+ 遥感与传感器状态同化
+ 图网络表达渠系和田块传播
+ 数据驱动残差修正
+ 历史干预的因果校准
+ 不确定性集合 rollout
```

过程模型负责守住水量平衡和基本生理规律；学习模型负责修正区域参数偏差和未建模过程。二者应分别输出贡献和不确定性。

### 5.4 结果空间

不要过早将结果压缩成一个 reward。至少保留：

- 产量及减产风险；
- 总用水量；
- 水分生产率；
- 作物胁迫持续时间；
- 农户间供水公平；
- 能耗与成本；
- 深层渗漏、氮淋失等生态风险；
- 约束违反概率。

Planner 可以在不同治理目标下组合这些指标，但原始结果必须保留。

## 6. AWM 系统架构

```text
多源农业数据
    ↓
Agricultural Renderer / Observation Model
    ↓
Belief-State Estimator
    ↓
Hybrid Action-Conditioned Simulator
    ↓
带不确定性的多步 rollout trace
    ↓
MPC / Robust Planner
    ↓
候选农业管理方案
    ↓
Evidence Gate + Human Review + Failure Memory
```

其中：

- Renderer 负责观测对齐、空间聚合、质量与来源追踪；
- State Estimator 推断根区水分、生物量等不可完全观测状态；
- Simulator 才是 AWM 的核心；
- Planner 只能消费 simulator trace；
- Evidence Gate 决定结果只能用于诊断、离线评估、影子运行还是实际试点；
- Failure Memory 保存跨年份、极端天气、不同土壤和异常灌溉条件下的失败案例。

农业系统还需要支持多时间尺度：

- 小时级：天气、供水和灌溉事件；
- 日级：土壤水分、蒸散和作物胁迫；
- 周级：作物生长和病虫害扩散；
- 季节级：产量、收益和资源利用效率；
- 年度及多年尺度：轮作、土壤健康和基础设施演化。

不能把所有过程粗暴压缩为同一个时间步。

## 7. 严格验证阶梯

建议将 AWM 的能力声明分为七级：

1. 能重建历史观测和隐状态；
2. 无动作条件下的未来预测通过时间留出验证；
3. 动作条件化的单步转移通过验证；
4. 多步 rollout 不发生明显漂移或物理守恒破坏；
5. 干预效果经过历史项目、准实验或田间试验校准；
6. 离线规划优于规则、过程模型和传统优化基线；
7. 影子运行或小规模受控试验验证决策收益。

### 7.1 核心指标

评价指标不能只有产量 RMSE，还应包括：

- 水量平衡误差；
- 多步 rollout 误差；
- 概率校准和区间覆盖率；
- 极端天气下的尾部失败；
- false allow / false block；
- 约束违反率；
- planner decision regret；
- 跨年份、跨土壤和跨尺度稳定性；
- 相邻田块、上下游和农户之间的空间外溢误差。

尤其要明确：

> 如果只有遥感、天气和产量数据，而没有真实灌溉动作日志，第一版最多能声明“过程模型支持的情景推演”，不能声明已经学到了真实灌溉干预的反事实效果。

## 8. 与 TWM、UWM 的关系

三者不是按行业简单换皮，而是分别建模不同类型的地理世界：

| 模型 | 核心世界 | 主要时间尺度 | 典型动作 |
|---|---|---|---|
| TWM | 土地、生态和空间治理世界 | 年—多年 | 用地转换、保护、整治、规划 |
| UWM | 城市设施、人口与治理世界 | 月—年 | 设施建设、交通、更新、环境治理 |
| AWM | 水土作物与农业经营世界 | 小时—季节—多年 | 灌溉、施肥、种植、防治、资源配置 |

AWM 最独特的理论贡献应是：

> 把部分可观测的生命过程、受约束的农业管理动作、空间传播与资源网络、多时间尺度和治理证据统一为一个可推演系统。

现有 Geospatial World Model Kernel 可以继续提供公共的 state、action、transition、evidence 和 claim contract；AWM 新增农业状态估计、生物物理守恒、多时间尺度动力学以及空间干扰接口。现有耕地布局研究则作为 AWM 与 TWM 之间的长期规划层，而不是从头重做。

总体结构建议为：

```text
通用 Geospatial World Model Kernel
├── TWM：土地与自然资源治理
├── UWM：城市系统治理
└── AWM：农业生产与资源管理
    └── 首个原型：灌区—田块作物水分管理
```

## 9. 最终建议

农业世界模型应采用“田块—农场—灌区/县域”的分层建模路线，但首个可证伪闭环应聚焦灌区—田块作物水分管理。

推荐的首版范围是：

- 一个灌区或县域试验区；
- 一种主要作物；
- 一个完整生长季；
- 日级核心动力学和事件级灌溉动作；
- 田块—渠系—水源空间图；
- 灌溉时机、灌溉量和水量分配动作；
- 产量、水分生产率、胁迫、成本和公平多目标结果；
- 过程模型锚定、学习残差修正和证据分级；
- MPC 或稳健规划器消费 simulator rollout；
- 在真实干预证据不足时严格限制反事实和生产能力声明。

这一方向能够同时建立完整农业应用版图、形成严格可验证的旗舰原型，并最终沉淀为可复用的 AWM 架构，而不是农业应用功能的松散集合。
