# 重庆规划与地块版本资产验证报告

## 对应需求

- 客户侧需求2：规划与地块版本资产。
- 技术路线：传统GIS和数据治理负责规划/地块资产清单、版本证据和时点谱系；UWM仅消费经过批准和验证的时间基线。

## 已实现

- 产品模式：`uwm.planning_parcel_version_registry.v1`。
- 产品包：`planning-version-2f92539f914b57c94c3a`。
- 从本地规划压缩包审计中筛选4项关键资产：
  - 璧山地类图斑：101,657个要素；
  - 福禄村规划数据库：8,050个要素、28个图层；
  - 2019年璧山土地开发相关台账：1,438行；
  - 璧山城镇村调查区参考图层：1,488个要素。
- 建立规划版本证据契约、版本通道和UWM时间基线门。
- 独立服务、6个鉴权API和“规划与地块版本”独立页面。

## 证据边界

- 4项资产均来自“规划院提供数据样例及Demo系统功能演示建议”压缩包审计。
- 批准状态已验证资产：0。
- 权威当前版本：0。
- 2019只记录为文件/台账中观察到的年份，不提升为规划版本或有效期。
- DLTB图斑不是法律宗地产权，台账行不是空间地块历史。
- 审计创建时间不是规划生效时间。

## 门控结果

- 批准标识、版本标识、有效期、空间适用范围、前后版本、变更原因、源哈希和权威当前版本通道全部 `unavailable/null`。
- 权威基线选择、当前版本解析、版本链遍历、地块历史重建、修编比较、时序结果连接、UWM批准规划初始化和规划变化转移归因全部关闭。

## 验证结果

- 聚焦Python测试通过。
- 独立验证器通过，`fabricated_value_count=0`。
- 六件套bundle ID一致。
- 验证摘要：4项版本资产、0项批准已验证、0项当前权威版本、0个开放时间机制。

## 生产化前置条件

必须为每个规划/地块版本接入发布机关、批准或发布标识、版本号、生效与失效时间、空间范围、对象类型、CRS、模式定义、不可变源哈希、前序/后续版本、变更原因和可引用依据。完成版本谱系后，UWM才能建立可审计的规划时间基线。
