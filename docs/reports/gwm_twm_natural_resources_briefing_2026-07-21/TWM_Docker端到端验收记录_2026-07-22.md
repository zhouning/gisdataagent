本轮重新执行 PPTX 生成源后，正式 PPTX 的更新时间为 16:38、共 29 页。宿主机 LibreOffice 在已有用户进程锁下无法稳定完成同一版 PDF 覆盖，容器内 LibreOffice 对该外部挂载 PPTX 也返回“source file could not be loaded”；因此本轮验收以 16:38 生成的 PPTX 为准，15:53 的同名 PDF 未宣称为新版 PDF。现场应优先使用 PPTX；如需 PDF，应在无 LibreOffice 进程锁的环境中从该 PPTX 重新导出。

## 4. 现场演示建议

完整 E2E 是压力验收脚本，不应在汇报现场从头执行。主要耗时来自全量空间要素传输和全量状态关系构建。

建议会前完成项目、状态和规则结果预热，现场按以下顺序演示：

1. 在“汇报演示”中说明 GWM 正式定义、Simulator 组合转移、状态写回和证据边界。
2. 在“数据依据”中展示 22,401 条记录、21,603 个空间要素、真实事件编译链和 Paper9 双县离线证据。
3. 只加载 `synthetic_projects.geojson` 的 90 个项目要素证明真实接口上图；不要现场触发全部 21,603 个要素的压力加载。
4. 使用预构建状态依次展示风险命中、推荐方案和地图差异，重点解释规则依据、动作可行域、状态写回和人工复核任务。
5. 最后展示 GWM-Bench 的失败门禁，主动说明当前 Kernel 未达到生产准入，以增强技术可信度。

本轮现场主路径已经在 `docs/reports/twm_executive_demo_script_2026-07-22.md` 固定为：地图定位 -> 规则检查 -> 风险预测 -> 三期验证 -> 依据核查 -> 载入 7 个候选 -> 3 个可行/4 个阻断 -> 合法可行域内比选 -> 推荐与阻断方案上图。

## 5. 仍需坚持的边界

- 当前 TWM 数据基础足以支撑受控工程演示，不足以训练省域真实治理动力学。
- Paper9 证明特定耕地布局优化流程可离线运行并通过三项硬约束，不等于业务审批或治理成效。
- 上海供地事件链完成了真实事件到训练候选的编译，尚未完成因果识别和训练准入。
- GWM Simulator 的 rollout 是模型条件下的方案推演，不自动等于真实政策因果效果。

## 6. 非阻断运行风险

容器启动日志仍有两个既有环境告警，但未影响本轮 TWM API、浏览器流程或地图联动：

- 后台通用审计表初始化读取到空的整数环境值；TWM 自身依据核查接口在本轮通过。
- `cad-parser-service` MCP 配置仍引用 Windows Python 路径，当前 0/1 MCP 连接；本次 TWM 场景不依赖该 MCP。

这两个问题不应在汇报时表述为 TWM 能力缺陷，但在正式部署前应分别修复环境变量校验和 MCP 配置。
