# UWM、3D 城市环境与智能体应用讨论

按照《人工智能：一种现代方法》第4版里对智能体的定义，智能体通过感知器感知环境，通过执行器作用于环境；强化学习里则更具体：智能体在状态 `s` 下选择动作 `a`，环境转移到新状态 `s'`，并返回奖励 `r`。放到 UWM 场景里，现在的“智能体”主要不是直接控制物理城市，而是：

```text
感知城市数据 -> 建立城市状态 -> 进行模拟/规划/评估 -> 向人类管理者输出建议 -> 人类执行现实动作
```

所以现在 UWM 更像“人机协同决策智能体”，不是完全 autonomous 的城市控制智能体。

## 2D UWM 能解决什么

当前 2D 或 2.5D 数据已经能解决很多宏观和中观问题：

- 行政单元宜居性分析
- 服务可达性
- 空气质量暴露
- 人口/建成区/路网关系
- 空间邻接溢出
- 多步政策规划 replay
- 城市治理层面的策略比较

这些问题的状态输入不一定必须 3D。很多宏观治理问题，本质上是空间分布、时序变化、资源配置和政策组合问题。

## 3D UWM 会带来什么质变

城市当然是三维的。3D 不只是“看起来更真实”，而是会让智能体获得新的状态变量和行动空间：

- 建筑高度、体量、楼层、容积率
- 街谷形态、遮阳、热岛、风环境
- 可视域、通视、遮挡、噪声传播
- 地下空间、天桥、立交、轨道站厅
- 人群垂直疏散、消防救援、应急避难
- 无人机航路、低空经济、空中交通
- 自动驾驶/机器人在道路和街区中的感知交互
- 施工、更新、城市设计方案的反事实模拟

这类问题用 2D 会丢掉关键机制。比如同一个地块，在 2D 上只是一个 polygon，但在 3D 里可能是 30 层高楼、底商、架空层、地下车库、裙楼、连廊，对热环境、人流、消防、物流、交通影响完全不同。

## 状态输入会复杂很多

2D UWM 的状态大概是：

```text
admin unit / grid / road / POI / population / pollution / service
```

3D UWM 的状态会变成：

```text
3D geometry + semantic objects + physical fields + dynamic agents + temporal evolution
```

也就是：

- 几何：mesh、point cloud、BIM、CityGML、3D Tiles
- 语义：建筑用途、楼层功能、道路等级、入口、消防通道
- 物理：光照、风、热、噪声、水流、污染扩散
- 动态对象：人、车、无人机、机器人、施工设备
- 行为规则：交通规则、疏散规则、部门治理规则
- 时间：日夜、季节、事件、施工周期、政策周期

所以它不再只是 3D 可视化，而是 4D 城市世界模型：三维空间 + 时间演化。

## 计算也会显著复杂

复杂度主要来自四点：

1. 数据量暴涨

   3D mesh、点云、BIM、视频、轨迹数据都比 2D 表格/栅格重得多。

2. 状态维度暴涨

   2D admin unit 可以几十个特征；3D 场景可能是百万级对象、体素、面片或点。

3. 模拟成本暴涨

   风、热、污染、人流、车辆、遮挡、传感器仿真都可能需要物理模型或神经模拟器。

4. 智能体动作空间变复杂

   2D 里动作可能是“在哪个片区加服务设施”；3D 里动作可能是“在哪个楼层、哪个入口、哪个高度、哪条路径、哪个时间窗口执行”。

因此 3D UWM 必须做层级抽象：

- 宏观层：城市/区县/街道
- 中观层：街区/道路/建筑群
- 微观层：建筑/楼层/入口/人车流
- 具身层：车辆、无人机、机器人、人群个体

不能把所有 3D 数据直接塞给一个大模型或一个 RL agent，那会不可控、不可解释、不可验证。

## 无人驾驶是不是其中一类应用

无人驾驶模型训练确实是 3D/4D 世界模型的典型应用之一。它需要：

- 3D 道路场景
- 传感器模拟：camera、LiDAR、radar
- 动态交通参与者
- 遮挡、天气、光照
- 交通规则
- 高风险长尾场景
- 闭环仿真和安全验证

但无人驾驶属于“具身智能体”的局部高频控制问题，时间尺度是毫秒到秒，空间尺度是车周边几十米到几公里。

UWM 当前更偏“城市治理智能体”，时间尺度是天、月、年，空间尺度是街道、区县、城市。二者都可以叫 world model，但不是同一个问题。

更准确地说：

- 自动驾驶：3D UWM 的一个具身智能应用分支
- 城市治理：3D UWM 的宏观/中观决策应用分支
- 无人机巡检、消防救援、应急疏散、低空交通：介于两者之间

## 判断

UWM 必须先把 2D/2.5D 的世界模型闭环做扎实：真实数据、状态渲染、动态模拟、规划、评估、证据门控。现在项目已经在这个方向推进。

但如果目标是更有效管理城市复杂巨系统，3D 是迟早要进入的。不是为了炫酷可视化，而是因为很多城市机制本来就是三维的。未来 UWM 应该演化为：

```text
2D 宏观治理世界模型 + 3D 局部场景世界模型 + 多智能体交互模拟 + 人机综合集成决策
```

这样它才可能从“城市分析工具”升级为真正面向复杂巨系统管理的城市智能底座。
