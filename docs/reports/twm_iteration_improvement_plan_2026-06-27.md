# TWM 后续完善与迭代规划

日期：2026-06-27
对象：GIS Data Agent / Territory World Model（TWM）
用途：把 2026-06-27 讨论形成的 TWM 后续规划固化为文档，并作为后续 roadmap 刷新的依据。

## 1. 当前判断

TWM 当前已经从后台 API 和技术验证，推进到可在 GIS Data Agent 前端中演示的原型链路：可以浏览数据基础、全量加载主演示空间数据、联动总览地图、构建状态、执行规则审查、风险预测、验证口径、证据审计、方案比选、基线对比和技术载荷查看。

但当前 TWM 仍应被定义为“可演示、可验证、可审计的国土空间世界模型原型”，不是生产级自然资源审批模型。它已经具备 world model 的工程雏形和理论框架，但真实业务增益、跨区泛化、跨期预测、政策动作因果效果和生产级规划推荐，仍必须依赖自然资源部门权威数据、真实历史样本和严格基线验证。

## 2. 当前已完成能力

### 2.1 前端演示与地图联动

- TWM 页面已改为中文优先，不再混用中英文界面文案。
- TWM 操作页已拆分为四个子页签：`总览地图`、`数据证据`、`操作推演`、`技术载荷`。
- `总览地图` 已支持 `定位审查区`、`展示风险命中`、`展示推荐方案`，并向主地图推送空间图层。
- `数据证据` 已支持数据基础浏览器、数据包切换、全量空间数据加载、数据清单、验证快照、适配分析和来源报告。
- `操作推演` 已串起创建项目、构建状态、规则检查、风险预测、验证口径、证据审计、候选方案载入和方案比选。
- `技术载荷` 已提供结构化 JSON 展开区，便于技术人员复核前端动作和后端返回载荷。

### 2.2 数据基础与空间一致性

- 主演示数据包已调整为 `twm_bishan_multi_admin_eval`。
- 该数据包总量为 `22,401` 条，其中空间 GeoJSON 全量为 `21,603` 个要素。
- 主演示 bbox 为 `[106.152182211, 29.667518609, 106.367539714, 29.886844144]`。
- `twm_bishan_demo` 与主范围高度重叠，但不是当前默认叙事样例。
- `twm_one_map_village_standard_sample` 当前为投影坐标量级，尚不能和 WGS84 演示范围直接混合叠加。
- 已修复此前总览地图演示范围与数据基础空间范围不对应的问题。

### 2.3 后端接口与自动化验证

- 新增 `TerritoryWorldModelService.data_foundation_map_preview(...)`。
- 新增接口 `GET /api/twm/data-foundation-map-preview/{dataset_id}`。
- 支持抽样预览和全量 GeoJSON 两种模式，其中 `max_features_per_layer=all` 返回全量空间要素。
- 自动化 E2E 已覆盖页面入口、子 tab、全量加载、地图 bbox 相交、项目构建、规则审查、风险预测、验证审计、方案比选、基线对比和技术载荷。
- 最新 E2E 报告见 `docs/reports/twm_e2e_test_report_2026-06-27.md`。

### 2.4 TWM 核心能力雏形

当前实现已经具备以下工程雏形：

- 对象、关系、规则、证据状态构建。
- 行动条件化 forecast。
- counterfactual rollout。
- validation ladder 和 evidence gate。
- action mask / execution gate。
- constrained beam planning consumer。
- 基线对比报告。
- trainable dynamics candidate backend 与 readiness/report gate。
- 公开 benchmark、GeoSOS/FLUS 对比和 Dynamic World admin20 实验资产。

这些能力证明 TWM 不是单纯地图控件或规则引擎。但其中不少能力仍处于 scaffold、candidate 或 review-only 阶段，需要真实数据和严格实验才能升级主张等级。

## 3. 主要不足

### 3.1 数据不足

- 当前没有自然资源部门真实权威生产数据。
- 缺少真实审批、复核、执法、补正和后续变化历史。
- 缺少政策动作标签和 action feasibility 标签。
- 缺少可与人工 GIS、规则引擎、传统优化器同案对比的真实 baseline。
- 部分数据样例存在 CRS 不一致问题，必须在演示和生产接入前显式治理。

### 3.2 模拟器不足

- 当前模拟器具备行动条件预测接口和候选后端，但真实动态学习尚未通过权威跨期数据验证。
- `future_latent_state` 仍是紧凑代理指标，不应描述成完整未来空间状态。
- 公开实验显示 TWM 在某些 change FoM、需求约束或 direct FLUS adapter 对比上有优势，但 FLUS ANN 版本在部分 changed-pixel allocation 上仍更强，因此不能宣称全面优于 FLUS。
- 真实泛化性目前不能严肃主张，必须等跨区、跨期、跨政策动作 holdout 结果。

### 3.3 规划器不足

- 当前 planner 可以消费候选方案、执行硬约束过滤、风险收益评估和 beam ranking。
- 但候选方案生成器、真实业务目标函数、政策优先级、人工复核机制和方案实施反馈仍不完整。
- TWM 不能被描述为自动审批或自动替代规划人员，只能描述为证据门控的辅助决策和审计平台。

### 3.4 工程产品化不足

- `service.py` 仍是大型 facade，后续应拆分为状态、数据、规则、模拟器、因果校准、规划器、证据审计和 readiness 服务。
- 当前 21,603 个 GeoJSON 要素可支撑演示；全国级数据必须升级为瓦片化、空间索引、分层加载和服务端聚合。
- 模型注册、版本固定、回滚、审计、权限、脱敏和内网部署流程仍需完善。
- 前端还需要加强地图图层控制、空间数据目录浏览、CRS 提示、加载状态和失败恢复。

## 4. 迭代路线

## 4.1 一周内：自然资源部演示加固

目标：保证后天原型演示稳定、直观、边界清楚。

重点任务：

1. 冻结主演示数据包为 `twm_bishan_multi_admin_eval`。
2. 人工按 `docs/reports/twm_natural_resources_demo_script_2026-06-27.md` 完整走一遍。
3. 演示前确认 `全量加载空间数据`、`定位审查区`、`风险命中`、`推荐方案` 的地图范围都与主演示 bbox 对齐。
4. 演示中明确说明当前数据是演示/非生产数据，不是自然资源部权威数据。
5. 对 `twm_one_map_village_standard_sample` 加强 CRS 风险提示，避免误叠加。
6. 保留 E2E 截图和测试报告，作为手工确认前的自动化证据。

验收标准：

- 演示脚本每一步均可人工复现。
- 地图上能看到数据基础、审查区、风险命中和推荐方案。
- 页面不出现中英文混杂的主要业务文案。
- 不出现空间范围不一致的叙事。

## 4.2 一个月内：数据基础和产品体验补齐

目标：把 TWM 从“能演示”推进到“可接真实数据试点”。

数据基础：

- 建立权威数据接入模板：项目范围、三调/年度变更、永久基本农田、生态红线、城镇开发边界、规划分区、审批历史、复核记录、证据材料。
- 建立 CRS 检测、自动转换建议和阻断规则。
- 建立数据 lineage、字段映射、版本、来源、更新时间和数据质量摘要。
- 建立同案 baseline 数据导入模板，支持人工 GIS、规则引擎和传统优化工具对比。

前端产品：

- 将数据基础浏览器升级为空间数据目录，可以查看每个图层的范围、要素数、字段、来源和抽样属性。
- 增加地图图层开关、透明度、定位、属性查看和冲突对象高亮。
- 为全量加载增加进度、分层加载和失败恢复。
- 将演示脚本关键步骤沉淀为页面内可复用的“演示流程模式”或“审查流程模式”。

后端工程：

- 为 full GeoJSON 增加更明确的大小限制和服务端安全阈值。
- 启动向量瓦片或分块 GeoJSON 技术路线验证。
- 将数据基础接口和 TWM 状态构建接口的诊断字段标准化。

验收标准：

- 任一接入数据包能自动给出空间范围、CRS 状态、图层清单和可用性结论。
- 前端能直接浏览数据基础中的空间数据，而不是只显示几个摘要框。
- baseline comparison 可在真实或脱敏同案数据上运行。

## 4.3 三个月内：真实试点与可验证模拟器

目标：用真实或脱敏业务样本证明 TWM 是否有增益。

数据和评测：

- 接入至少一个真实试点区域的权威边界、控制线、项目审批、规则命中、复核和结果反馈。
- 建立跨期 holdout：用历史前段训练或校准，用后段验证。
- 建立跨区 holdout：至少保留一个行政单元不参与训练，用作外部检验。
- 建立同案 baseline：人工 GIS 审查、规则引擎、传统土地利用模拟或优化排序。

模拟器：

- 用真实历史构建 action-conditioned dynamics 数据集。
- 区分静态现状预测、治理动作预测、反事实评估和因果效果估计。
- 对风险、收益、不确定性、action mask 和 evidence gate 分别评测。
- 引入更强的 TWM-native suitability learner，但保留需求约束、规则解释和审计链。

规划器：

- 明确候选方案生成来源：人工方案、规则生成、优化器生成、MPC/beam 生成。
- 将方案输出分为推荐、阻断、复核三类。
- 输出阻断原因、证据来源、风险变化、收益变化和不确定性。

验收标准：

- 至少一个真实或脱敏试点通过数据 readiness。
- 至少一个预测或规划主张能和 baseline 同案比较。
- 如果 TWM 没有超过 baseline，报告必须如实说明，不升级主张。

## 4.4 六到十二个月：全国级能力和生产化

目标：在权威数据和试点验证成立的前提下，把 TWM 推进为全国级国土空间治理智能底座。

数据平台：

- 接入全国级一张图、年度变更、项目审批、规划管控、执法督察和证据材料。
- 建设多尺度状态图：图斑、项目、村镇、区县、省域、全国。
- 建设时序版本库和政策动作库。
- 建设生产级数据权限、脱敏、审计和内网部署机制。

模型能力：

- 建立多区域、多年份、多政策动作的训练、校准和验证体系。
- 建立模型注册、版本固定、回滚、实验记录和发布门禁。
- 将 TWM simulator、planner、renderer、auditor 形成清晰服务边界。
- 将 claim ladder 作为生产发布和汇报主张的硬门禁。

产品能力：

- 支持全国范围地图浏览、项目审查、政策推演、方案比选和审计报告生成。
- 支持省、市、县多角色协同和不同权限的数据可见性。
- 支持将审查意见、证据截图、规则命中和推荐方案导出成汇报材料。

验收标准：

- 全国级数据在瓦片化和空间索引下可稳定浏览。
- 跨省、跨市、跨年份 holdout 结果可重复。
- 关键业务指标相对 baseline 有明确提升，且能解释提升来自哪里。
- 任何生产结论都能回溯到数据版本、规则版本、模型版本、证据和人工复核记录。

## 5. 六条主线

| 主线 | 当前状态 | 下一步 | 成功标志 |
|---|---|---|---|
| 数据基础 | 演示数据可浏览、可全量加载，主范围已修正 | 权威数据模板、CRS 治理、lineage、真实历史接入 | 任一数据包可自动给出 readiness 和空间证据 |
| 理论形式化 | 已形成对象-关系-规则-证据-行动-动态-规划框架 | 写成稳定白皮书和状态/action/claim contract | 不再依赖“堆算法”叙事 |
| 模拟器 | 有 forecast、rollout、候选 dynamics 和 benchmark | 真实 action-conditioned 数据集、跨期/跨区验证 | 能说明哪些预测通过、哪些只可复核 |
| 规划器 | 可消费候选方案并做约束过滤和 beam ranking | 候选生成、目标函数、政策优先级和人工复核闭环 | 输出推荐、阻断、复核并解释原因 |
| 评测体系 | 已有 E2E、claim gate、baseline comparison scaffold | 真实 same-case baseline、holdout、反事实和审计指标 | 任何升级主张都能被指标支持或阻断 |
| 产品化 | 前端可演示，地图联动已补齐 | 图层浏览、瓦片化、权限审计、内网部署 | 领导能看懂，业务人员能复核，技术人员能追溯 |

## 6. 风险与停止条件

必须避免的风险：

1. 把演示数据说成权威生产数据。
2. 把地图联动说成真实预测效果。
3. 把 planner、beam 或优化器本身说成 TWM 的全部。
4. 把 FLUS/GeoSOS 局部实验结果包装成全面优于传统模型。
5. 在没有真实历史和 baseline 的情况下讨论生产级泛化。

停止或降级条件：

1. 如果权威数据接入后无法建立同案 baseline，TWM 只能保持审查辅助和证据整理定位。
2. 如果跨区或跨期 holdout 不稳定，不能主张泛化。
3. 如果 TWM 不能降低漏检、提高证据完整性或提升方案质量，则不能主张业务增益。
4. 如果地图结果和数据基础空间范围不一致，演示和验收必须暂停。
5. 如果 CRS、数据来源或版本不可追溯，生产试点必须阻断。

## 7. 对外汇报口径

推荐表述：

> TWM 当前已经形成面向国土空间治理的地理空间世界模型原型，可以把数据基础、空间对象、规则证据、行动推演、方案比选和地图审计串成一条可验证链路。它的价值不在于替代自然资源专家，而在于把“看图、查规则、做推演、比方案、留证据”组织成可复核、可审计、可扩展的智能平台。

必须补充边界：

> 当前演示使用的是非生产数据。真实预测能力、泛化能力和规划增益必须在自然资源部门权威数据、真实历史样本和同案 baseline 上验证后才能升级主张。

不建议表述：

> TWM 已经可以自动审批，或者已经证明全国泛化。

更稳妥的结论：

> TWM 已经具备演示级闭环和继续争取权威数据的技术基础。下一阶段的核心不是继续堆功能，而是用权威数据、真实历史、基线对比和地图可视化，把每一个能力主张验证到可被业务和技术共同接受。
