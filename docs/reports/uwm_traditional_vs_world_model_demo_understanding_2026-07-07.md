# UWM 与传统方法双实现对照演示理解

日期：2026-07-07

本文档用于约束后续客户演示版本的实现：必须基于同一个数据基础、同一个城市宜居性分析场景，分别实现传统方法和 UWM 方法，并直观展示二者最终输出能力的差异。

## 核心理解

这个任务不是简单做两个页面，也不是让 UWM 使用更多数据然后赢传统方法。

真正要求是：

```text
同一数据基础 + 同一城市宜居性场景 + 两种方法能力边界不同 + 最终输出对照
```

传统方法和 UWM 必须读取同一批重庆城市宜居性数据：

- 同一批 36 个行政单元；
- 同一套空气质量、服务设施、人口、道路、建筑楼层、空间邻接等数据；
- 同一套宜居性端点；
- 同一时间/空间口径；
- 同一城市宜居性分析任务。

不能让传统方法少用数据、UWM 多用数据，然后宣称 UWM 有优势。

## 同一个业务场景

两种实现都必须面向同一个问题：

> 重庆中心城区哪些地方宜居性有问题，应该如何辅助城市管理者决策？

传统方法和 UWM 都要服务于城市宜居性分析，而不是一个做指标大屏、另一个做论文实验。

## 传统方法实现边界

传统方法不能故意做弱，而应代表真实常见的城市信息化方式。

传统方法可以做：

- 多源指标汇总；
- 静态综合评分；
- 行政单元排名；
- 风险/短板识别；
- TOP N 治理优先区；
- 静态单步启发式建议。

传统方法最终输出的是：

```text
当前哪里差、哪些地方优先关注。
```

传统方法不应做：

- action-conditioned rollout；
- 多步规划；
- 反事实模拟；
- 空间外溢推演；
- 风险调整规划；
- endpoint weight robustness；
- policy/action sequence search。

如果传统方法也开始做这些，它就已经不再是传统方法，而是接近 UWM 了。

## UWM 实现边界

UWM 使用同一份数据，但输出能力不同。

UWM 必须体现世界模型技术架构：

```text
Renderer:  D -> s_t
Simulator: (s_t, a_t) -> s_{t+1}, r, uncertainty
Planner:   search over a_{1:H}
```

UWM 应输出：

- renderer 构造的城市世界状态；
- action-conditioned 未来状态变化；
- 多步 action sequence；
- 每个行政单元的状态变化；
- 空间外溢；
- 风险调整收益；
- 端点权重稳健性；
- 与传统 baseline 的证据比较；
- claim boundary。

UWM 最终回答的是：

```text
如果采取哪些行动组合，未来宜居性会如何变化，为什么这个行动序列比传统静态策略更好？
```

## 客户演示中的直观差异

传统方法最终界面/报告应类似：

```text
九龙镇：宜居性风险最高
南坪镇：服务短板明显
观音桥街道：暴露风险高
建议：按综合得分排序治理
```

UWM 最终界面/报告应类似：

```text
推荐行动序列：
1. 对 江北区|观音桥街道|653 增加绿色基础设施
2. 对 九龙坡区|九龙镇|77 增加绿色基础设施

预计结果：
- 13 个行政单元 livability 改善
- 11 个邻近单元获得空间外溢收益
- risk-adjusted reward 优于 static baseline
- endpoint-aligned score 优于 static baseline
- 胜过 355 个 single-action replay baseline
- empirical p-value = 0.002809
```

客户应能直观看到：

> 传统方法输出“问题清单和排名”；UWM 输出“经过模拟和规划验证的行动方案及其未来影响”。

## 后续实现硬约束

后续开发客户演示版本时，必须遵守以下约束：

1. 传统方法和 UWM 共用同一个 data adapter；
2. 传统方法不能偷偷调用 UWM simulator/planner；
3. UWM 不能使用传统方法没有接入的数据；
4. 对比不只是指标分数，而是最终输出能力差异；
5. 可比较的数值仍要保留，例如 endpoint score、reward、p-value；
6. 所有输出都必须有 claim boundary；
7. 不能把离线模拟或 replay 说成真实政策 outcome。

## 目标实现形态

后续应实现一个客户演示用的“双实现对照系统”：

1. `traditional_livability_baseline`  
   同数据下的传统静态宜居性分析实现。

2. `uwm_livability_world_model`  
   同数据下的世界模型反事实决策实现。

3. `side_by_side_demo`  
   将两者最终输出并排展示，让客户直观看到传统方法无法输出 UWM 的反事实决策包。

## 成功标准

演示成功不是因为 UWM 图表更多，而是因为客户能明确看到：

- 传统方法只能告诉他“哪里有问题”；
- UWM 能告诉他“做什么、会发生什么、为什么这个行动序列更好、风险和外溢如何”；
- 两者使用同一份城市宜居性数据；
- UWM 的优势来自 renderer / simulator / planner 的世界模型能力，而不是数据不公平或展示包装。
