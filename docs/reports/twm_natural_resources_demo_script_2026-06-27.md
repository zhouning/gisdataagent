# TWM 自然资源部原型演示脚本

版本日期：2026-07-03（自然资源部现场演示前复核版）
演示入口：`http://127.0.0.1:8000/`
主演示数据包：`twm_bishan_multi_admin_eval`（璧山多行政单元评估样例）
数据边界：演示/非生产数据，不能作为权威审批结论。

## 演示目标

用一个国土空间审查场景说明 TWM 如何把数据基础、地图定位、规则证据、风险推演、方案比选、基线校验和技术载荷串成一条可审计的业务链路。

本脚本用于人工操作验证。每一步都给出“操作”“预期看到”“讲解要点”。如果某一步预期不一致，应停止演示并记录问题。

## 0. 演示前准备

操作：
1. 打开 `http://127.0.0.1:8000/`。
2. 登录后进入右侧 `智能分析`。
3. 打开 `TWM`。

预期看到：
- 页面标题为 `国土空间世界模型（TWM）`。
- 子 tab 包含 `总览地图`、`数据证据`、`操作推演`、`技术载荷`。
- 默认处在 `总览地图`。

讲解要点：
> 这不是一个孤立地图插件，而是 GIS Data Agent 中面向国土空间审查的世界模型原型。后面会从数据基础、地图、规则、预测、方案和证据边界逐步演示。

## 1. 数据证据：先确认数据基础是什么

操作：
1. 切换到 `数据证据`。
2. 在 `数据基础浏览器` 中确认选中 `璧山多行政单元评估样例`。
3. 如果没有选中，点击 `浏览 璧山多行政单元评估样例`。
4. 在 `空间图层目录` 中找到 `synthetic_projects.geojson`，点击该行 `上图`。
5. 再点击 `全量加载空间数据`。
6. 在 `坐标诊断` 的图层列表中，点击 `parcel_current.geojson` 的 `隐藏`，再点击 `显示`。

预期看到：
- 数据包 ID 显示 `twm_bishan_multi_admin_eval`。
- 总量显示 `22,401`。
- 面板中出现 `空间图层目录`，至少能看到 `parcel_current.geojson`、项目、永久基本农田、生态红线、规划分区、年度变化等空间图层。
- 每个空间图层行能看到字段数量、代表性字段和样例属性；项目图层中应能看到 `XMMC`、`YDMJ`、`approval_status` 等字段。
- 点击 `synthetic_projects.geojson` 的 `上图` 后，面板出现 `已联动图层 synthetic_projects.geojson，90 个空间要素`，地图先显示项目空间图层。
- 面板中出现 `已全量联动 6 个空间图层、21,603 个空间要素`。
- 面板中出现 `坐标诊断`，主演示包状态为 `可直接叠加`。
- `坐标诊断` 图层列表中出现 `隐藏/显示` 开关；隐藏 `parcel_current.geojson` 后，地图应从 6 个图层变成 5 个图层，重新显示后恢复 6 个图层。
- 中间地图出现密集图斑、项目、管控边界等空间图层。
- 当前数据性质仍显示为 `演示/非生产`。

人工核查重点：
- 这一步不是采样预览，而是全量加载当前主演示数据包的 GeoJSON 空间要素。
- 在全量加载前，先看 `空间图层目录`，并用字段/样例属性说明每个图层不只是几何轮廓，还带有审查所需的业务属性；再用 `上图` 逐层核查至少一个空间图层。
- 全量加载后，用图层开关临时隐藏大图斑层，再恢复显示，说明演示地图不是静态图片，而是可以按图层聚焦查看。
- 看到的空间范围应与后续 `总览地图 -> 定位审查区` 保持同域，不应跳到另一个区域。
- 如果坐标诊断显示 `需 CRS 转换`，不能继续把该数据包作为当前地图叠加演示对象。

讲解要点：
> 先把数据基础讲清楚。当前主演示数据包是璧山多行政单元评估样例，包含空间图斑、项目、永久基本农田、生态红线、规划分区、年度变化以及规则、审批、复核、证据索引等表格。空间图层目录里能看到字段和样例属性，例如项目名称、用地面积、审批状态、风险场景等；这说明 TWM 消费的是带业务语义的空间对象，不是几张静态图。我们先逐层加载项目图层，证明空间目录中的数据可以直接回到地图；再全量加载 6 个空间图层，说明这是一套可审查的数据基础。它能支撑端到端原型演示，但仍不是自然资源部门权威生产数据。

## 2. 总览地图：确认空间范围和数据基础对应

操作：
1. 切换到 `总览地图`。
2. 点击 `定位审查区`。

预期看到：
- 地图状态显示 `已联动：审查区定位`。
- 中间地图显示审查范围、拟建项目、硬约束边界。
- 该空间位置应与刚才 `全量加载空间数据` 看到的璧山多行政单元范围一致。

人工核查重点：
- 如果定位审查区和全量数据图层明显不在同一区域，说明演示不能继续。
- 当前脚本要求二者对应到 `twm_bishan_multi_admin_eval` 的空间范围。

讲解要点：
> 领导看惯了地图，所以我们从地图入口开始讲业务对象。这里的蓝色/青色范围表示审查范围和项目，绿色和紫色表示管控边界。关键是这些对象必须落在同一个数据基础空间范围内。

体现的 TWM 能力：
- 渲染器能力：把 TWM 当前业务状态转成地图图层。
- 空间一致性：地图叙事与数据基础范围对应，而不是拿几个无关框框展示。

## 3. 操作推演：构建可推演业务状态

操作：
1. 切换到 `操作推演`。
2. 点击 `璧山演示`。
3. 在 `项目名` 中填写一个演示项目名，例如 `TWM 自然资源部演示`。
4. 点击 `创建项目`。
5. 点击 `构建状态`。

预期看到：
- 项目创建成功。
- `选择项目` 中出现刚创建的项目名。
- 状态摘要出现对象数和关系数。
- 对象数和关系数应大于 100。

讲解要点：
> TWM 做的不是简单加载文件，而是把项目、图斑、规则、证据和关系组织成一个状态版本。后续规则检查、风险预测和方案比选都基于这个状态进行。

体现的 TWM 能力：
- 状态建模能力：把分散 GIS 对象和业务关系组织成可计算、可审计的状态。
- 端到端上下文：项目、状态、规则、预测和规划使用同一个状态上下文。

## 4. 规则审查：从叠加变成证据化风险

操作：
1. 在 `操作推演` 中点击 `检查业务规则`。
2. 切换到 `总览地图`。

预期看到：
- 地图状态显示 `已联动：风险命中`。
- 地图上出现红色风险命中区域。
- 右侧或操作区中规则命中数量大于 0，证据数量大于 0。

人工核查重点：
- 红色风险区域应仍在主演示数据包空间范围内。
- 不应只看到状态文字变化，而地图没有变化。

讲解要点：
> 传统 GIS 可以做叠加，但 TWM 进一步把命中的规则、风险分数、证据来源和业务解释组织起来。风险不是只画红框，而是进入后续预测、验证和方案比选。

体现的 TWM 能力：
- 规则证据能力：把空间冲突转成规则命中和证据项。
- 渲染器能力：规则命中结果能回到地图上展示。

## 5. 风险预测与验证：说明模拟器能力

操作：
1. 切回 `操作推演`。
2. 点击 `风险预测`。
3. 点击 `验证口径`。
4. 点击 `证据审计`。

预期看到：
- `风险预测` 后结果区出现规划收益、约束风险、可信度等信息。
- `验证口径` 后出现阶段列表或验证结论。
- `证据审计` 后证据项数量大于 0。

讲解要点：
> 这里体现的是 TWM 的模拟器能力。系统基于当前状态和治理动作预测风险、收益和不确定性。如果证据不足，系统不会直接给强结论，而是降级为需要复核。

体现的 TWM 能力：
- 模拟器能力：对当前状态和候选治理动作做风险、收益、不确定性推演。
- 证据门槛能力：明确“能不能相信这个结论”，避免原型把演示数据包装成生产结论。

## 6. 方案比选：说明规划器能力

操作：
1. 在 `操作推演` 中点击 `载入候选`。
2. 点击 `方案比选`。
3. 切换到 `总览地图`。

预期看到：
- 候选方案数量大于 0。
- `方案比选` 后出现推荐方案。
- 地图状态显示 `已联动：推荐方案`。
- 地图上出现推荐方案和阻断/风险方案图层。

人工核查重点：
- 推荐方案和阻断方案应仍在主演示数据包空间范围内。
- 如果方案结果没有地图联动，不适合领导演示。

讲解要点：
> 这里体现的是 TWM 的规划器能力。系统从候选方案中筛选推荐方案，同时识别被硬约束阻断或风险较高的方案。推荐不是只看一个分数，而是同时考虑硬约束、风险、收益和证据门槛。

体现的 TWM 能力：
- 规划器能力：在约束、收益、风险和证据门槛之间做可解释选择。
- 地图联动能力：推荐方案和阻断方案回到地图上展示。

## 7. 数据证据：说明边界、基线和下一步真实数据

操作：
1. 切换到 `数据证据`。
2. 查看 `数据基础浏览器`。
3. 向下查看 `关键阻断项`、`完整数据清单`、`完整验证快照`、`问题-数据适配`、`来源报告`。
4. 查看 `生产声明` 和 `主张矩阵`。
5. 查看 `试点就绪矩阵`：重点看 `生产门槛`、合成数据不能替代生产验收、测试数据计划。
6. 查看 `规则样例覆盖`：重点看 `TWM-FARM-001`、`TWM-ECO-001`、`TWM-PLAN-001`、`TWM-URBAN-001` 是否有正例/反例样例，以及 `boundary_case` 缺口。
7. 点击 `基线对比`。

预期看到：
- `完整数据清单` 中包含 `twm_bishan_multi_admin_eval`。
- 文件清单中能看到 `parcel_current.geojson`、`synthetic_projects.geojson`、`tables/approval_records.csv`、`tables/rule_evaluation.csv` 等。
- `问题-数据适配` 中明确说明哪些输出安全、哪些不能承诺。
- `试点就绪矩阵` 显示当前总体仍受生产观察历史和政策动作标签阻断；`生产门槛` 不应显示为通过。
- `规则样例覆盖` 显示四类硬约束规则；现有演示/合成数据可支撑回归覆盖，但 `boundary_case` 缺口应被明确列出。
- `基线对比` 返回 TWM 和基线对比内容。

讲解要点：
> 最后看能力边界。TWM 当前证明的是端到端链路、证据台账、规则-预测-方案闭环和方法框架；真实生产结论必须等权威数据接入后再验证。
> 新增的试点就绪矩阵和规则样例覆盖矩阵，是为了防止演示现场只讲“能做什么”而忽略“还缺什么”。当前可演示的是工程闭环和可审计验证流程；不能把合成样例、公开 benchmark 或 demo e2e 结果说成自然资源部生产验收。

体现的 TWM 能力：
- 主张边界管理：明确哪些能力已有数据支撑，哪些仍是原型主张。
- 数据证据台账：完整展示数据包、文件计数、生产/非生产边界、验证快照和来源报告。
- 基线对比能力：避免只展示 TWM 自己的结果，必须和人工 GIS、规则引擎或优化工具比较。

## 8. 技术载荷：只在被问到时打开

操作：
1. 切换到 `技术载荷`。
2. 展开 `最新技术载荷`。

预期看到：
- 页面显示结构化 JSON。
- JSON 中可见最近一次 API 返回的状态、方案或验证载荷。

讲解要点：
> 这个页面主要给技术人员复核。它说明前端展示背后不是静态图片，而是结构化的状态、规则、预测、验证和方案结果。

## 9. 收束语

> 这个原型现在重点证明三件事：第一，TWM 可以把国土空间业务状态和地图联动起来；第二，可以把规则命中、预测推演、方案比选和证据门槛串成闭环；第三，它没有把演示数据当成权威结论，后续需要接入自然资源部门真实权威数据，才能做严谨的业务增益验证。

## 10. 人工验证失败时的停止条件

出现以下任一情况，应停止演示并记录问题：

1. `全量加载空间数据` 后地图没有出现空间图层。
2. `synthetic_projects.geojson` 单图层 `上图` 后地图没有出现项目空间图层。
3. `定位审查区` 与全量数据图层明显不在同一空间范围。
4. `风险命中` 或 `推荐方案` 只显示状态文字，地图没有联动变化。
5. 数据证据中看不到 `twm_bishan_multi_admin_eval` 或完整数据清单。
6. `试点就绪矩阵` 或 `规则样例覆盖` 没有出现，或合成数据被显示为可满足生产验收。
7. `基线对比` 没有返回对比结果。
8. 技术载荷无法展开或没有 JSON 内容。
