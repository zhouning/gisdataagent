# 传统宜居性 Phase 1A 验证报告

## 交付范围

本阶段实现重庆样例的可复现设施数据产品与 LIV 2.0 S1 当前状态设施供需评估。它不替代后续 S7 网络选址、S6 43 类冲突分析或 S4 项目一致性分析，也不进入 UWM 的未来状态推演。

## 实现链路

- 源清单与读取：高德 POI、百度 AOI、区县人口、OSM 道路、现状用地；
- 设施产品：来源记录、原始分类、内部规范类、映射状态、行政关联和证据边界；
- S1 评估：行政区设施库存、每万人设施数、未映射与未匹配对象；
- API：`GET /api/uwm/traditional-livability/s1` 读取离线快照，缺失或 schema 错误时返回 503，不编造评估；
- 前端：传统宜居性页面独立展示 S1，不把 `not_assessed` 显示为“不达标”。

## 真实数据验证

执行根目录为本地只读解压样例，公开 JSON 只保留相对路径和校验和，不泄露开发机绝对路径。

验证命令使用 `--max-poi-features 50000` 与完整 AOI，因此 `complete_inventory=false`。该边界是主动标记的采样验证，不是完整设施库存。

- 构建耗时：3.70 秒；
- POI 输入：50,000；
- AOI 输入：26,292；
- 去重后设施：76,292；
- 人口单元：40（包括重庆市汇总行）；
- S1 供需指标：270；
- 所有供需指标合规状态：`not_assessed`；
- 权威 FP/FPP 标准：未提供；
- 容量与运营状态：未提供。

## 证据边界

1. 内部分类不是权威 LIV 2.0 43 类字典；未识别类别保持 `unmapped`，不猜测。
2. 高德 POI 可通过行政代码匹配人口；百度 AOI 当前只有区县名称，未建立权威名称—代码 crosswalk，因此保持未匹配。
3. POI/AOI 代表地图对象，不代表核定容量、运营状态、生命周期或服务质量。
4. 没有权威 FP/FPP 标准时只输出库存和每万人指标，不输出“达标/不达标”。
5. 当前 S1 尚未包含道路网络服务区；该能力在 Phase 1B 与 S7 location-allocation 共同实现。
