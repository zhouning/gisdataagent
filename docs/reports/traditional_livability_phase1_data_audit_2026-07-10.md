# 传统宜居性 Phase 1 数据审计

## 结论

现有“城市宜居性分析（传统方法）”是 36 个行政单元的静态代理指标加权排序，能够表达当前状态的综合优先级，但尚不构成 LIV 2.0 S1、S4、S6、S7 所要求的设施清单、供需标准、网络服务区、冲突检测和选址优化能力。

Phase 1 不再扩展综合评分维度，而是建立可复现的“设施—人口—路网—地块”共享数据产品。传统宜居性负责基于该数据产品完成确定性分析；UWM 后续消费其可信当前状态，不在 UWM 页面重复实现静态分析。

## 分类与标准边界

1. 高德 POI 的三级分号分类与百度 AOI 的逗号分类可用于建立可解释的设施语义映射。
2. 当前没有权威 LIV 2.0 43 类字典，因此 Phase 1A 先使用版本化内部规范类，并保留 `unmapped` 与映射依据；S6 实施前必须支持导入权威字典，不能猜测补齐 43 类。
3. 当前没有权威 FP/FPP 阈值。S1 引擎应接受外部标准配置；缺少标准时只输出库存、人口归一化率、覆盖率和“标准未提供”，不得给出合规/不合规结论。
4. POI/AOI 不提供核定容量、运营状态、生命周期和设施组件。此类字段应在数据合同中显式为空，并列为生产阻塞项。

## Phase 1 数据产品边界

共享数据产品由以下可独立校验的对象组成：

- `source_manifest`：源文件、图层、校验和、记录数、坐标系、时间与许可/来源说明；
- `facility_catalogue`：稳定设施 ID、名称、来源、原分类、规范类、映射状态、点/面几何引用和行政代码；
- `population_units`：行政代码、年份、人口口径、原值和代理状态；
- `network_edges`：道路类型、方向、长度、成本模型和假设；
- `land_parcels`：地块 ID、现状用地、面积、空间范围与适宜性输入；
- `quality_report`：重复对象、缺失字段、未映射分类、空间异常和生产阻塞项。

原始 447MB 数据不提交 Git。代码通过 `UWM_TRADITIONAL_LIVABILITY_SOURCE_ROOT` 读取只读源目录，并生成可重建的本地派生产品；单元测试使用小型内存/临时样例。

## 实施顺序

1. Phase 1A：源清单、受控设施分类、设施目录、人口需求和 S1 供需评估。
2. Phase 1B：基于道路网络的服务区与 S7 location-allocation。
3. Phase 1C：S6 权威 43 类导入、未映射报告和 150m 冲突。
4. Phase 1D：S4 项目活动分类、需求一致性、重复供给与现有资源冲突。

该顺序保证 S7、S6、S4 复用同一设施对象和证据边界，不产生四套互不一致的数据加工逻辑。
