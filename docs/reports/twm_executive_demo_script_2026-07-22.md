# TWM 新版现场演示脚本

面向对象：省自然资源厅信息中心主任
建议时长：12 至 13 分钟
演示入口：GIS Data Agent -> 智能分析 -> TWM -> 汇报演示
演示定位：展示受控工程能力、研究证据和试点路径，不进行生产效果承诺

## 演示场景卡：整场演示只回答一个业务问题

**场景名称：重庆市璧山区多行政单元受控样例——耕地保护与空间布局方案审查。**

**场景性质：** 这是基于 `twm_bishan_multi_admin_eval` 工程样例的受控演示，数据中含合成或非生产要素，用于验证系统流程，不代表璧山区真实在办项目，也不用于形成行政审批结论。

**业务问题：** 在永久基本农田、生态保护红线和用途管制等约束下，拟建项目及空间布局候选方案中，哪些方案不可进入推荐空间，哪些方案可以进入合法可行域继续比选，以及系统凭什么形成这一判断？

**系统输入：** 项目、现状图斑、永久基本农田、生态保护红线、规划分区、行政单元、规则条款、空间计算结果和复核材料；演示采用“保护”动作、项目目标、依据完整度 `0.78` 和 `3` 期验证。

**候选方案：** 优化数据包中共有 `7` 个候选方案。按当前冻结数据，`3` 个进入合法可行域，`4` 个因触碰永久基本农田或生态保护红线等硬约束被阻断。现场推荐方案编号以系统实时结果为准，但必须来自这 `3` 个合法可行候选。

**演示输出：**

- 审查范围及项目、图斑、控制线的地图联动；
- 规则命中、证据材料和待人工复核事项；
- 单步风险、规划效用和不确定性预测；
- `3` 个合法方案各自独立展开 `3` 期空间状态转移，共 `9` 次状态转移计算；
- 每期累计动作、空间几何、对象关系、硬约束和空间目标均重新写回并留存哈希；
- 每条 trace 均标记为 Simulator 在线递归执行，不消费预计算时期状态；
- `7 / 3 / 4` 候选审计、跨期累计排序及不可推荐原因。

**不输出：** 自动审批通过或不通过、璧山区真实治理效果、政策因果效果、生产级最优布局。

**材料关系：** 璧山多行政单元样例是现场操作主场景；Paper9 双县离线结果是算法路线的既有落地旁证；上海供地事件编译说明真实事件如何进入训练准备；GWM Benchmark 说明当前 Kernel 的验证边界。后三者均不是本次璧山场景的实时推演结果。

## 一、演示前检查

1. 使用 1920 x 1080 或不低于 1440 x 900 的屏幕，浏览器缩放设为 100%。
2. 登录后进入 TWM，确认默认打开全宽“汇报演示”页。
3. 顶部必须显示“受控演示就绪，生产效果尚未验证”。如果显示“演示证据需复核”，先检查本地证据文件，不要带着异常状态开始正式汇报。
4. 确认 Paper9 区域显示“离线产物实时核验”或带日期的“验证快照”，两种状态都不能口播为生产验收。
5. 确认 Benchmark 区域保留 `0/10` 和“训练输入准入：未通过”，不要为了画面好看隐藏失败项。
6. 正式演示前点击一次顶部刷新按钮。v0.3 已编译对象数是实时值，口播时以屏幕为准，不背固定数字。
7. 进入“操作推演”，确认业务场景为“耕地保护与占补平衡审查”，工作空间预设为“重庆市璧山区多行政单元”，依据完整度为 `0.78`，验证期数为 `3`。
8. 优先准备一个已完成状态构建和规则检查的演示项目；现场不全量加载 21,603 个空间要素，也不重新训练模型。

## 二、现场演示主线

### 0:00 至 0:45 先给结论

停留在顶部状态区。

建议话术：

> 今天展示的不是一个换皮的一张图，也不是让大模型直接生成规划结论。TWM 的目标，是把自然资源空间对象、规划规则、业务动作、状态变化、候选方案和证据责任组织成一个可推演、可验证、可审计的治理闭环。当前受控演示已经就绪，但生产效果尚未验证，这个边界系统会主动显示。

主任应先看到三个信号：

- 系统能做什么；
- 证据来自哪里；
- 哪些结论当前不能说。

### 0:45 至 1:30 展示业务闭环

指向“观测 -> 编译 -> 推演 -> 比选 -> 验证 -> 审查”。

建议话术：

> 一张图解决的是看见和查询，TWM 增加的是行动进入以后世界状态如何变化、有哪些方案可选、为什么某个方案不可行，以及现有证据是否足以支撑结论。最后输出的不是一个裸分数，而是风险理由、证据缺口、候选方案和人工复核任务。

### 1:30 至 2:30 解释 GWM 的独特性

停留在“GWM 在世界模型谱系中的位置”。

建议话术：

> 视频和机器人世界模型主要学习感知与动作后的短时变化；气象模型主要预测连续物理场；数字孪生和一张图主要还原当前状态；LLM 擅长理解意图和编排工具。GWM 的独特任务，是同时表达坐标、尺度、空间关系、人类行动、制度约束、证据来源和区域迁移。它不是用语言想象一个未来，而是把未来状态放进可计算、可否证的空间约束中。

### 2:30 至 3:45 解释技术架构

指向三列架构：DAM-GK -> GWM Runtime Kernel -> TWM。

建议话术：

> DAM-GK 的全称是 Dynamic Action-Conditioned Multi-scale Geospatial Kernel，也就是动态、动作条件、多尺度地理空间内核。它处理状态编码、多关系传播、动作条件、时滞、动态拓扑、多尺度一致性和不确定性。它只是动力学算子，不等于完整世界模型。GWM Runtime Kernel 继续负责状态版本、规则和动作契约、模拟器、规划器、评价器、结论发布前的证据审查、审计和人工复核。TWM 再把自然资源图斑、控制线、项目、规则和审批责任实例化进来。

容易被追问的理论来源：

- 状态、动作、转移和回报来自 MDP、强化学习与模型预测控制；
- 图关系传播来自图神经网络和关系建模；
- 动态拓扑和时滞来自时空过程建模；
- 反事实与对照来自因果推断的识别思想；
- 准入门、版本和审计来自安全关键系统与模型治理。

### 3:45 至 5:15 展示耕地布局优化落地证据

停留在双县结果表。

建议话术：

> 这条路线不是从概念开始的。耕地布局优化面对的是组合决策：换入一块地会改变相邻地块的连片关系，连续多步调整又会改变后续可选动作。逐地块适宜性评分表达不了组合效应，静态叠加表达不了多步后的邻接变化，穷举不可计算，单步贪心又容易停在局部方案。因此我们用学习到的状态转移和多步滚动搜索，在硬约束下产生候选布局。

按屏幕读结果，不做额外推断：

- 四川省内江市东兴区：耕地面积 `+508.783 ha`，坡度 `-0.343%`，连片度 `+0.0530`，完成 475 次置换；
- 重庆市璧山区：耕地面积 `+4.323 ha`，坡度 `-0.856%`，连片度 `+0.0268`，完成 424 次置换；
- 两地均通过耕地面积不减少、平均坡度下降、空间连片度上升三项硬门槛；
- 百亩方变化只是观察指标，不是三项硬门槛之一。

必须补充：

> 这证明离线全流程能够运行并产生满足约束的候选方案，不等于方案已经获批，也不等于已经证明跨省泛化和真实治理成效。

### 5:15 至 6:15 解释 GeoSOS-FLUS 对标

停留在比较表。

建议话术：

> 选择 GeoSOS-FLUS，是因为它是土地利用变化模拟的权威对标物，可以检验 TWM 是否只是换名的土地利用模拟器。FLUS 擅长在需求量、适宜性、邻域竞争和转换规则下模拟土地利用格局。TWM 的目标范围更宽，显式处理业务动作、动作可行性、状态写回、方案搜索、规则证据和审计责任。因此可以说目标能力边界和理论上限更宽，但不能说当前预测精度已经优于 GeoSOS-FLUS。精度优劣仍要同数据、同任务、同切分评测。

### 6:15 至 7:00 展示 TWM 数据基础

指向五个数据指标。

建议话术：

> 当前受控底座有 22,401 条记录和 21,603 个空间要素，能够跑通对象、关系、规则、证据、风险审查、方案和审计链。还有 256 行、128 对、4 个区域、8 个时期的合成时序实验用于管线诊断。但生产观测历史和生产政策动作历史都是 0，所以系统不会把这些数据升级成真实审批、预测或因果结论。

### 7:00 至 8:15 展示真实事件编译

停留在上海事件链。

建议话术：

> 这是近期 Geospatial Kernel 数据工程最关键的进展。系统从 62 个官方供地事件候选开始，恢复 13 宗宗地几何，其中 9 宗具备严格前后期窗口，再形成 194 个处理状态节点、194 个匹配对照候选和 194 个远距离负对照。它证明官方事件可以编译成状态、动作、时间和对照候选。

紧接着指出两个红色或黄色门：

> 当前仍不能确认对照单元完全没有其他供地或建设事件，也没有观测到实际开工时间，因此对照设计未完成，训练没有准入。这一页叫真实事件数据编译，不叫政策效果预测。

### 8:15 至 9:15 展示 Benchmark 的否证能力

停留在 Benchmark 门禁矩阵。

建议话术：

> 我们要求 Benchmark 能够否定自己的 Kernel。当前 10 个固定种子中，完整 Kernel 在核心 persistence 门槛上是 0/10，不能通过。但无图结构消融、动作置乱和反转拓扑分别给出了 10/10 的诊断信号，说明模型确实在使用空间图、动作和拓扑信息；完整模型优于无动作输入只有 5/10，动作增益还不稳定。右侧 v0.3 的 forcing 和 topology 证书仍然失败，训练输入未准入。

结论只说：

> 这些结果证明研发过程具备发现错误和拒绝过早结论的能力，不证明 DAM-GK 已经成熟。

### 9:15 至 10:15 收束到省级试点

停留在“当前主张边界”和“省级试点的最小数据闭环”。

建议话术：

> 现在最合理的合作方式，不是先汇聚全省所有数据，而是选一个责任链清楚、可脱敏、能取得前后结果的业务闭环。P0 是权威现势空间底板和脱敏业务闭环历史；P1 是动作可行性标签和多期结果观测；P2 是现有人工 GIS、规则引擎或 FLUS 等工具的同题基线。这样才能回答 TWM 是否降低复核成本、减少漏检、提升方案质量，而不只是展示技术复杂度。

### 10:15 至 12:30 执行重庆市璧山区主场景

不要临场任选入口，按下面的固定路径完成同一个业务场景：

1. 点击“进入地图联动”，用“定位审查区”说明本次审查对象是重庆市璧山区多行政单元受控样例，再展示项目、永久基本农田和生态保护红线的空间关系。
2. 进入“操作推演”，确认业务场景为“耕地保护与占补平衡审查”，选择“重庆市璧山区多行政单元”和已预热状态。
3. 点击“检查业务规则”，展示风险命中已经关联规则编号、空间计算和证据材料；切回地图确认风险命中上图。
4. 点击“风险预测”和“验证口径”，说明这是通用单动作预测与验证入口；验证未通过时如实显示“需复核”，不要把这一入口与后面的多候选空间状态转移混为一谈。
5. 点击“依据核查”，说明证据审查不是再算一个模型分数，而是检查证据摘要、关键复核任务和结论发布条件。
6. 点击“载入候选”，确认屏幕显示候选方案 `7`、合法可行 `3`、阻断方案 `4`。
7. 点击“方案比选”，确认页面显示 `3 个方案 x 3 期`、`9 次状态转移计算`、`9 次硬约束重算`和“Simulator 在线递归执行”。逐期查看每个方案的累计动作数、空间目标、父状态与当前状态哈希和约束复核；确认推荐方案来自跨期轨迹排序，四个阻断方案不参与选优。不要把推荐候选口播为审批结论、真实效果预测或全局最优解。

建议话术：

> 这个场景回答的是，在保护红线和用途管制约束下，哪些空间布局方案根本不能推荐，剩余方案中哪个更值得提交复核。系统先对七个候选做准入检查，四个硬约束方案退出推荐空间；现状基线、均衡治理和生态约束优先三个合法方案分别展开三期状态转移。Simulator 从初始状态开始在线执行，每一期只消费上一期写回状态和本期新增动作，重新汇总项目与控制线、规划区的关系，重算永久基本农田和生态红线约束，再输出当期空间目标。规划器只读取九条完整状态转移 trace 做跨期累计排序，不消费预计算时期状态，也不使用候选表里的旧汇总分决定结果。

必须补充能力边界：

> 当前多方案演示使用 GIS 与规则驱动的确定性机制后端，能够证明状态、动作、关系、约束、结果和审计链真实执行；它还不是已经通过真实业务历史留出验证的学习型政策效果模型。页面会主动显示这一边界。

“查看数据依据”用于主任追问数据来源时补充；“状态图谱”和“技术载荷”仅在主任主动追问对象关系、接口或原始结构时打开，不纳入主路径。

## 三、结束语

> 未来智能体平台不能只靠 LLM。LLM 负责理解需求、调用工具和解释过程，世界模型负责维护可计算状态、模拟行动后果、搜索方案并接受基线检验，结论发布前的证据审查负责决定结果能否提交、是否需要复核。TWM 是这一架构在自然资源领域的实例，当前已经具备受控演示和省级试点设计条件，下一步的关键不是再增加概念，而是用一个真实业务闭环完成数据准入和同题价值验证。

- “DAM-GK 已经通过通用世界模型验证”；
- “TWM 当前精度已经全面超过 GeoSOS-FLUS”；
- “22,401 条数据已经足够生产部署”；
- “上海供地事件链已经完成因果识别”；
- “系统可以自动替代规划审批或执法认定”；
- “百亩方是本次双县实验的硬约束”；
- “0/10 只是数据不好，所以可以忽略”。

推荐替代表述：

- “受控工程演示已经就绪，生产效果尚未验证”；
- “目标能力边界更宽，当前精度需要同题评测”；
- “真实事件已经完成可追溯编译，训练准入门仍未通过”；
- “Benchmark 给出机制诊断信号，同时否定了当前成熟度主张”；
- “系统辅助形成候选方案、证据缺口和复核任务，法定决策仍由业务责任主体完成”。

## 五、常见追问

### 这是不是另一个土地利用模拟模型？

不是。土地利用模拟是 TWM 可消费的一类动力学或基线能力；TWM 还要求显式动作、规则可行性、状态写回、方案搜索、证据责任和人工复核闭环。

### 0/10 为什么还值得展示？

因为它防止把局部消融信号包装成通用能力。系统已能识别图、动作和拓扑信号，但尚未稳定超过核心基线，这正是下一轮数据和 Kernel 设计的可操作问题。

### 为什么不用 LLM 直接调用 GIS 工具？

LLM 可以编排工具，但不能仅凭语言保证空间状态一致、动作合法、跨期结果可复现。世界模型提供状态和转移约束，结论发布前的证据审查限制结果的使用等级。

### 省厅需要先提供多少数据？

先提供一个可脱敏的最小业务闭环，而不是全库：权威空间底板、项目或事件几何、动作及时间、规则命中、复核处置和后续结果，再配一套现有工作流基线。

### 最大落地难点是什么？

不是前端或单个模型，而是三件事同时成立：真实行动与结果能够可靠对齐；法定规则和版本能够机器执行并追溯；跨地区、跨时期效果能够在严格留出和业务基线下通过验证。
