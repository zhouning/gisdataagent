# 重庆开发控制规则与规划条件证据就绪度验证报告

## 对应需求

- 客户侧需求22：开发控制规则与规划条件分析。
- 技术路线：先建立可追溯规则资产目录和项目级 DCR 数据契约；在权威项目规划条件缺失时，DCR+ 世界模型执行门保持关闭。

## 已实现

- 产品模式：`uwm.development_control_rule_readiness.v1`。
- 产品包：`development-control-5793d9f64ee815896790`。
- 规则资产：9项，覆盖参考分类标准、技术数据标准、质量/校验能力和规划规则契约。
- 项目级 DCR 通道：14项，覆盖批准用途、容积率、建筑密度、高度、绿地率、退界、间距、停车、公共服务、用途兼容、特殊控制区、批准文件、规则优先级和有效期。
- 独立服务、6个鉴权 API 和“开发控制规则”独立页面。

## 证据边界

- 9项资产全部来自仓库内可追溯文件，但均为 `reference_only`。
- 可执行项目级规则：0项。
- 可用 DCR 通道：0项；所有值保持 `null`，缺失不解释为零或不受限制。
- DCR+ 门禁中的适用性、法定参数提取、冲突规则消解、项目合规判断、约束传播和自动方案修改全部关闭。
- 土地利用分类不等于开发许可，静态筛查距离不等于法定退界，规则匹配不等于项目审批。

## 未生成内容

- 未生成法定容积率、密度、高度、绿地率、退界、间距、停车或公共设施配建要求。
- 未生成可建面积、开发规模、建设许可、项目审批或合规结论。
- 未自动修改规划方案，也未声称任何规则对具体项目具有法律适用性。

## 验证结果

- 聚焦 Python 测试通过。
- 独立验证器通过，`fabricated_value_count=0`。
- 六件套产品文件 bundle ID 一致。
- 独立验证摘要：9项规则资产、14个 DCR 通道、0项可执行项目规则、0项可用 DCR 通道。

## 生产化前置条件

只有在接入经批准的项目级规划条件后，才可逐通道开放执行能力。每条可执行规则必须包含权威来源、批准或发布标识、版本、有效期、空间适用范围、对象类型、参数定义、单位与计算方法、冲突优先级和可引用条款，并通过独立法律/规划业务复核。
