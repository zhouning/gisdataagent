# 本体驱动的灌区世界模型（ODIWM）需求评估

日期：2026-08-14

评估对象：课题群二“本体驱动的灌区世界模型（Ontology-Driven Irrigation World Model, ODIWM）”

评估性质：立项前需求与技术路线评估，不代表能力已实现或指标已承诺

## 1. 执行摘要

本课题方向具有较高科研价值，可以复用既有 Geospatial World Model（GWM）、Water World Model（WWM）、Agricultural World Model（AWM）研究中的状态—动作合同、地理拓扑、守恒计算、模型路由和本体治理基础，但当前需求文本存在创新主张过满、概念层次混合、技术选型过早收敛、验证路径不足和预期指标不可直接验收等问题。这里的“可复用”主要指工程合同、专业算子和验证方法，不表示既有 Geospatial Kernel 已经实现 JEPA，也不表示已有可直接迁移的 JEPA 编码器、训练目标或模型权重。

综合判断为：

> **建议修改后立项，不建议按当前文本直接承诺。**

ODIWM 不宜被描述为一个从零开始、以单一 `Irrigation-JEPA` 替代专业机理模型的端到端系统。适合灌区场景的路线不是在 Geospatial Kernel 和 JEPA 之间二选一，而是确定明确的主次关系：

- **工程与首期科研主线：**本体和权威 GIS 拓扑、类型化状态与动作合同、守恒内核、状态估计、专业机理模型、约束优化、Proposal 和人工审查；
- **学习型加速支线：**在相同合同和评价口径下比较降阶模型、状态空间模型、图时空模型、神经算子、受界残差和其他代理；
- **JEPA 候选研究：**只有在有效轨迹、无标签时空数据和独立验证条件满足时，才评估其是否具有额外表征或代理价值，不作为首期交付前置条件。

更准确的总体定位是：

> **ODIWM 是 WWM 的灌区运行层、AWM 的田间水土作物层与灌区专业本体治理层的融合实例。它在确定的语义合同中执行带不确定性的动作条件动力学推演，并通过专业机理模型、按条件准入的学习型代理、规划器、证据门和人工审批形成受治理的条件情景与候选方案比较闭环。**

其真正有潜力形成学术突破的核心问题，不是将“本体、JEPA、PINN、MCTS”简单组合，也不是为既有内核补贴一个 JEPA 标签，而是通过严格实验回答：

> 本体约束是否能够显著提高跨灌区迁移能力、物理与业务约束合规性、长时多步推演稳定性和规划决策质量？

## 2. 与既有 GWM 研究和实现的关系

### 2.1 不是完全独立的新方向

现有 WWM 研究已将灌区渠系配水识别为适合运行型世界模型的任务。其特点是渠系网络明确、调控动作明确、容量和时延约束明确、反馈相对频繁，具备构造动作条件多步推演闭环的基础。

现有 AWM-CropWater 研究也已提出“田块—农场—灌区/县域”的分层作物—水资源世界模型，目标是在天气不确定、供水受限和田块状态部分可观测的条件下，联合规划渠系水量分配与田间灌溉时序。

因此，ODIWM 更适合作为既有研究合同和专业问题定义上的融合实例：

```text
Geospatial Kernel 合同与算子层
├── WWM 灌区运行层
│   ├── 水源、渠系、闸门、泵站与量测设施
│   ├── 渠系水动力与输配水状态
│   └── 配水、闸控、泵控和应急调度动作
├── AWM 田间生产层
│   ├── 田块、土壤、作物与根区状态
│   ├── 蒸散发、土壤水分和作物胁迫过程
│   └── 灌溉时机、灌溉量和田间管理动作
└── ODIWM 专业语义与治理层
    ├── 灌区领域本体与版本化实例图
    ├── 状态、观测、动作、约束和证据合同
    ├── 模型路由、Proposal、审批与执行审计
    └── 跨灌区语义对齐与迁移验证
```

### 2.2 Geospatial Kernel 与 JEPA 没有直接实现继承

既有 Geospatial Kernel 的实质是围绕权威 GIS 拓扑、类型化状态与动作、守恒通量、水量账、专业算子、状态估计、预测闭包和证据准入组织的计算内核。其基本关系可以概括为：

```text
GIS Compiler
  -> Conservative Kernel
  -> Forecast Closure
```

该实现没有以 JEPA 为骨架，也没有提供现代 JEPA 通常需要的 context/target encoder 分支、停止梯度或 EMA target 更新、masked latent target prediction 和相应训练循环。因此，不能将 ODIWM 的 JEPA 候选描述为 Geospatial Kernel 的自然升级、既有能力延伸或已有模型迁移。

历史研究代码中曾存在标记为 JEPA 的独立潜在动力学原型，使用冻结地理嵌入预测下一时刻表示。它与 Geospatial Kernel 是两条不同路径，并且更准确地属于“冻结表征 + 潜在动力学预测”，不能作为完整现代 JEPA 已实现的证据。WWM、AWM 和 TWM 文档中对潜在状态或 GeoJEPA 的讨论也主要是候选研究方向，而非 Geospatial Kernel 的实现骨干。

ODIWM 可以复用的内容与必须新建的内容应明确分开：

| 可复用基础 | ODIWM 需要新增并验证 |
|---|---|
| 权威拓扑编译、状态/动作/forcing 合同 | 灌区专用状态、动作和跨尺度耦合 |
| 守恒通量、水量账、状态估计与预测闭包接口 | 经现场数据校准的渠系—田间专业模型 |
| 模型准入、留出验证、证据和人工审批框架 | 任一学习型代理的训练数据、模型和独立验证 |
| 本体发布、映射和工具治理 | 若采用 JEPA，其编码器、目标分支、训练目标和权重 |

二者未来可以通过相同状态、动作、forcing、拓扑和证据合同进行集成，但这是接口层组合，不是算法或模型权重的直接继承。

### 2.3 必须采用分层耦合，而非单一潜在空间

渠系水动力、田间土壤水分和作物生长具有不同的空间支撑、状态变量、时间尺度和验证方法：

| 子系统 | 典型对象 | 主要过程 | 典型时间尺度 |
|---|---|---|---|
| 水源与骨干渠系 | 水库、渠段、闸门、泵站 | 蓄泄、输水、分水、水位流量传播 | 分钟—小时 |
| 末级渠系与田间供水 | 支渠、斗渠、农渠、田块入口 | 配水、输水损失、入田过程 | 小时—日 |
| 土壤—作物系统 | 土层、根区、作物群体 | 入渗、蒸散、根系吸水、胁迫与生长 | 日—生育期 |
| 经营与治理系统 | 用水户、配额、水权、调度规程 | 申请、分配、审批、执行和对账 | 事件—季度 |

不能将这些过程粗暴压缩为同一时间步或同一个不可解释的潜在状态。推荐使用类型化、分层、可组合的 belief state，并通过显式边界通量和状态交换实现耦合。

## 3. 需求中最有价值的部分

### 3.1 本体作为类型化状态与动作合同

将灌区本体用于定义 Object、Link、State、Observation、Action、Constraint 和 Evidence，能够为世界模型提供稳定的语义坐标。其直接价值包括：

- 限定对象类型、关系方向、单位、空间支撑和时间支撑；
- 区分真实状态、传感器观测、外生强迫、候选动作、已下发指令和实际执行动作；
- 防止模型任意改写渠系拓扑、工程能力、水权约束和动作权限；
- 为不同灌区的对象与动作建立显式对齐合同；
- 为模型输入、输出、Proposal 和执行回执提供可审计的版本身份。

这一方向成立，但需要注意：本体提供的是语义确定性和结构约束，不会消除水文气象、状态估计、参数和模型结构的不确定性。

### 3.2 从像素预测转向对象状态演化

灌区世界的核心对象是渠道、闸门、泵站、水源、田块、土壤、作物和用水主体。以对象—关系状态作为学习和推演单元，比照搬视频生成式世界模型的像素预测路线更符合专业问题结构。

潜在状态仍可以存在，但必须能够解码或映射到受本体约束的显式状态，例如：

- 渠段水位、流量和存量；
- 闸门开度、泵站工况和实际过流；
- 田块根区土壤含水量和水分胁迫；
- 作物物候、冠层状态和蒸散需求；
- 配额余额、累计供水和公平性状态；
- 数据质量、模型适用性和证据等级。

### 3.3 机理模型与学习模型组合

渠系水动力、土壤水分和作物耗水过程应由专业模型守住物理账和基本机制。学习模型更适合承担：

- 部分可观测状态估计；
- 区域参数反演和在线校准；
- 未建模过程的残差修正；
- 高成本模拟器的快速代理；
- 模型误差与不确定性估计；
- 跨灌区表征迁移。

这比用一个统一神经网络替代圣维南方程、Richards 方程和作物模型更可信，也更容易形成可证伪的模块级研究结论。

### 3.4 Proposal、人工审批与受治理 Action

“候选方案而非自动命令”的定位适合真实灌区运行环境。Proposal 至少应绑定：

- 输入状态快照、预报版本和本体版本；
- 候选动作序列及其适用对象；
- 硬约束检查和不可行原因；
- 各情景下的预测结果和不确定性；
- 相对于规则、专业模型和现行方案的增量价值；
- 模型版本、运行轨迹和证据引用；
- 审批主体、权限范围、有效期和撤销条件。

## 4. 需要修正的核心论断

### 4.1 “确定语义空间”不等于确定性世界

当前表述：

> 让世界模型在“确定的语义空间”中推演，而非在“概率的黑箱”中生成。

问题在于，本体可以确定类型、关系、约束和合法动作，但真实灌区仍然是部分可观测并且存在天气、需水、设备状态、测量误差和参数不确定性的动态系统。

建议改写为：

> **在版本化、可验证的语义合同中执行带不确定性的动作条件动力学推演，限制模型的对象、关系、动作和约束边界，同时显式传播状态与模型不确定性。**

### 4.2 本体约束不自动产生因果性

当前表述：

> 从“相关性预测”跃迁到“本体约束的因果性推演”。

这一表述不严谨。本体能够保证“对什么对象施加了什么类型的动作”表达正确，但不能自动解决混杂、策略选择偏差、未观测干预和反事实不可观测等因果识别问题。

因果主张至少需要以下证据之一：

- 随机或受控灌溉试验；
- 自然实验或准实验；
- 明确的结构因果模型和可辩护识别假设；
- 专业机理模型支持的合成干预，并明确标记为模型条件情景；
- 跨年份、跨区域的前瞻影子验证或受控试点。

建议改写为：

> **形成由本体和机理约束的动作条件推演能力，并通过田间试验、准实验、历史项目或前瞻试点对动作效果进行因果校准。**

### 4.3 PINN 不应被预设为唯一物理融合方式

将物理规律嵌入学习系统的方向正确，但 PINN 对大规模渠网、刚性偏微分方程、复杂边界、长时多步推演和多工况泛化未必是最优方案。

建议将以下路线纳入公平比较：

1. 专业机理模型直接计算；
2. 专业机理模型加数据驱动残差修正；
3. 可微分模拟器；
4. 神经算子或图网络代理模型；
5. PINN 或弱形式物理信息学习；
6. 多保真模型路由与误差校正。

技术路线应由准确率、守恒误差、稳定性、推理成本和跨域迁移结果决定，而不是由课题名称预先决定。

### 4.4 MCTS 不应与“秒级最优”绑定

灌区调度通常同时具有连续动作、多目标、长时域、部分可观测、硬约束和不确定外生输入。MCTS 可以作为候选规划器，但不保证优于 MPC、MILP、动态规划、启发式调度或鲁棒优化。

建议将规划器定义为可插拔消费者，并比较：

- 规则与现行调度规程；
- MILP 或网络流优化；
- MPC 与鲁棒 MPC；
- MCTS 或 beam search；
- 强化学习策略；
- 专家给定方案集合的情景排序。

输出应称为“满足冻结约束和目标权重的候选 Proposal 集”，不宜在未证明全局最优性时使用“最优调控 Proposal”。

### 4.5 Action Type 对齐不足以完成 Sim-to-Real

本体中的 Action Type 与现实设备动作一一映射，是迁移的必要条件，但不是充分条件。真实迁移还需要处理：

- 渠道断面、糙率、渗漏和设备能力差异；
- 传感器偏差、数据缺失和时间延迟；
- 控制指令与实际执行之间的偏差；
- 通信失败、执行器迟滞和人工干预；
- 作物、土壤、气候和管理制度差异；
- 未见极端事件和非平稳变化。

建议增加系统辨识、域随机化、在线状态同化、安全屏障、影子运行、回退策略和受控试点。

### 4.6 “LLM 永远不生成 SQL”需要改为治理边界

不让 LLM 直接连接生产数据库或执行任意 SQL 是合理的安全原则，但完全禁止生成任何中间查询计划并非必要，也可能与现有受治理 NL2Semantic2SQL 能力冲突。

建议改为：

> **LLM 不直接访问生产数据源、不持有数据库凭据、不执行任意 SQL，也不绕过本体和权限合同；LLM 只生成受类型、权限、预算和只读策略约束的查询或工具计划，由确定性服务验证并执行。**

同时，本体查询、指标服务、结构化数据查询、GIS 工具和 RAG 应按问题类型协作，不应让 OAG 成为新的孤立服务或宣称能够替代所有数据访问方式。

### 4.7 与 Cosmos、Genie 的对标需要调整

NVIDIA Cosmos 和 DeepMind Genie 主要面向视觉、物理 AI 或通用交互环境。将 ODIWM 描述为其“灌区专业化改造”可以用于通俗说明，但不足以构成严格学术定位。

建议正式定位为：

> **面向灌区网络物理系统的本体—机理—学习混合世界模型。**

学术比较对象应同时包括：

- 灌区数字孪生和渠系水动力模拟；
- 土壤—作物过程模型；
- 水资源系统优化与灌区配水优化；
- 图时空预测和神经算子；
- 物理信息机器学习；
- action-conditioned latent world model；
- ontology-guided machine learning 与 neuro-symbolic systems。

## 5. 建议的 ODIWM 技术架构

```text
多源观测、工程台账、调度日志、气象与田间数据
                         ↓
灌区本体、实例解析、版本和时空语义对齐
                         ↓
类型化 Observation / State / Action / Forcing / Evidence
                         ↓
Belief-State Estimator
                         ↓
分层混合模拟器
├── 渠系水动力模型
├── 土壤水分模型
├── 作物蒸散发与生长模型
├── 简化模型 / 降阶模型 / 状态空间基线
├── 通过准入的学习型代理或受界残差
└── 不确定性估计与确定性模型路由
                         ↓
动作条件、多步、集合 rollout trace
                         ↓
规则 / MILP / MPC / MCTS / 鲁棒规划器
                         ↓
Proposal：动作、结果、约束、风险、不确定性与证据
                         ↓
Evals 与 Evidence Gates
                         ↓
人工审批
                         ↓
受治理 Action Runtime
                         ↓
现实执行、回执、对账、补偿与状态同化
```

### 5.1 本体的职责边界

本体负责：

- 对象、属性、关系、过程、角色、规则和信息对象的定义；
- 状态变量、动作类型、约束类型和证据类型的语义合同；
- 数据字段、设备接口、模拟器端口与领域概念之间的映射；
- 可行关系和允许状态转换的静态验证；
- 跨灌区概念对齐、版本治理与来源追踪。

本体不负责：

- 替代数值水动力求解；
- 从历史数据中自动识别因果效应；
- 消除观测和预测不确定性；
- 自动决定公共目标权重与供水公平原则；
- 自动获得现实控制权限。

模型路由默认优先使用已经校准并通过适用性检查的专业模型或透明基线。学习型代理只有在相同任务合同下证明精度、守恒、稳定性或速度价值后才可晋级；规划阶段仍应保留高保真模型复核或独立评估器。JEPA、神经算子、图时空模型和 PINN 都属于待比较的技术选项，不是架构中的固定依赖。

### 5.2 Irrigation-JEPA 的触发条件与合理研究定义

不需要通过完整实施两套平行系统才能判断主线。专业模型、状态估计、守恒内核和约束优化是灌区场景的必要基础；是否增加 JEPA，应在数据审计和简单基线完成后按证据触发。至少应先确认：

- 存在足够多相互独立的轨迹窗口、动作事件和未见验证窗口；
- 大量未标注时空观测确实可被表示学习利用，而不是只有少量已治理状态变量；
- 直接监督预测、状态空间模型、降阶模型或普通图模型尚不能满足任务；
- JEPA 式目标相对同容量非 JEPA 模型的增量能够通过消融验证；
- 多步动作响应、物理账和规划消费是最终评价，而不是 latent 相似度。

Irrigation-JEPA 可以被定义为本体锚定的动作条件潜在动力学候选，但至少需要满足：

1. 具有明确分离的 context encoder 和 target encoder，target 分支采用停止梯度及可复现的更新机制；
2. 预测被遮蔽对象、变量、区域或未来窗口的 target embedding，而不是仅以普通下一状态回归冒用 JEPA 名称；
3. 潜在节点与本体对象或对象集合有稳定对应关系；
4. Link 对应权威渠系、供水、空间邻接或管理关系；
5. Action 通过明确对象、端口、时间和单位进入状态转移；
6. 外生天气与需水情景不与控制动作混写；
7. 输出能够解码为显式状态、约束违反概率和不确定性；
8. 多步 rollout 逐步写回状态；
9. 水量平衡、拓扑和工程能力形成硬门；
10. 与专业模型、直接监督模型、action-agnostic 模型和简单基线公平比较；
11. 本体约束和 JEPA 目标的贡献分别通过消融实验单独证明；
12. 规划收益通过独立 Planner 实验验证，不以 latent 或单步预测精度代替。

若模型没有上述 JEPA 机制，应称为“潜在动力学模型”或“学习型代理”，不应仅因使用地理 embedding 或预测潜在状态而命名为 Irrigation-JEPA。

### 5.3 OAG 服务的合理产品边界

OAG 不应成为另一个独立的 Agent 控制面。推荐形成统一的“问题—通道—证据—Proposal”合同：

```text
自然语言问题
  → 语义落地与权限识别
  → 本体/指标/结构化查询/GIS/RAG 通道路由
  → 确定性工具和模拟器调用
  → 候选 Proposal
  → 证据与风险检查
  → 人工审查
```

LLM 负责意图解释、工具计划和结果表达；确定性服务负责授权、查询、计算、约束验证和执行。

## 6. 科研成立条件与验证设计

### 6.1 数据成立条件

首期至少需要：

- 权威渠系拓扑、断面、闸泵和工程能力数据；
- 带时间戳、单位、质量标记和校准记录的水位、流量、闸位及泵站遥测；
- 调度计划、下发指令、人工修改、设备执行和实际过流的分离日志；
- 田块边界、作物类型、播期、生育期和土壤属性；
- 气象观测、历史预报版本和蒸散发资料；
- 土壤水分、灌溉事件、田间入水量和作物结果；
- 水权、配额、轮灌规则、渠道容量和安全边界；
- 设备故障、缺测、异常工况和专家驳回记录。

如果缺少真实灌溉动作和执行结果日志，系统最多能够声明“专业模型支持的条件情景推演”，不能声明已经从数据中学到真实灌溉干预的反事实效果。

### 6.2 必需基线

ODIWM 不能只与慢速高精度模拟器比较。至少需要以下基线：

| 能力 | 最低基线 |
|---|---|
| 状态预测 | persistence、季节平均、ARX/状态空间模型 |
| 渠系动力学 | 经验证的圣维南或简化渠系水动力模型 |
| 土壤水分 | 水量平衡桶模型、Richards 方程或成熟田间模型 |
| 作物耗水 | FAO-56 ET0/Kc、区域作物模型 |
| 调度规划 | 现行规则、网络流/MILP、MPC 或专业优化模型 |
| 潜在模型 | 无本体约束的同容量模型 |
| 学习型代理 | 直接监督模型、状态空间/降阶模型、图时空模型、神经算子及适用的 JEPA 变体 |
| 图结构贡献 | 无 Link、错误 Link、静态 Link 等消融 |
| 物理贡献 | 无物理约束、软约束、硬约束和专业模型路由对比 |

### 6.3 建议验证阶梯

1. **Gate 0：问题、语义和权限冻结。**冻结对象、状态、动作、外生强迫、结果、权限、基线和评价口径。
2. **Gate 1：本体、映射和实例图验证。**通过能力问题、SHACL、拓扑、单位、时态和来源校验。
3. **Gate 2：数据与时间可用性验证。**验证传感器质量、历史预报 vintage、issue-time 截断、指令—执行对账和数据切分。
4. **Gate 3：专业模型与物理账验证。**验证模型适用性、参数来源、数值稳定性和渠系—田间水量闭合。
5. **Gate 4：状态估计验证。**在传感器留出和缺测条件下验证 belief state 与不确定性校准。
6. **Gate 5：动作条件预测验证。**使用冻结的时间、事件和空间留出比较强基线，证明 Action 输入确实改善动作响应预测；同时完成本体、Link、物理和 forcing 消融。
7. **Gate 6：快速代理验证。**仅对已触发的代理研究，验证同任务精度、守恒、稳定性、适用性和端到端速度；没有合适代理时允许保留专业模型路线。
8. **Gate 7：动作效果与因果证据。**区分专业模型条件情景、历史关联、准实验、受控试验和前瞻干预，按证据限制因果表述。
9. **Gate 8：Planner 验证。**比较多种规划器的可行率、regret、稳健性和运行成本，并使用独立评估器防止利用模型漏洞。
10. **Gate 9：跨灌区迁移验证。**冻结源灌区模型，记录目标灌区零样本、少样本和完全校准表现。
11. **Gate 10：前瞻影子与受控试点。**先使用实时可得输入完成不影响生产的影子运行；只有联合评审通过后，才在明确权限、回退方案和人工审批条件下讨论有限受控使用。

Gate 0 至 Gate 4 是共享基础。Gate 6 只在学习型代理被触发时适用；Gate 7 的动作效果证据与 Gate 8 的离线规划增量是两个不同维度。未通过 Gate 7 时仍可比较“给定模型条件下”的候选规划，但不能把 Gate 8 的结果表述为现实因果收益，也不能据此进入自动控制。

### 6.4 核心评价指标

不应只评价平均预测误差或推理速度。建议至少覆盖：

- 水量平衡误差和质量守恒违反率；
- 水位、流量、土壤水分、蒸散和胁迫的多时距误差；
- 多步 rollout 漂移；
- 概率校准、区间覆盖率和极端事件尾部风险；
- 动作响应方向、幅度和时延误差；
- 硬约束 false allow / false block；
- Proposal 可行率与约束违反概率；
- planner decision regret；
- 相对现行规则和专业优化模型的增量收益；
- 跨年份、跨作物、跨渠系和跨灌区迁移退化；
- 本体 grounding 正确率和工具路由正确率；
- 专家采纳率、驳回原因和人工修订幅度；
- 完整查询、推演和规划链路的 p50/p95 延迟与资源成本。

## 7. 现有基础与真实缺口

### 7.1 可复用基础

既有平台和研究当前可复用的能力包括：

- Geospatial Kernel 的 GIS 拓扑编译、守恒计算、状态估计、预测闭包和验证门；
- GWM 的 state、observation、action、forcing、transition、evidence 和 claim 合同，但不包括现成 JEPA 模型；
- WWM 的水利状态、动作边界、模型路由、多步推演和分级验证思想；
- AWM-CropWater 的灌区—田块作物水分管理问题定义；
- PostgreSQL 权威本体、不可变发布包和 RDF 读投影架构；
- OWL、SKOS、SHACL、稳定 URI、来源映射和能力问题验证；
- 本体草稿、版本基线、append-only 变更、Diff 和审批边界；
- 类型化本体查询、受控结构化查询、GIS 工具与证据组织能力；
- HITL、策略决定、幂等、Outbox、审计和专项执行器基础。

### 7.2 不能视为已有的能力

以下内容仍是 ODIWM 的核心研究与工程缺口：

- 经灌区领域专家审定的专业本体；
- 三个目标灌区的权威实例图和跨灌区语义映射；
- 渠系、闸泵、田块、土壤与作物的多尺度统一状态合同；
- 任一灌区学习型代理的训练数据、实现和独立验证；
- 若采用 JEPA，其 context/target encoder、训练目标、模型权重和增量证据；
- 圣维南、土壤水分和作物模型的稳定耦合；
- 真实动作、执行回执与结果的时间对齐；
- 反事实识别与动作效果校准证据；
- 面向连续多目标调度的生产级 Proposal Planner；
- 跨灌区 Sim-to-Real 和前瞻影子运行证据；
- 灌区生产控制接口、回退和安全认证。

因此，现有平台基础可以降低语义治理和运行控制面的建设成本，但不能替代 ODIWM 最核心的专业数据、动力学和验证工作。

## 8. “十五五”预期指标评估

### 8.1 三个特大灌区完成概念验证

原指标：

> 在淠史杭、河套、都江堰三个特大灌区完成 ODIWM 概念验证。

评价：具有战略价值，但并行从零建设风险高。三个灌区在气候、地形、渠系结构、作物制度、地下水条件和运行管理机制上差异显著。

建议改为：

> **完成一个主试点的端到端验证，并在另外两个灌区开展冻结协议下的跨域迁移验证。至少一个灌区完成前瞻影子运行，另外两个完成零样本、少样本或有限校准比较。**

这样才能把“三个灌区”转化为迁移能力证据，而不是三个互不相干的演示项目。

### 8.2 推理速度从小时级到毫秒级、提升 1000 倍

评价：当前不可直接验收。机理模型一次完整模拟与世界模型单步前向计算不属于同一任务。必须冻结：

- 相同空间范围和分辨率；
- 相同预测时域和时间步；
- 相同输入、边界和输出变量；
- 相同精度与守恒门槛；
- 相同情景数量和硬件；
- 区分单次 rollout 与完整规划搜索。

建议拆分为：

1. 单次代理 rollout 相对指定专业模拟器的加速比；
2. 端到端生成固定数量可行 Proposal 的 p95 延迟；
3. 在达到精度、守恒和约束门槛时的 Pareto 前沿；
4. 不同空间规模和规划时域下的延迟扩展曲线。

“1000 倍”可以作为挑战目标，但不宜预先作为不带任务合同的刚性指标。“毫秒级”也只可能适用于有限规模的单次模型前向，而不应笼统用于完整反事实规划闭环。

### 8.3 至少支持十种反事实场景

评价：场景数量过于容易完成，不能代表反事实能力。十个自然语言模板可能对应同一种模型调用，也可能没有独立验证。

建议改为：

> **覆盖不少于十类经过语义冻结的干预场景，每类具有独立的 Action 定义、适用条件、专业基线、约束集和验证样本；总体报告动作响应误差、约束违反率、不确定性校准和规划 regret。**

候选场景可以包括水源削减、渠段故障、闸门动作、泵站停运、轮灌调整、作物需水变化、气象预报偏差、输水损失变化、供水公平约束和应急限水等。

### 8.4 发表 Nature / Science 子刊论文二至三篇

评价：可作为冲刺目标，不适合作为唯一刚性验收指标。论文发表受审稿周期和期刊判断影响，不能完全由项目执行控制。

建议形成三条相对独立的论文线：

1. 本体锚定的灌区动作条件世界模型方法论文；
2. 物理约束、长时 rollout 与跨灌区迁移论文；
3. 前瞻影子运行、规划价值和人机协同论文。

项目验收更适合考核冻结数据集、公开协议、可复现实验、跨灌区结果和前瞻验证；高水平综合或领域顶刊作为成果目标和加分项。

## 9. 建议的首期范围

首期不宜直接覆盖三个特大灌区的全部业务。建议选择一个可证伪的窄闭环：

- 一个主灌区中的一个代表性渠系或管理片区；
- 一种主要作物和一个完整生长季；
- 骨干渠—末级渠—田块入口的可核验拓扑；
- 小时级渠系状态与日级田间水分状态；
- 闸门开度、配水量和灌溉时机三类核心动作；
- 天气、需水和上游供水作为外生情景；
- 水量、作物胁迫、供水公平和能耗作为分离结果；
- 专业模型作为教师、基线和安全后端；
- 先比较透明统计、状态空间、降阶、图时空和其他快速代理，再按数据条件决定是否增加 JEPA；
- 连续滚动控制优先比较 MPC，组合调度优先比较 MILP/约束搜索，MCTS 仅在离散分层动作和可控 rollout 成本下进入比较；
- 只形成 Proposal，不直接闭环控制生产设备；
- 通过历史回放后进入前瞻影子运行。

## 10. 综合评级

| 维度 | 评分 | 判断 |
|---|---:|---|
| 研究方向价值 | 8/10 | 灌区是动作明确、网络效应强、可形成真实闭环的高价值场景 |
| 与既有研究体系契合度 | 8/10 | 状态合同、地理拓扑、本体治理和 Action Runtime 可衔接；JEPA 算法与权重不能直接继承 |
| 当前创新主张严谨度 | 5/10 | 将语义、物理、因果、规划和最优性混合表述 |
| 当前技术可行性 | 5/10 | 各组成技术存在，但跨尺度集成、数据和验证难度高 |
| 指标可验收性 | 3/10 | 1000 倍、毫秒级、十种场景和论文数量缺少验收合同 |
| 修改后立项建议 | 有条件推荐 | 需先冻结首期问题、数据、基线、验证阶梯和能力边界 |

## 11. 最终建议

建议将以下内容确立为工程和首期科研主线：

- 本体锚定的对象—关系动态状态；
- Geospatial Kernel 风格的权威拓扑、守恒账、状态估计和预测闭包；
- 经校准的专业机理模型及其动作条件、多步、带不确定性的情景推演；
- 规则、MILP/MPC 等约束规划与独立模型复核；
- OAG 支持的确定性工具编排；
- Proposal、人工审批、受治理 Action 和全链路审计；
- 跨灌区语义对齐和迁移验证。

建议将学习型快速代理作为通过数据和基线门后启动的加速支线，将 JEPA 作为该支线中的候选方法之一。即使 JEPA 试验失败，上述主线仍应能够形成可用的数字影子、专业模型情景工作台和候选方案比较能力。

建议删除或改写以下过度承诺：

- 本体约束自动带来因果性；
- PINN 是唯一或必然最优的物理融合方法；
- MCTS 必然秒级产生最优方案；
- Action Type 一一映射即可完成 Sim-to-Real；
- 完整世界模型规划普遍达到毫秒级和 1000 倍加速；
- OAG 或本体查询替代所有结构化查询和文档检索能力。

立项前应优先完成四项冻结工作：

1. **问题冻结：**明确首个灌区、渠系范围、作物、时间尺度、动作和结果。
2. **语义冻结：**形成最小灌区本体、实例图、Action/Forcing/Observation 分离合同。
3. **证据冻结：**盘点真实遥测、调度指令、执行回执、田间灌溉和作物结果数据。
4. **验证冻结：**预注册专业基线、数据切分、消融实验、速度口径和晋级门槛。

只有完成以上工作，ODIWM 才能从概念组合转化为一个可以被证伪、比较、复现和逐级进入真实灌区的科研系统。
