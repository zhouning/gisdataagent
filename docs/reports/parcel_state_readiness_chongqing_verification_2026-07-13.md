# 重庆用地与地块状态就绪度验证报告

## 对应需求

- 客户侧需求3：用地与地块状态。
- 技术路线：传统GIS负责要素物化、地类校验、面积统计、现状/规划叠加和冲突筛查；UWM消费经过版本验证的`t0`状态、动作和观测转移标签。

## 已实现

- 产品模式：`uwm.parcel_land_use_state_readiness.v1`。
- 产品包：`parcel-state-195b33acc1f9b06fec4a`。
- 3项源资产：
  - 璧山DLTB主状态源：审计101,657个要素；
  - 福禄村规划数据库辅助规划用途源：审计8,050个要素、28个图层；
  - 2019年璧山土地开发台账辅助审批状态源：审计1,438行。
- DLTB审计确认存在`BSM`、`DLBM`、`DLMC`、`TBMJ`等核心状态字段。
- 建立15类传统GIS/UWM状态通道和UWM地块状态输入契约。
- 独立服务、6个鉴权API和“用地与地块状态”独立页面。

## 证据边界

- 当前使用的是源数据审计元数据，源GDB要素行未物化到产品。
- 审计要素数量不是当前土地利用分布。
- DLTB标识码不是法律宗地产权。
- 地类类别不是开发许可或审批状态。
- 需求2的批准版本和有效期门尚未打开。

## 门控结果

- 15个状态通道全部`unavailable/null`，记录数保持为空。
- 物化状态节点：0。
- 观测转移标签：0。
- 地类域校验、面积统计、现状/规划叠加、法律状态、冲突筛查、UWM t0初始化、转移学习和未来推演全部关闭。

## 未生成内容

- 未生成各地类面积、数量或空间分布。
- 未生成规划用途冲突、审批状态或法律地块状态。
- 未生成地块状态节点、状态转移标签或未来土地利用情景。

## 验证结果

- 聚焦Python测试通过。
- 独立验证器通过，`fabricated_value_count=0`。
- 六件套bundle ID一致。
- 验证摘要：3项源资产、101,657个审计主状态要素、0个物化状态节点、0条观测转移、0个开放机制。

## 生产化前置条件

必须物化可追溯的DLTB要素行和几何，绑定需求2中的权威版本与有效期，完成地类代码域、面积单位、行政区、权属、规划用途和审批台账连接。至少需要两个经过一致性验证的观测时点，才能构建UWM转移标签和校准Kernel。
