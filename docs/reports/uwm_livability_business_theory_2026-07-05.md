# UWM 城市宜居性分析的业务理论基础与结果形态

日期：2026-07-05

## 1. 与耕地空间布局优化场景的对应关系

在 paper1、paper2、paper3、paper4、paper9 系列耕地空间布局优化研究中，业务理论基础可以概括为：

```text
耕地适宜性评价 + 耕地保护/整治目标 + 空间连片化
```

也就是说，深度强化学习不是为了单纯“移动图斑”，而是在耕地适宜性评价体系、地形约束、连片度目标和百亩方等业务目标支撑下，找出应该被调整的地块，使耕地平均坡度下降、连片度上升、集中连片优质耕地区域增加。

UWM 城市宜居性场景与之同构，但业务理论基础应从“耕地适宜性”切换为“城市宜居性/人居环境适宜性”：

```text
城市宜居性/人居环境适宜性
= 环境健康风险
+ 公共服务可达性
+ 空间公平
+ 城市形态/活动耦合
+ 规划可实施约束
```

因此，UWM 不应只回答“哪里宜居分数高”，而应回答：

```text
哪些城市空间单元处于低宜居性陷阱？
低宜居性由什么机制导致？
应该在哪些地方采取哪类干预？
干预后热风险、污染暴露、服务可达性、公平性是否真的改善？
这些结论证据强度到什么程度？
```

## 2. 业务理论基础

UWM 城市宜居性分析的核心理论基础包括五个方面。

第一是环境健康风险理论。城市空间中的高温热暴露、空气污染、交通暴露和极端天气压力，会直接影响居民健康风险。因此，宜居性不能只看建设强度或服务设施数量，还必须看居民是否暴露在高热、高污染、高风险环境中。

第二是公共服务可达性理论。城市宜居性不等于设施总量，而是不同居民能否在合理时间、距离和成本内到达教育、医疗、商业、公园、公共交通、慢行网络和就业活动机会。服务缺口大的区域即使环境条件较好，也可能是低宜居区域。

第三是空间公平与环境正义理论。UWM 必须回答“谁受益、谁受损”。如果规划干预只提高了全市平均宜居性，却没有改善低宜居区域、脆弱人群或高暴露群体的处境，那么这个优化结果的业务价值是不充分的。

第四是城市复杂系统理论。城市形态、道路交通、建筑密度、绿地水体、人口分布、活动强度、服务设施和环境暴露是耦合系统。一个干预动作可能产生空间溢出，例如增绿不仅影响本地热风险，也可能改善周边热环境和活动舒适度。

第五是规划可实施性约束。城市干预动作不是任意可选的。增绿、交通减排、公共服务补点、建筑降温改造和慢行网络优化，都要受空间条件、用地约束、预算约束、服务半径、规划管控和证据质量限制。

## 3. 与耕地优化指标的类比

两类场景可以这样对应：

```text
耕地平均坡度下降        -> 城市热风险/污染暴露下降
耕地连片度上升          -> 服务、绿地、慢行、公共设施的空间可达性改善
百亩方增加              -> 形成更连续、更均衡、更可服务的高宜居生活单元
识别应调整地块          -> 识别应治理的街道/网格/街区及其适合的干预动作
耕地适宜性评价体系      -> 城市宜居性评价与干预适宜性体系
```

这意味着，UWM 中的深度强化学习或 model-based planning 也不是为了单纯优化一个抽象分数，而是为了在城市宜居性理论约束下，找出最应该被治理的空间单元和最合适的治理动作。

## 4. UWM 当前适用的指标体系

结合当前 `gisdataagent` 项目中的 UWM 设计，城市宜居性状态可以用以下指标表达：

```text
heat_risk                 热暴露/热风险
air_pollution_exposure    空气污染暴露
service_accessibility     医疗、教育、商业、公园等服务可达性
equity                    脆弱人群、低宜居区域是否受益
livability                综合宜居性状态
```

这些指标不是为了做静态排名，而是为了构成城市世界模型中的状态变量。UWM 应把城市表达为：

```text
城市观测 O_t
-> 城市状态 z_t
-> 干预动作 a_t
-> 状态转移 z_t+1
-> 多目标结果 y_t+k
-> 证据门控价值判断 V
```

## 5. 可解释的城市干预动作

UWM 中的动作应对应真实城市治理或规划干预，而不是任意数学操作。当前最合理的动作集合包括：

```text
increase_green_infrastructure   增绿、树冠、蓝绿基础设施
traffic_emission_control        交通减排、低排放区
add_community_service           公共服务补点
cool_roof / retrofit            冷屋顶、建筑降温改造
```

每个动作都应具有明确业务含义和预期影响。例如，增绿主要用于降低热风险和部分污染暴露；交通减排主要用于降低空气污染暴露；公共服务补点主要用于改善服务可达性和公平性；建筑降温改造主要用于降低高温风险。

## 6. 最终结果应该是什么

UWM 的最终结果不应该只是一个“城市宜居性排名图”。更合理的结果应该是一个证据门控的城市干预方案包，包括以下内容。

### 6.1 当前低宜居区域识别

识别哪些街道、网格或街区处于低宜居状态，并说明其问题来源：

```text
热风险高
污染暴露高
公共服务不足
脆弱人口集中
交通或活动压力高
多因素耦合形成低宜居陷阱
```

### 6.2 机制解释

每个低宜居区域都应能解释其主要机制。例如：

```text
该区域低宜居主要由热暴露和绿地不足导致；
该区域主要由空气污染暴露和道路活动压力导致；
该区域主要由公共服务可达性不足导致；
该区域平均宜居性不低，但脆弱人群暴露较高，存在公平性问题。
```

### 6.3 干预适宜性图

输出哪些地方适合采取哪类干预：

```text
适合增绿的单元
适合交通减排的单元
适合公共服务补点的单元
适合建筑降温改造的单元
不建议干预或证据不足的单元
```

### 6.4 多步优化方案

输出推荐的 action sequence，而不是只给单步建议。例如：

```text
第 1 步：在高热风险且脆弱人口集中的街道增加绿地基础设施；
第 2 步：在服务缺口明显的相邻街道补充社区公共服务；
第 3 步：在污染暴露高的道路走廊实施交通减排。
```

### 6.5 前后对比指标

优化结果应能证明干预后关键指标朝业务目标方向改善：

```text
heat_risk_delta < 0
air_pollution_exposure_delta < 0
service_accessibility_delta > 0
equity_delta > 0
livability_delta > 0
```

这与耕地优化中的“坡度下降、连片度上升、百亩方增加”是同一类证据逻辑。

### 6.6 公平性结论

结果必须说明改善是否真正流向低宜居区域、弱势群体或高暴露群体。如果只是平均宜居性提高，而低宜居区域没有改善，或者脆弱人群收益很低，那么这个方案不能被视为高质量优化结果。

### 6.7 证据边界

最终报告还必须标注证据等级：

```text
哪些结论有真实观测支持；
哪些结论来自 public proxy；
哪些结论来自 simulator replay；
哪些结论只是 exploratory 情景；
哪些结论因为数据不足不能用于政策主张。
```

## 7. 一句话结论

UWM 的业务价值不是“算出哪里宜居”，而是：

```text
在城市宜居性理论约束下，找到最应该被治理的空间单元和最适合的治理动作，
并证明这些动作会让热风险下降、污染暴露下降、服务可达性上升、公平性上升，
同时给出不确定性和证据等级。
```

当前 `gisdataagent` 中的 UWM v0 已经具备 action-conditioned rollout、evidence-gated planner 和 learned rollout planner 的雏形，可以支撑 simulator replay 和 proxy 场景下的动态规划优势分析。但仍应保持边界：当前还不能宣称 UWM 已经在真实政策 outcome 上证明优于传统方法。
