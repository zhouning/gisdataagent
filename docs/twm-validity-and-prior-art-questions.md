# TWM 可用性证明与国际已有工作答辩口径

日期：2026-06-21

## 一句话回答

用户问“怎么证明 TWM 的结果可用、准确、可靠”，不能只回答“模型先进”。应回答：TWM 的可信度来自一整套证据链，包括数据基础审计、历史回放、空间和时间 holdout、约束误判率、规划 regret、因果校准、输入泄漏审计和人工复核闭环。

用户问“世界上以前有没有类似工作”，答案是：有大量相邻工作，但很少有系统同时覆盖自然资源业务中的空间对象语义、规则证据、行动条件预测、因果校准、可行性约束和规划器闭环。FLUS/PLUS 更接近土地利用模拟器，UrbanSim 更接近城市规划仿真平台，AlphaEarth/Prithvi 更接近地理基础模型；TWM 的定位是把这些能力放进自然资源业务决策闭环。

## 1. 如何证明 TWM 输出结果可用、准确、可靠

### 面向普通用户的回答

TWM 的结果不能靠“模型说得像”来证明，而要靠“用过去验证未来”来证明。

一个可靠的 TWM 至少要回答四件事：

1. 输入数据是否足够真实、完整。
2. 用过去某一时点的数据预测下一期真实结果，预测是否准确。
3. 对禁止或高风险行为，模型有没有错误放行。
4. 模型推荐的规划方案，是否比人工基线、规则基线或传统模型更稳、更合规。

因此，TWM 对外不应承诺“所有结果天然准确”。更准确的说法是：

> TWM 的每个输出都必须带证据等级。通过历史回测和生产数据验证的结果，可以进入辅助决策；只通过合成测试或演示数据的结果，只能用于研发验证和方案推演，不能直接作为审批或法定规划依据。

### 面向技术和研究人员的证明框架

TWM 的可信度应分层证明：

| 层级 | 证明对象 | 关键方法 | 通过后能说明什么 |
|---|---|---|---|
| 数据基础 | 输入是否可用 | 表结构审计、空间关系审计、生产标记审计、缺失字段检查 | 数据是否具备建模资格 |
| 渲染器 | GIS 状态是否被正确表达 | 对象、关系、规则、证据、审查任务一致性检查 | TWM 是否正确理解业务世界 |
| 模拟器 | 行动后果预测是否可信 | 历史回放、train/validation/test、空间 holdout、时间 holdout | 模型是否能预测状态变化和风险 |
| 行动可行性 | 是否错误放行高风险行为 | action mask confusion matrix，重点看 false_allow | 模型是否满足安全约束 |
| 规划器 | 推荐方案是否更好 | 与 FLUS/PLUS/规则基线/人工方案比较，计算 regret、风险和效用 | 推荐是否有实际改进 |
| 因果校准 | 行动效果是否只是相关性 | 匹配、IPW、AIPW、空间干扰诊断、block bootstrap | 效果估计是否具备因果解释基础 |
| 生产监控 | 上线后是否稳定 | 漂移检测、置信度、人工复核、异常报警 | 是否可持续运行 |

### 当前项目内已有证据

当前 TWM 已经具备工程级验证和合成压力测试基础：

- `docs/reports/twm_data_foundation_health.md` 显示，本地 TWM fixture 包含审批、审查、规则、状态快照等基础数据。
- synthetic experiment foundation 有 256 行、多区域、多时期、128 个 treated/control counterfactual pair。
- synthetic action mask 有 64 个 allowed 和 64 个 blocked 样本。
- v11 strict stress report 中，raw `torch_spatiotemporal_transformer` 的 action mask、conditional high-risk、unseen `region_policy` 和 unseen `region_action_policy` 均达到 `false_allow=0`、`false_block=0`。
- backend input leakage audit 通过，说明当前严格测试没有把目标标签、未来输出、执行 mask 等目标派生字段喂给模型。
- Paper7 caliper-matched branch 当前有 2445 个 matched pair，作为外部经验校准支路通过。

但也必须明确边界：

- 当前生产可用 observed history 行数为 0。
- synthetic 和 structural fixture 均标记为 synthetic / not-for-production。
- 因此当前证据能支持“工程可行、合成压力测试通过、具备严格验证框架”，但还不能支持“生产级准确率已被证明”。

推荐对外表述：

> TWM 当前已经完成工程级和合成压力验证，证明这条技术路线可行；生产级准确性需要接入真实历史审批、监管、变化检测和规划执行结果，做严格历史回放后才能给出。

## 2. 世界上以前有没有类似工作

### 结论

有相邻工作，而且不少已经取得成果；但它们通常只覆盖 TWM 的一部分能力。

TWM 不应宣传成“世界上从未有人做过土地模拟”。更准确的说法是：

> TWM 站在已有土地利用模拟、城市仿真、地理基础模型和规划优化系统之上，目标是把自然资源业务中的空间对象、规则证据、行动预测、因果校准和规划决策统一到一个可验证的世界模型闭环中。

### 典型已有工作

| 类别 | 代表工作 | 已有成效 | 与 TWM 的关系 |
|---|---|---|---|
| 土地利用模拟 | FLUS / GeoSOS | FLUS 通过系统动力学 + CA 模拟多类土地利用变化，论文报告其在中国 2000-2010 回放中优于 CLUE-S 和传统 CA | 最接近 TWM 的“土地变化模拟器”部分 |
| 土地斑块模拟 | PLUS | PLUS 结合 LEAS 和 CARS，用于土地扩张驱动分析和斑块级模拟，项目说明其在模拟精度和景观格局相似性上有优势 | 可作为 TWM 模拟器基线 |
| 城市规划仿真 | UrbanSim | 官方称 UrbanSim 已在多洲城市和区域规划中使用，支持土地利用、交通、经济、环境综合仿真 | 证明“规划仿真辅助决策”是成熟方向 |
| 城市增长 CA | SLEUTH | 经典城市增长 CA 模型，用历史城市扩张校准并预测未来增长 | 可作为传统空间增长模型参照 |
| 地理基础模型 | AlphaEarth Foundations | 生成通用地理 embedding，在多类地理制图任务中表现强 | 可作为 TWM 的感知/表征增强，不等同于规划世界模型 |
| 遥感基础模型 | Prithvi-EO | 面向遥感任务迁移，论文报告在 GEO-Bench 上优于多个地理基础模型 | 可增强遥感特征，但不直接解决行动决策闭环 |

### TWM 与这些工作的本质区别

FLUS/PLUS 主要回答：

> 未来土地利用格局可能怎么变？

TWM 要回答：

> 在给定自然资源规则、证据、审批约束和规划目标下，如果采取某个行动，空间对象状态、风险、效用和后续可行方案会怎么变化？

也就是说，TWM 不只是土地利用格局预测，而是“行动条件世界模型”：

- 输入不是单纯栅格驱动因子，还包括对象、关系、规则、证据、审查任务和行动上下文。
- 输出不只是未来 land-use map，还包括状态变化、约束风险、规划效用、可行性 mask、置信度和反事实比较。
- 验证不只看像不像真实地图，还要看 false_allow、planner regret、因果校准、空间干扰和生产证据门槛。
- 规划器不是后处理，而是世界模型的消费者，需要受行动可行性和证据等级约束。

## 对外建议话术

### 简短版

TWM 不是靠模型自信证明结果可靠，而是靠历史回放和证据门槛证明。世界上已有 FLUS、PLUS、UrbanSim、SLEUTH、AlphaEarth、Prithvi 等相邻工作，它们分别证明了土地模拟、城市仿真和地理基础模型的有效性。TWM 的创新点不是简单发明一个新的 CA 模型，而是把自然资源业务中的空间对象、规则证据、行动预测、可行性约束、因果校准和规划优化放进一个统一的可验证闭环。

### 严谨版

当前 TWM 已完成工程级验证和合成压力测试，能够证明体系结构、训练管线、约束安全检查和规划消费链路可行；但生产级准确率必须基于真实历史业务数据进行时间外推、区域外推、行动外推和规划 regret 验证。没有通过生产 observed history gate 前，TWM 输出应定位为研发验证、方案推演和辅助研判，不应直接升级为法定审批依据。

## 下一步验证建议

1. 建立真实历史 observed history：审批记录、审查任务、规则命中、空间变化、规划实施结果。
2. 设定严格时间切分：用早期数据训练，预测后期真实结果。
3. 设定严格区域切分：留出某些区县/片区作为 unseen region holdout。
4. 与 FLUS/PLUS/规则基线/人工方案对比。
5. 对 action mask 单独设置红线指标：生产环境中 false_allow 必须接近 0，并由人工复核兜底。
6. 对规划输出设置 regret、约束违规率、耕地保护、生态保护和建设适宜性等业务指标。
7. 所有输出带 claim level：合成验证、历史回放验证、生产监控验证必须分级展示。
