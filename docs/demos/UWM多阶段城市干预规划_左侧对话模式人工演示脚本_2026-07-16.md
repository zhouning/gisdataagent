# UWM多阶段城市干预规划：左侧对话模式人工演示脚本

日期：2026年7月16日

## 一、演示目标

验证用户能够在左侧对话框中先查看输入UWM的当前城市状态和地图，然后明确确认是否训练Simulator并正式执行多阶段未来推演。系统不得在用户确认前提前形成规划结论。

## 二、启动与登录

1. 在项目目录运行`docker compose up -d app db minio`。
2. 浏览器打开`http://127.0.0.1:8000`。
3. 使用`admin / admin123`登录。

## 三、从@菜单调用UWM规划

1. 在左侧对话输入框键入`@`。
2. 在候选菜单中找到并点击`@UWM规划`。候选说明应为“先展示当前城市状态，再确认执行UWM多阶段城市干预规划”。
3. 输入框应自动出现`@UWM规划 `，无需手工记忆或输入能力名称。
4. 在其后补充指令并发送：

```text
@UWM规划 请先展示沙坪坝区土湾街道及1阶邻域的当前输入状态，再对增绿降温、交通减排和公共服务三类动作进行2步多阶段城市干预规划，采用均衡的不确定性偏好
```

也可以在`@`后继续输入`UWM`、`多阶段`或`城市干预`筛选该候选。

系统应路由到：

- 意图：`WORLD_MODEL`；
- 管线：`UWM多阶段城市干预规划`；
- 第一阶段：`uwm_multistage_state_inspection`。

发送后系统应先真实调用本机`gemma4-26b-ollama`，显示`Gemma4场景语义解析`，并明确列出：

- 规划区域：沙坪坝区·土湾街道；
- 邻域范围：1阶空间邻域；
- 规划时域：2步；
- 允许动作：增绿降温、交通减排、公共服务；
- 不确定性偏好：balanced；
- Gemma4解析耗时。

必须说明：Gemma4只负责自然语言场景解析，不负责生成数值变化和规划结论。

## 四、检查推演前状态体检

系统首先显示`UWM推演前状态体检`，此时不得显示规划结论。

预期数据：

- 场景：沙坪坝区·土湾—石井坡复合压力场景；
- 当前规划域：6个空间单元；
- 全域底座：1,017个状态节点、7,932条空间关系；
- 本场景候选动作：9个；
- 社区公共服务候选：5个；
- 增绿降温候选：2个；
- 交通减排候选：2个。

状态体检逐一显示6个单元的热风险、污染暴露、服务可达性、公平性、宜居性和候选动作数量。

中间地图应加载6个状态单元，地图标题为`UWM推演前：当前城市状态与候选动作`。

必须向客户指出：

> 当前只读取并展示状态快照，尚未训练Simulator、尚未执行未来推演、尚未形成规划结论。

## 五、理解UWM将执行的能力

确认前，对话应明确说明：

- Simulator：23维输入预测6维下一状态变化，共138个系数；
- Kernel：把目标单元变化传播到真实空间邻域；
- Planner：生成`t1`并写回世界，再选择第二步；
- 对照：同时比较传统静态排序、单步模型和多步但不写回状态的结果。

## 六、正式确认推演

用户可以选择：

- `确认2步推演`；
- `改为3步推演`；
- `暂不推演`。

本次演示点击`确认2步推演`。

系统进度应显示：

```text
训练Simulator → 构建空间Kernel → 想象未来 → 写回状态 → 重新规划
```

## 七、检查正式推演结果

预期结果：

1. 石井坡街道增加绿色/降温基础设施；
2. 石井坡街道新增或改善社区公共服务。

能力证据：

- 规划时域：2步；
- 候选动作：9个；
- 主搜索想象动作：73次；
- 完整未来序列：64条；
- 保留较优路径：8条；
- 第二步首选因状态写回发生切换：是；
- 发生名次变化的后续动作：2个。

页面同时显示5,844/973条训练/留出记录、23维输入、6维输出、138个系数和运行ID。

## 八、检查地图联动

运行完成后默认将第二步未来分叉发送到地图。

依次点击：

1. `查看当前世界`；
2. `查看第一步传播`；
3. `查看第二步分叉`；
4. `查看最终轨迹`。

每次点击都应在中间地图生成对应的新地图消息。

第二步分叉中：

- 橙色虚线表示不更新世界状态时的旧选择；
- 紫色表示UWM写回`t1`后重新规划的新选择。

## 九、检查运行审计

点击`查看运行审计`，应显示：

- 运行ID；
- 训练和留出数量；
- Simulator训练耗时；
- Kernel构建耗时；
- 想象动作数量；
- 请求摘要；
- 状态写回验证；
- 训练数据主要为Simulator回放而非真实政策项目的证据边界。

## 十、取消路径

重新发起命令并点击`暂不推演`。

系统应停留在状态体检阶段，并明确说明：

> 未训练Simulator，也未执行未来推演。

## 十一、客户表述边界

可以表述：系统先展示UWM输入世界，再经用户确认执行动作条件预测、空间传播、状态写回和多阶段重规划。

不能表述：当前结果证明现实政策因果效果，或者能够直接替代正式规划、投资和行政审批。
