# 自然资源本体应用客户演示讲稿

- 文档版本：V1.2

- 修订日期：2026-08-05

- 本次修订：按新版系统界面重构演示主线，突出“原始字段—本体解释—业务结果”，补充平台名称动态配置

- 演示应用：GIS Data Agent

- 本体版本：自然资源“一张图”本体 V2.0.1

- 演示数据：规划院提供数据样例及 Demo 系统功能演示建议

- 场景范围：重庆市璧山区福禄镇和平村、斑竹村

- 结论边界：辅助预审，不替代法定审批或行政决定

## 一、演示目标

这次演示不以“展示一张复杂的本体图谱”为目标，而是回答客户最关心的三个问题：

1\. 基础地理数据经过本体增强后，为什么比原来的时空数据底座更好用？

2\. 本体在一次具体业务分析中到底做了什么，而不是停留在概念层面？

3\. 这套能力怎样进一步支撑自然资源其他业务部门、跨行业部门和智能体应用？

全程围绕一句业务问题展开：

> *一个规划地块从什么状态变成什么状态，属于什么业务过程，受什么空间规则约束，还缺少什么审批证据，为什么得到这个处置建议？*

建议始终采用同一条讲解主线：

> *原始字段 → 本体解释 → 空间和规则检查 → 业务结论 → 版本化证据*

## 二、开场表述

建议用以下表述开场：

> *传统时空数据底座解决了数据汇聚、地图展示和空间查询问题，但数据的业务含义仍然分散在字段说明、标准文档、业务规则和人员经验中。本体是在数据之上建立统一、可计算、可追溯的业务语义层，让系统不仅知道“哪里有一个图斑”，还知道“它是什么、处于什么状态、发生了什么过程、受什么规则约束、依据在哪里”。*

需要明确：本体不是把数据库表名、菜单名或“智能问数”等系统功能变成类。本体模型中的核心对象是土地、地块、耕地、建设用地等领域实体，以及状态、业务过程、约束、证据和它们之间的关系。

## 三、本体在演示中发挥的作用

### 1. 同一条地块记录的前后对比

以一条“规划前为旱地、规划后为村居住用地”的图斑为例，原始数据提供：

| **原始字段** | **字段值** | **传统系统能够直接知道的内容** |
|--------------|------------|--------------------------------|
| BSM          | 图斑标识   | 这是一条记录                   |
| JQDLMC       | 旱地       | 规划前字段的值                 |
| GHDLMC       | 村居住用地 | 规划后字段的值                 |

传统方式能够判断两个字段值不同，但无法仅凭字段自动回答“这是什么业务过程、需要检查哪些规则、还缺少什么依据”。

本体方式将同一条记录解释为：

> *地块实体 \`LandParcel\` → 耕地利用状态 → 建设占用
> \`ConstructionOccupation\` → 建设用地利用状态*

并继续连接两类业务关系：

- constrainedBy：这个转换受生态红线、历史文化保护、地质灾害、林地等空间约束；

- authorizedBy：建设占用需要关联审批文件等授权证据。

因此，系统不再只显示“旱地变成村居住用地”，而是能够给出“建设占用、空间冲突、材料待补或条件复核”等业务解释，并说明为什么。

### 2. 客户需要记住的对比

| **传统方式** | **本体方式** |
|----|----|
| 发现两个字段值不同 | 识别为土地利用状态变化和具体业务过程 |
| 得到图层相交面积 | 解释该相交为什么构成某类业务约束 |
| 发现材料字段为空 | 识别为 authorizedBy 审批证据缺口 |
| 输出一个结果数字 | 输出可追溯到对象、规则、来源和版本的证据链 |
| 业务逻辑依赖单个系统和人员经验 | 形成可供智能体和跨部门应用复用的稳定语义接口 |

### 3. 各技术组件的职责边界

| **组件** | **职责** |
|----|----|
| 自然资源本体 V2.0.1 | 定义实体、状态、过程、关系、规则、证据语义及稳定 URI |
| MMFE | 将来源字段、代码和部门术语对齐到本体目标语义，保留冲突和未决映射 |
| GIS 引擎 | 在正确坐标系中执行几何修复、空间叠加和面积计算 |
| SHACL | 校验状态转换、来源、法律依据和审批证据的完整性 |
| Agent | 理解业务问题、规划任务、调用能力并组织证据化解释 |

演示中应使用准确表述：本体定义“数据表示什么以及应该检查什么”；GIS
引擎计算“在哪里、相交多少”；智能体组织“怎样回答和解释”。

## 四、演示前准备

### 1. 环境检查

- 使用桌面浏览器，建议分辨率不低于 1440×900；

- 确认“智能分析”分组下可以看到“本体模型”和“本体应用”；

- 确认本体应用显示 Ontology V2.0.1 和“辅助预审”；

- 确认和平村变化地块已经显示在中间地图；

- 提前执行一次场景，确认业务结论、证据链、数据治理和总体架构均可打开；

- 演示前恢复到“用地转换辅助预审”的未执行状态。

### 2. 页面导航

完整入口：

> *智能分析 → 本体应用*

本体应用内部有四个页签：

- 业务结论：展示原始数据、本体解释、业务结果和代表性地块；

- 证据链：展示实体、状态、过程、规则命中、证据缺口和字段映射；

- 数据治理：展示质量检查、项目关联待办和来源资产；

- 总体架构：展示数据层、语义层、智能体层和应用层的关系。

“执行与依据”位于工作区底部，用于展开查看执行统计和语义分析执行链。它是过程详情，不是演示首屏主线。

## 五、30 分钟演示流程

### 0-4 分钟：为什么需要本体

操作：进入“智能分析 → 本体应用”，停留在“业务结论”。

新版首屏已经展示三段式过程：

1\. 原始数据：BSM + JQDLMC + GHDLMC；

2\. 本体解释：地块实体、源状态、转换过程、目标状态；

3\. 业务结果：执行后形成可解释的处置建议。

讲解要点：

- 传统底座能够看到“旱地”和“村居住用地”两个字段值不同；

- 本体把它解释成“地块由耕地利用状态经过建设占用变为建设用地利用状态”；

- 本体进一步规定该过程需要检查空间约束和审批证据；

- 这就是从“字段和值”提升为“对象、过程、规则和依据”。

建议话术：

> *这三个区域是整个演示最重要的内容。左边是数据库实际给我们的字段，中间是本体给出的业务解释，右边才是系统给业务人员的处置建议。本体发挥作用的位置就是中间这一层，没有它，空间结果和业务规则仍然是分散的。*

### 4-13 分钟：和平村用地转换辅助预审

操作：选择“用地转换辅助预审”，点击“执行语义分析”。

讲解结果：

- 902 个规划地块中，445 个地类发生变化，变化面积 79.73 公顷；

- 识别出农业结构调整、建设占用、土地复垦、土地整治和一般土地利用转换；

- 25 个变化地块命中禁止性或保护性空间约束；

- 108 个地块涉及建设占用但未关联审批文件；

- 312 个地块命中地灾或高郁闭度林地等条件约束。

重点解释右侧“业务结果”：

- “空间冲突”来自 constrainedBy 关系所指向的保护性空间约束及真实 GIS
  相交结果；

- “材料待补”来自建设占用的 authorizedBy 证据要求，不是大模型主观判断；

- “条件复核”表示需要联动地灾、林业等部门，不等同于不合规；

- 即使没有命中空间冲突，只要审批证据缺失，也不能显示为“合规”。

操作：点击三段式区域中的“查看为什么”，或点击代表性地块右侧的证据按钮。

### 13-18 分钟：查看证据链

进入“证据链”后，按从上到下顺序讲解：

1\. 地块实体：当前判断对应哪个具体空间对象；

2\. 源状态：规划前地类如何映射到本体状态；

3\. 转换过程：为什么识别为建设占用等业务过程；

4\. 目标状态：规划后地类如何映射到本体状态；

5\. 规则命中：约束类型、名称和真实相交面积；

6\. 证据缺口：是否存在 authorizedBy → ApprovalDocument 缺失；

7\. 字段映射：MMFE 如何将来源字段对齐到本体目标语义；

8\. 版本证据：本体版本、演示包版本和源资产 SHA-256。

建议话术：

> *业务人员看到的是处置建议，审查人员可以继续追到状态、过程、规则和来源。这个结论不是一个不可解释的模型答案，而是一条可以复核的语义证据链。*

### 18-22 分钟：斑竹村土地利用结构调整

操作：切换“土地利用结构调整”，点击“执行语义分析”。

讲解要点：

- 1,555 个规划地块中，559 个发生变化，变化面积 87.24 公顷；

- 农用地从 625.63 公顷增至 634.69 公顷，净增 9.06 公顷；

- 旱地增加 16.21 公顷，园地增加 1.73 公顷；

- 林地减少 3.31 公顷，坑塘水面减少 4.20 公顷；

- 宅基地（村居住用地）减少 12.20 公顷。

强调新版页面中的对比：传统方式只有结构表中的汇总数字；本体方式通过共享的土地利用状态语义，把统计变化与
559 个具体变化地块及其转换过程建立一致解释。

### 22-25 分钟：数据治理

操作：点击“数据治理”。

讲解要点：

- 系统检查
  CRS、几何、地块标识、规划前后状态、语义映射、项目关联和审批证据；

- 21 类地类术语已经映射，水库水面、河流水面、特殊用地 3
  类进入治理待办，没有静默猜测；

- 和平村项目台账有 16 项，但 TDGHDL.XMMC 为空，因此系统显示 0/16
  空间关联，而不是伪造项目位置；

- 质量警告进入治理任务，不能被智能体隐藏。

### 25-28 分钟：总体架构和跨部门扩展

操作：点击“总体架构”。

按自下而上讲解：

| **层次** | **定位** |
|----|----|
| 数据层 | 承载基础地理、规划地类、管控边界、项目台账和跨部门数据，保留来源结构与版本 |
| 语义层 | 以本体为内核，定义实体、状态、过程、约束、证据和跨源映射；MMFE执行语义融合 |
| 智能体层 | 围绕稳定领域概念理解问题、规划任务、调用 GIS 和数据工具、解释证据 |
| 应用层 | 支撑规划审查、结构调整、自然资源业务协同和跨行业场景 |

跨部门扩展时，不要求其他部门废弃自己的编码或表结构。农业、林业、生态环境、应急管理等部门可以把本部门术语映射到共享概念，由
MMFE 处理映射和冲突，从而保留各自业务体系，又形成可协同的共同语言。

### 28-30 分钟：总结

建议收束表述：

> *本体建设的价值不是增加一个图谱页面，而是让基础地理数据从“可看、可查”升级为“可理解、可计算、可解释、可协同”的时空数据底座。它让智能体获得稳定的领域知识结构，让跨部门数据获得可对齐的语义目标，也让每个分析结论能够回到对象、规则、数据和版本证据。*

## 六、本体模型页面的辅助演示

如客户希望查看模型本身，再进入“智能分析 →
本体模型”。建议只展示与业务主线有关的内容：

- 搜索“土地”或 Land，说明土地、农用地、建设用地、未利用地的分类关系；

- 搜索“建设占用”，说明它是过程类，不是土地的静态分类；

- 查看耕地利用状态、建设用地利用状态与转换过程之间的关系；

- 查看字段映射和 SHACL 校验；

- 导出 Turtle、SHACL 或 JSON-LD，在 Protégé 中继续查看和治理。

不要在客户尚未理解业务价值前直接展示全域大图。图谱是模型治理工具，业务应用页才是价值证明。

## 七、平台名称配置

系统默认名称为 Geospatial Data
Agent。管理员可动态修改为“宁夏时空数据智能平台”等客户化名称。

操作路径：

> *顶部“管理” → 管理后台 → 系统配置*

配置项：

- 平台名称：2-80 个字符；

- 平台副标题：0-120 个字符；

- 页面提供即时预览；

- 保存后立即同步到登录页、顶部栏和浏览器标题，无需重新登录；

- 更新动作写入审计日志；

- 修改只影响用户界面品牌，不改变 API 路径、数据库对象或部署标识。

生产部署前必须执行 131_platform_branding_settings.sql
数据库迁移。数据库不可用时，公开页面回退到默认名称；管理员保存会明确报错，不会产生虚假的保存成功状态。

## 八、演示口径边界

- 统一使用“辅助预审”“空间初筛”“条件复核”，不表述“系统已经完成法定合规审查”；

- 不宣称重点项目已经定位到具体图斑，当前源数据缺少可靠项目空间关联；

- 不把本体描述成空间计算引擎，空间叠加和面积由 GIS 引擎完成；

- 不把 MMFE 描述成本体，MMFE 是依据本体执行语义融合的引擎；

- 不把本体描述成一张展示图，它是业务语义、关系、规则和证据合同；

- 不表述“每次点击都在线执行完整 OWL 推理”。当前演示结果在构建阶段按
  V2.0.1 本体语义和规则确定性编译，运行时校验本体版本与数据哈希后读取；

- 不把“未命中已注册约束”等同于“合法合规”，仍需法定审批和人工确认。

## 九、应急处理

### 地图底图未显示

继续讲解彩色业务图斑和右侧本体应用页。底图瓦片网络问题不影响本地变化图斑、语义分析和证据链。

### 执行按钮无响应

刷新本体应用页，确认本体版本和演示包校验通过。必要时使用已经准备好的验收截图继续讲解，但不要改变数据口径。

### 客户追问是否为实时推理

回答：

> *本次演示为了保证数据口径、结果复现和现场稳定性，使用按 V2.0.1
> 本体预编译并做哈希校验的演示包。生产实现可根据场景接入在线规则推理、MMFE
> 和实时 GIS 服务，但每项能力仍需遵守版本、权限和证据治理要求。*
