# ADR-163: 清单基线驱动的自然资源本体证据扩展

**Status**: Proposed

**Date**: 2026-08-05

**Decision owners**: Natural Resource Domain Owner, Data Governance, GIS Engineering

**Related decisions**: [ADR-140 策划型自然资源领域本体与来源映射分层](adr-140-curated-natural-resource-domain-ontology.md), [ADR-162 自然资源本体空间单元分离与语义质量发布门](adr-162-natural-resource-ontology-semantic-quality-gates.md)

## Context

`时空基底数据属性挂接0804.xlsx`只列出 269 个验收属性，许多图层仅给出少量核心字段。若直接按清单行建模，会把地类图斑、自然幢、水域、规划和登记对象的完整标准属性丢失；若把 EA 表、标准表和全部 56,258 个来源字段直接提升为 OWL 类或数据属性，又会重新污染领域本体。

## Decision

1. 附件是不可回退的最低覆盖基线，不是完整本体或规范字段定义来源。
2. 每个清单图层先匹配冻结 `2.2.0` 包中的 EA SchemaArtifact、十册标准属性结构和代码表，再展开命中结构的全部字段。
3. 领域本体只策划稳定的实体、空间单元、状态、过程、主体、角色、权利、规则、信息对象和观测类，以及领域属性、对象关系和约束。
4. EA package、表、标准结构表、字段和智能问数不进入领域 OWL 类层次。来源表保留为 `SchemaArtifact`，来源字段保留为 `SchemaField`。
5. 每个命中结构的来源字段必须得到唯一处置：映射到领域属性、映射到对象关系、映射到相关观测/证据语义，或明确标记为 schema-only 实现字段。存在未映射或歧义字段时禁止形成候选发布包。
6. 来源 Schema 到领域类、SchemaField 到领域属性/对象关系的映射必须进入不可变 JSONL 与 RDF 产物，并保留来源标识和决策依据。
7. 对未在 EA 或十册标准中找到完整结构的清单项显式记录证据缺口，保留附件字段最低覆盖，但不推测或伪造完整字段。
8. `2.3.0` 只生成未激活候选包与 Protege 审查包；在领域负责人验收前不更新在线版本、PostgreSQL 权威源或 Fuseki 投影。

## Consequences

- 清单覆盖可以逐行验收，同时完整字段范围能够从 EA 和标准证据扩展，不受附件列举数量限制。
- 类数量不再代表完整性；完整性由清单覆盖、来源结构命中、字段语义处置、能力问题、SHACL 和 OWL-RL 质量门共同衡量。
- 对字段语义的新增或修正需要维护显式映射种子并重新运行证据审计，不能依赖名称相似度自动确认。
- 当前 5 个来源结构缺口必须由新增标准/EA 证据或领域负责人提供正式字段定义后才能关闭。
