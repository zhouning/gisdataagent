# ADR-140: 策划型自然资源领域本体与来源映射分层

**Status**: Accepted

**Date**: 2026-08-04

**Decision owners**: Natural Resource Domain Owner, Data Governance, GIS Engineering, Cognitive Runtime

**Related decisions**: [ADR-139 自然资源本体运行时](adr-139-natural-resource-ontology-runtime.md)

## Context

`1.0.x` 编译器把 EA package、数据库表、标准表、平台功能和运行时能力统一提升为
`owl:Class`。这保留了来源结构，却没有回答“现实世界中有哪些对象、对象如何分类、
状态如何变化、业务过程受到什么约束”。结果在 Protege 和 GIS Data Agent 中形成数千个
技术类，“智能问数”等应用功能与土地、耕地等领域概念处于同一个类层次。

自然资源本体需要同时支持领域专家审定、Agent 推理、跨部门语义对齐、EA/标准字段映射、
时态变化记录和发布门校验。EA 仓库与标准草案仍是重要证据，但来源的目录结构不能自动
决定领域语义。

## Options Considered

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 继续把所有来源记录提升为 OWL 类 | 自动化程度高、记录数量大 | 类/个体混淆，无法形成可信推理，来源噪声直接污染领域模型 | 不选 |
| 仅手工维护小型 OWL 文件，丢弃 EA/标准结构 | 类层次清晰 | 失去字段映射、来源追踪和数据落地能力 | 不选 |
| 策划领域本体 + SKOS 参考分类 + 数据映射模块 + 独立运行能力模块 | 保留形式语义、数据落地和来源证据，模块可独立治理 | 需要领域审定和映射维护 | **选择** |

## Decision

### 1. 四类模块严格分离

1. 领域本体只包含现实实体、状态、过程、角色、权利、规则、信息对象和观测。
2. 标准代码表使用 SKOS `ConceptScheme` / `Concept`；只有具有内涵类语义且经过审定的概念才提升为 OWL 类。
3. EA 表、标准表、字段和关联属于数据/应用映射模块。表是 `SchemaArtifact` 个体，字段是 `SchemaField` 个体，不是领域类或 OWL 数据属性。
4. GIS Data Agent、智能问数、工具、接口和 Runtime action 属于独立的应用能力本体，不进入自然资源领域类层次，也不由本包导入。

### 2. 土地采用实体、状态和过程三轴模型

- `土地`是核心实体类；`农用地`、`建设用地`、`未利用地`是其互斥分类；`耕地`和`非耕农用地`是`农用地`的互斥子类。
- 地块是持续存在的空间对象。历史变化通过带有效期的`土地利用状态`个体记录，避免删除旧事实或让同一时点出现互斥类型。
- `农业结构调整`和`建设占用`是`土地利用转换`过程类，不是土地类型。
- 转换记录必须连接受影响地块、源状态、目标状态和发生时间。建设占用还必须连接法律政策依据与审批文件。
- OWL 表达类层次、互斥、公理和属性域值；SHACL 表达记录完整性与允许的状态转换；PROV-O 和 OWL-Time 表达来源和时间。

### 3. 来源只提供证据，不自动造类

编译器可以自动抽取 EA 与标准元数据、生成稳定 URI、发现映射候选和报告冲突，但不得仅凭
表名、package 名、字段名或应用菜单名生成领域 `owl:Class`。新增领域类必须进入版本化 seed，
具有定义、父类、建模角色、来源说明和领域负责人审定状态。

### 4. 能力问题作为发布合同

发布门至少验证以下问题：

- 能否从土地遍历到农用地、建设用地和未利用地？三者是否互斥？
- 能否从农用地遍历到耕地和非耕农用地？两者是否互斥？
- 哪些过程允许耕地和非耕农用地相互转换？
- 哪些过程允许农用地转为建设用地，所需审批和依据是什么？
- 给定标准代码或 EA 表，能否找到其描述的领域类和映射证据？
- “智能问数”、EA package 和数据库表是否未出现在领域 OWL 类层次？

## Trade-offs

- 接受类数量小于来源记录数量。类数量不再作为本体完整性指标，能力问题覆盖率、定义质量、映射覆盖率和约束通过率才是质量指标。
- 接受自动抽取不能替代领域审定。候选映射保留 `candidate` 状态，不以名称相似度产生 `owl:sameAs`。
- 接受土地分类在不同时点和法规口径下可能变化。分类定义必须绑定适用标准与时间，实例历史使用状态模式保存。

## Consequences

### Positive

- Protege 类层次只展示可解释的自然资源语义，不再由 EA 目录和平台功能主导。
- Agent 可以区分对象、状态和活动，并能解释一次用途转换的前因、结果、依据和审批。
- EA 与标准内容仍可通过稳定映射定位到领域概念、字段和来源证据。

### Negative

- 每次扩展分类或过程都需要领域负责人参与，不能依赖一次性批量生成。
- OWL 的开放世界语义不足以单独执行全部业务规则，需要 SHACL 和应用层事务校验配合。

### Mitigation

- 采用版本化 seed、能力问题测试、SHACL 回归集和审定状态管理。
- GIS Data Agent 默认显示领域模型，参考分类与数据制品通过筛选和映射视图按需查看。
- 在映射覆盖率和专家审定达到阈值前，不把候选关系升级为确认关系。

## Revisit Triggers

- 省级自然资源领域负责人批准新的分类口径或发现当前分类与有效法规冲突。
- 需要引入上位本体并与 ISO 191xx、GeoSPARQL、SOSA/SSN 或国家数据语义标准建立正式对齐。
- 对象级时态事实达到需要 RDF-star、命名图或专用时态知识图谱存储的规模。
